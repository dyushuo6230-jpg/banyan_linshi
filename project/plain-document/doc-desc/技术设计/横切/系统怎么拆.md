# 系统怎么拆

五端是同一套生意的五个入口，不是五个互不相干的产品。平台和租户是后台暴露面；店内小程序走本地生活接口；在线商城的顾客端走自己的独立接口。共库不是共业务：隔离靠业态、用户池、订单归属，不要理解成「两个库」。

结构配以后的静态架构图。本篇不写端口和域名，数字见《部署与环境》。

## 出现在哪些端

| 端 | 对应哪一套 | 不是什么 |
|---|---|---|
| 平台后台 | 平台接口 + 配套网页 | 不是独立业务模块 |
| 租户后台 | 同一套租户接口 + 配套网页 | 不是四套后台网址 |
| 租户入驻 | 入驻静态页（只嵌部分文件） | 不是接口进程 |
| 众享营销 - 本地生活 | 店内小程序工程 → 本地生活接口 | 不服务在线商城的顾客端逛买 |
| 众享源品 - 在线商城 | 在线商城的顾客端多端工程 → 在线商城的顾客端独立接口；H5 另有独立静态进程 | 不暴露扫桌、认店、店支付 |

忽略且不考虑仓库里标明忽略的旧目录（旧 uni 工程、仓库根旧后台等）。不要拿它们联调。

## 仓库里代码怎么摆

这是当时仓库怎么摆的对照，方便交接对文件夹。不是第二套需求，也不是开工清单。端口和域名仍只看《部署与环境》。依赖夹、构建产物不当业务目录。

五端对上哪几棵树：

- 平台后台：后端仓里的平台服务和配套网页。
- 租户后台：同一后端仓里的租户服务和配套网页（一套系统，四套菜单）。
- 入驻页：入驻静态，不是接口进程。
- 众享营销 - 本地生活：店内小程序工程，只打本地生活接口。
- 众享源品 - 在线商城：在线商城顾客端工程只打自己的独立接口；H5 另有独立静态工程。

```text
仓库根/
├── docs/                         全部文档
│   ├── governance/               通用怎么写文档（不是本项目需求）
│   ├── project/                  本项目正式文档根：需求、决策、架构、批次
│   │   ├── prd/                  产品需求真源

│   │   └── plain-document/       本套白话说明（本文所在夹）
│   └── temp/                     只读参考，不参与维护迭代；不要当本批设计真源
├── go-uni-app/                   店内小程序工程 → 只打本地生活接口
│   └── src/addon/                业务插件（餐饮点餐、小魔推代码仍在、店内页等）
├── go-uni-app-online/            在线商城的顾客端工程（手机/小程序/H5 同一套）→ 只打自己的接口
│   └── src/addon/shop/           购物、分类、附近、我的、详情
└── nunu-go-api/                  后端：多个可运行服务，共用模型和工具包
    ├── app/admin/                平台接口 + 平台网页
    ├── app/merchant/             租户接口 + 租户网页
    ├── app/mall/                 本地生活顾客端接口（店内、付到店、扫桌核销）
    ├── app/mall-online/          在线商城的顾客端独立接口（禁止接到本地生活或租户后台）
    ├── app/h5/                   本地生活相关静态页进程
    ├── app/h5-online/            在线商城的顾客端 H5 整包静态（根路径进首页）

    ├── deploy/sql/               改真表只走这里的增量脚本
```

在线商城的顾客端工程开发时代理只打在线商城的顾客端本机接口，细则见《部署与环境》。两套顾客端工程不要混接。

## 怎么串起来

```text
平台网页 ──登录态加防伪──► 平台接口
租户网页 ──登录态加防伪──► 租户接口（一套系统，四套菜单）
入驻页   ──静态──► 入驻托管
店内小程序 ──请求头里的票──► 本地生活接口（钱进该店）
在线商城的顾客端多端   ──请求头里的票──► 在线商城的顾客端独立接口（钱目标进平台）
在线商城的顾客端 H5    ──整包静态──► 独立静态进程（根路径进首页）
                    │
                    └── 同一套库、同一套缓存实例、短信和上传沿用
```

能力按「业态树、入驻、商品、履约、交易、用户、登录」切开。平台 / 租户 / 两套 C 端只是这些能力露给人看的面，不要按进程再拆一套「平台模块」「租户模块」。

本地生活接口不管在线商城的顾客端逛买，也不作废在线商城顾客端的票。在线商城的顾客端接口可以露出已审过的源品秒杀、拼团，不暴露扫桌、认店、店支付、本地生活拼团秒杀。两套二进制可以不同步发版：在线商城的顾客端挂了，店内和租户后台仍应能跑。

## 关键约束

- 租户后台是一套系统、四套菜单，餐饮 / 美发 / 商超 / 在线商城不要理解成四套产品。
- 众享源品只调自己的接口。禁止接到本地生活接口或租户后台「方便联调」。
- 进程之间不要求同步互调，也不共用登录票。
- 推广员、小魔推、监控大盘本期不改造。消息、搜索、通知细则未定，不写成已选中间件。

## 和正式设计的关系

正式切法在架构总册和模块边界：能力域是真源，进程名只是暴露面。本篇用人话对齐五端，并附当时仓库目录对照方便交接。不贴类名清单。静态图在《系统上下文》《应用架构》。目录对照不是需求，改文件夹以当时仓库为准再刷这一节。
