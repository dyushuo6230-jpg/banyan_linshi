# 部署与环境

本篇是这套白话说明里**唯一写端口和域名**的一篇。其它篇需要数字，指向这里。共库、短信、上传沿用，不等于业务可以混接。真实配置文件不进版本库。Jenkins、面板、Nginx 由运维加的，本文不代替运维清单。未合主分支不要说成生产已上线。

## 出现在哪些端

五端都要落到具体进程。在线商城顾客端只打在线商城的顾客端接口，不要指到本地生活或租户后台。

## 怎么串起来

本机多端口并存；测试外网一律测试域，正式一律正式域。容器内监听仍按现码习惯再反代，外网只认下面写死的在线商城的顾客端域名。在线商城的顾客端开发代理只打本机在线商城的顾客端接口，不得改到本地生活或租户后台。

```text
平台接口 ──┐
本地生活接口 ──┼── 同一套库
租户接口 ──┤    同一套缓存实例（在线商城的顾客端会话键必须隔离）
在线商城的顾客端接口 ──┘    短信 / 上传沿用同一通道
入驻静态、在线商城的顾客端静态：各自进程，不是接口
```

在线商城的顾客端挂了，本地生活和租户后台仍应能跑。回退在线商城的顾客端进程或在线商城的顾客端 H5，不必强制回退本地生活。

## 本机进程

| 干什么 | 本机端口 |
|---|---|
| 平台接口 | 8031 |
| 本地生活接口（店内 + 店支付） | 8032 |
| 租户接口（一套后台） | 8033 |
| 入驻 H5（部分文件嵌入） | 8034 |
| 其它已有首页进程 | 8081（在线商城的顾客端不得占用） |
| 在线商城的顾客端独立接口 | 8035 |
| 在线商城的顾客端 H5 独立静态进程 | 8036（根路径进首页） |

在线商城的顾客端工程开发时代理只打 `127.0.0.1:8035`。

测试一律 `.gyyx.store`，正式一律 `.zhengdeyunqi.cn`。

| 用途 | 测试 | 正式 |
|---|---|---|
| 在线商城的顾客端接口 | `https://test-shop-online-api-go.gyyx.store` | `https://shop-online-api-go.zhengdeyunqi.cn` |
| 在线商城的顾客端 H5 | `https://test-shop-online-h5-go.gyyx.store/`（根路径，不用子路径） | `https://shop-online-h5-go.zhengdeyunqi.cn/` |

在线商城的顾客端支付 / 退款回调打**对应环境的在线商城的顾客端接口域名**，不打本地生活接口，也不打租户后台。

在线商城的顾客端 H5：打包后整包拷进独立静态工程再编二进制。不挂微信业务域名校验文件。

本地生活、平台、租户的外网具体主机名，除「测试域 / 正式域」这条总规则外，未在本篇写死的不编造。

## 关键约束

- 独立进程不等于独立库。
- 在线商城的顾客端登录密钥独立，不抄本地生活那一份。
- 在线商城的顾客端微信通道独立；商户号、小程序身份不编造。
- 缓存同一实例；本地生活现状用其中一个库号。在线商城的顾客端用独立键前缀或独立库号，**数字不冻结**。
- 配置目录分本地 / 测试 / 正式示例；密钥在示例里保持占位，不进 Git。

## 和正式设计的关系

正式部署架构是真源。测 / 正式 Nginx 与流水线加编在仓库外。监控、容灾、灰度比例、编排脚本未定，不把未选的云厂商写成已定。
