# 权限与菜单模板

租户后台是一套系统、四套菜单。入驻通过后按业态套模板。侧栏看不见不等于已经授权：直访旧页或调接口，仍要按权限拒绝。

规则全文在《租户后台与菜单》。细菜单树在分端两本租户后台。

## 出现在哪些端

- **平台后台**：同一页切换业态编菜单。种子四套。新本地根多一个页签，从餐饮 / 美发 / 商超之一拷快照后再删减。平台侧栏「无」= 删行。
- **租户后台**：登录后只看见本业态侧栏。在线商城无员工、无角色，只用主账号。
- **店员**：出餐 / 核销在店内小程序，不靠租户网页当另一套 App。

## 怎么串起来

入驻审核通过 → 套该业态菜单快照 → 租户打开后台看到对应侧栏。平台改某一业态并保存，只影响这一套。未保存就切换业态会不会丢草稿、改完要不要重登：**未定**。

「无」= 模板里删行。隐藏 = 行还在、侧栏不可见（本期四套都把小魔推隐藏）。已删的周边分类管理、平台秒杀管理、拼团审核，不要写回来。

## 关键约束

- 隐藏不是安全边界。看不见不等于已经授权。
- 直访旧路由仍要拒绝。无权限时的文案：**未定**。
- 在线商城没有：员工 / 角色、小程序装修、内容轮播、拼团秒杀、周边。
- 不能靠登录那一刻记住的旧角色授权，每次请求按当时库里的角色 / 超管标记。
- 平台超管只属于 `ZadminDister`。给其它角色勾权限时，管理员、角色管理、菜单管理、API 管理及配套接口不出现；保存带着这些项必须失败。藏菜单不是授权。

## 和正式设计的关系

正式权限与菜单在安全架构和租户工作台设计。本篇只交代套用和「无 / 隐藏」。

## 未定 / 本期不做

- 不新开第二套租户后台产品。
- 租户不能改平台模板定义。
- 隐藏与无权限文案、改模板后是否重登：未定。
