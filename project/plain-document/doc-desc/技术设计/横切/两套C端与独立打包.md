# 两套C端与独立打包

店内小程序和在线商城的顾客端不是同一套前端、也不是同一套接口。混接会串号、串钱、串履约。在线商城的顾客端多端同一套代码，有差异必须条件编译；本轮页面先做到能打包、够申请支付，完整逛买（含真扣到账）不是这些前端接口的必验。

本机和测试 / 正式怎么指过去，见《部署与环境》。本篇不写端口。

## 出现在哪些端

- **众享营销 - 本地生活**：店内小程序工程，只调本地生活接口。认店、扫桌、核销、付到店都在这里。
- **众享源品 - 在线商城**：在线商城的顾客端工程（手机、小程序、H5 同一套）。只调在线商城的顾客端独立接口。H5 整包打进独立静态进程，外网根路径进首页，不用入驻那种子路径。
- **供应商**：没有独立小程序给顾客装。顾客只进在线商城的顾客端。
- 平台、租户、入驻不是这两套 C 端。

## 怎么串起来

1. 店内工程打本地生活接口；开发代理、测试包、正式包都不要改去打在线商城的顾客端或租户后台。
2. 在线商城的顾客端工程打在线商城的顾客端独立接口。开发代理只打在线商城的顾客端本机服务。测试包、正式包只打在线商城顾客端自己的测试 / 正式接口域名。
3. 在线商城的顾客端 H5：整包产物拷进独立静态工程再编二进制。入驻 H5 仍是另一套、只嵌部分文件，不要两套静态混打。
4. 页面以现用页为准：新首页、现用详情、现用「我的」。旧首页、静态复刻、装修下发的旧底栏不当主链。默认底部只露购物、我的，细则在分端《众享源品-在线商城》。部分返回还可能落到旧首页，口径仍是回现用购物首页，留给开发改跳转。

## 关键约束

- 禁止把在线商城的顾客端接到本地生活接口或租户后台。
- 禁止把店内票拿去调在线商城的顾客端。
- 在线商城的顾客端 H5 不挂微信业务域名校验文件；用浏览器打开不依赖该文件。
- 本轮在线商城的顾客端：可登录、看平台轮播和已审商品、立即购买下未付单；支付按钮保留，不调起微信 / 支付宝 / 金豆。
- 两套小程序 appid 各配；在线商城的顾客端不得默认抄店内那一套。

## 和正式设计的关系

独立进程、独立打包、连接沿用（库 / 短信 / 上传）但端口和登录密钥不沿用，见架构总册和部署架构。本篇只把「不能混」说成人话。

## 未定 / 本期不做

- 不把完整逛买、真扣款成功当这些前端接口的必验。
- AI / 发现对接、在线商城的顾客端拼团秒杀、积分商城不作为上线能力。
- 测 / 正式的面板和流水线由运维加编，文档不代替运维清单。
