# 账号用户池与登录会话

同一部手机可以是三个号：店 A、店 B、在线商城的顾客端。登录态两套，作废互不影响。验收就看五条：忙不踢、闲必踢、退出或改密立刻作废、本地生活不能串店、库里没有明文密码。业务规则全文在《用户账号与用户池》《登录会话与口令》。

## 出现在哪些端

- **平台后台 / 租户后台**：网页登录态加防伪。不同账号同时在线互不踢；同一个号在别处再登，旧的那一段立刻作废。
- **租户入驻**：入驻资格票过期就不能提交。票里不要带着手机号给前端乱传。
- **众享营销 - 本地生活**：请求头里的票。认店只约束这一端。
- **众享源品**：短信或账号密码。H5「我的」必须能登上去并显示已登录，不强制绑微信。在线商城的顾客端也纳入可作废会话。
- **不用人点**：闲置超时、登录最长寿命到点、被禁用、被重置密码，旧会话都要废。

## 怎么串起来

一张用户相关数据、两个池：店铺池（按哪家店 + 手机）和众享源品池（按在线商城的顾客端 + 手机 / 账号）。不另建一张在线商城的顾客端专用用户总表来绕过分池。老数据一律看成店铺池；店铺身份是空的脏数据，不要默认当成在线商城的顾客端用户。

网页走登录态加防伪，不要改成纯请求头票。两套 C 端走请求头票。两套接口的登录密钥和作废名单必须分开，票不得跨过去。

认店：购物车、下单、支付不能信顾客端指定的店号。在线商城的顾客端没有「当前小程序等于唯一店」这一套。

平台非超管必须至少有一个角色才能保存；每次请求按当时库里的角色授权，不能靠登录那一刻记住的旧身份。平台超管只属于 `ZadminDister`。

## 关键约束

- 隐藏菜单不是安全边界：侧栏看不见不等于已经授权，直访旧页仍要按权限拒绝。细菜单树见分端；权限模板全文留给以后的《权限与菜单模板》。
- 店内票不能调在线商城的顾客端，在线商城顾客端登录票不能调店内。
- 停写、停读任何可登录明文旁路。重置密码只向当时的人亮一次。
- 平台超管登录名是 `ZadminDister`。各端登录页不写死账号、密码。登录与密钥框声明不要浏览器自动填。
- 设密复杂度：后台至少 10 位且四类至少三类；顾客端至少 8 位且字母+数字。设密页写明该端规则。登录已有密码只核对错。
- 闲置时长用已确认的后台默认，不在本篇发明新分钟数。登录票算法、过期秒数未冻结则 **未定**。

## 和正式设计的关系

用户主数据和签发登录票是两件能力：前者管注册分池，后者管口令和作废。正式设计在用户 / 认证会话两份里。跨域怎么配见《部署与环境》，本篇不写端口。
