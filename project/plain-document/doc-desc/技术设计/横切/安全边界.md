# 安全边界

菜单隐藏不是授权。不能串店、不能串池、不能拿店内票调在线商城的顾客端。入驻资格过期不能提交。本期明确不做的登录增强不要当缺口补进必验。

规则全文在《登录会话与口令》《用户账号与用户池》《租户后台与菜单》。隔离时序见《两套登录隔离-时序》。

## 出现在哪些端

- **平台 / 租户网页**：登录态加防伪。非超管必须有角色。每次请求按当时库里的角色授权。
- **入驻页**：资格票过期不能交。票面上不要带着手机号给前端乱传。
- **本地生活**：认店只约束本端。购物车、下单、支付不能信顾客端传来的店号。
- **众享源品**：两套票作废互不影响。在线商城顾客端登录票不能当店 A 会员。

## 怎么串起来

验收五条：忙不踢；闲必踢；退出或改密立刻作废；本地生活串不了店；库和接口都没有可登录明文密码。同一账号在别处再登，旧的那一段立刻作废。不同账号同时在线互不踢。

直访已删或隐藏的旧路由，仍要按权限拒绝。侧栏没有拼团审核、周边分类管理，直访同样要拦。

## 关键约束

- 店内票调在线商城的顾客端必须失败；在线商城顾客端登录票调店内必须失败。
- 各端登录页不写死账号、密码。重置密码只亮一次。
- 登录、AppID、支付/短信/OSS 密钥框声明不要浏览器自动填。不承诺 Chrome 对登录框一次都不填。
- 平台超管只属于 `ZadminDister`。非超管打不开管理员、角色管理、菜单管理、API 管理，对应接口也失败。
- 租户登录失败锁定次数：未定，不编次数。
- 日志不要出现完整密码、完整票。

## 和正式设计的关系

正式安全架构是真源。本篇只给人交接「什么叫越权」。不写密钥文件名。
