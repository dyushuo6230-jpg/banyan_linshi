# 测试怎么做

测的是两条产品线有没有串、主链能不能闭口，不是把仓库里每一页点一遍。两套 C 端的账号、接口、域名、协议都不要串着用。域名和本机指哪，见《部署与环境》。不抄测试用例编号，不写未实现的监控大盘。

## 出现在哪些端

五端都要测到人能看见的结果。店员出餐 / 核销在店内小程序测，不要只在租户网页上点一下当已经履约。在线商城的顾客端测现用页，不要把旧首页、静态复刻当主链。

## 怎么串起来（主链）

1. **入驻**：开着的业态能提交；在线商城 1～3 个一级；执照识别成功。同一手机待审或已通过不能再提。
2. **套菜单**：平台通过后，该店侧栏是对应模板。在线商城无装修、无员工。有秒杀报名、拼团报名、板块报名，不是店内自发那套。
3. **发品**：本地上架即可本店可售、平台不审。商城挂叶子送审，通过后在线商城的顾客端可售。未挂一级不能卖。
4. **履约或发货**：餐饮扫桌出餐；美发 / 商超整单核销。在线商城的顾客端能加购、看未付单、供应商能在详情发货（本轮顾客端可以仍是未付）。
5. **支付 / 未付**：店内付到店。在线商城的顾客端下未付单，点支付不真扣到账，按钮还在。未付倒计时，到期打开即关，到点不能再付。
6. **结算对账**：本地佣金是对账单，不是假入账。商城按一级快照抽佣再结。抽佣对错以《业态经营类目与抽佣》为准。
7. **源品活动**：平台开场、供应商报名、平台审过，顾客能进、能下未付单。到期没成团关未付单。不要用已删的秒杀管理、拼团审核去测。
8. **板块**：商品型要审过才上架；附近顶灯片走子列表。不按板块改支付通道。

登录五条不过，不能当生产已上线。见《登录会话与口令》。

## 关键约束（必看现象）

- 两套 C 端不要串测：店内号登不出现在在线商城的顾客端，在线商城顾客端账号进不了某店当会员；店内接口包不要打到在线商城的顾客端域名。
- 协议：在线商城的顾客端读在线商城的顾客端协议，不要套店内那份。
- 真评价：详情展示已提交的；有该商品已完成订单才能写。不要拿假数据验收。
- 本轮在线商城的顾客端不验收真扣款成功。加入购物车必须能进购物车，不能再弹敬请期待当交差。
- 小魔推不纳入必验。推广员不改造、不纳入必验。
- 已删菜单（平台秒杀管理、拼团审核、周边分类、WiFi）侧栏不应再出现。新菜单商城秒杀、商城拼团、板块不是旧入口复活。
- 隐藏菜单不是安全边界：直访仍应被拒，不要只测「看不见」。
- 部分退、外卖、AI 接真业务、发现对接：无此路径，不要写成失败用例清单去补功能。
- 源品附近两套详情不拉起店小程序。好友助力藏掉。限时折扣进秒杀列表。品牌联盟进超级品牌，没配则藏。

## 闭口看什么

- **后台、入驻、本地生活**：开发完成，能闭口就闭口。不要因为在线商城的顾客端还没做完就留到下次。
- **在线商城供应商**：发品送审、审品、接单发货、结算、店铺资料、三类报名要做完。
- **在线商城的顾客端现用页**：已经出现的能力接到自己的接口并能办完，或按已确认的表藏掉。「我的」能看出已登录，不强制绑微信。本轮不真扣款。完整逛买含真扣到账不是本轮必验。

未合主分支不要说成生产已经如此。测试环境用哪套域名，指向《部署与环境》。
