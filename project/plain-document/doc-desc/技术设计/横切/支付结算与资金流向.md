# 支付结算与资金流向

本地生活钱进该店账户；在线商城的顾客端目标是付给平台，再按商品所属一级类目快照抽佣后结给供应商。本轮在线商城的顾客端可以下未付单，不调起微信 / 支付宝 / 金豆，支付按钮保留。抽佣看哪、空或 0 怎么办，只以《业态经营类目与抽佣》为准，本篇不重写公式。订单状态见《订单支付与结算》。

## 出现在哪些端

- **众享营销 - 本地生活**：顾客付到该店。回调打本地生活接口自己的域名。
- **众享源品**：顾客下未付单。以后真扣到账时，回调打在线商城顾客端自己的域名，不能串到店内或租户后台。
- **租户后台**：看单、发货、对账、提现（仅在线商城有资金总览 / 提现）。本地佣金只出对账单，禁止假入账增加可提现余额。
- **平台后台**：看各店和在线商城顾客端的单、结算、提现审核。售后只看不办。
- **不用人点**：未付到期，打开列表 / 详情或去支付时立刻关单；定时仍会关。

## 怎么串起来

**本地生活**

顾客在该店小程序付 → 钱进该店通道 → 餐饮扫桌履约或美发 / 商超核销 → 出餐或核销成功写成已完成。支付成功不等于平台已经收到佣金。店线下转，平台勾已收。

**众享源品**

顾客立即购买走出未付单。目标态：付给平台通道 → 已付待履约 → 发货履约中 → 确认收货即已完成。本轮停在未付，不要标成已付。在线商城的顾客端本轮也不绑微信身份去付。

两套支付通道实现可以不同，商户号和小程序身份各配，在线商城的顾客端不得默认抄店内。未挂一级的货不能卖、不能下单，不要用缺省费率放行。

## 关键约束

- 给人看、给人填用元。
- 回调必须打对应那一套接口。在线商城顾客端的支付 / 退款不要打到本地生活接口。
- 本轮在线商城的顾客端不真扣款成功。按钮和组件还在，够申请支付。
- 通道参数、商户号、appid 未点名不编造。
- 部分退、退货物流本期无此路径。

## 和正式设计的关系

交易是一个能力、两套暴露面：店账户走本地生活接口，平台收款走在线商城的顾客端接口。正式支付设计在交易模块。本机和测试 / 正式回调域名见《部署与环境》。

## 未定 / 本期不做

- 真扣款成功路径、微信小程序支付本轮不验收。
- 支付申请是交付依赖；未配齐可先发登录与逛买以外的骨架，不把通道数字写进说明。
- 灰度切流、自动熔断开关名称未定。
