# 周边与到店服务

两边都有「附近」和第三方到店服务，规则相反。店内看的是**这家店勾了哪些本地业态**；在线商城的顾客端附近是**平台级全部本地根**，跟某供应商有没有勾选无关。

## 谁用、在哪一端

- **平台后台**：维护一份 CPS 目录（增删改、上下架）。没有「周边分类管理」这种菜单，不要写回来。也配跳转第三方小程序要用的应用号和路径。
- **租户后台 · 本地生活**：勾本店要展示的本地业态；对本店引用的 CPS 只能上下架，不能改目录正文。
- **租户后台 · 在线商城**：没有独立小程序，没有周边菜单，也没有周边 CPS。
- **众享营销 - 本地生活 · 顾客**：打开该店周边，只看见本店已勾业态的店，以及本店已上架且平台目录仍上架的 CPS。
- **众享源品 · 顾客**：附近筛的是当前全部本地业态根。CPS 只出平台目录上架项，跳转不带某供应商。

## 主路径怎么走

**店内**

1. 平台先有 CPS 目录。无行或平台下架，店内和在线商城的顾客端都不出这项。
2. 本地店勾自己的本地业态（可多选）。该店周边只展示已勾的那些业态。
3. 顾客点 CPS：拉起第三方小程序。平台填应用号和路径；店内带上店铺号、店名、本店应用号。不编更多键。

**在线商城的顾客端**

1. 附近按平台级本地根筛，不读某供应商的勾选。
2. CPS 同样只出平台目录上架项。跳转只带来自众享源品的标记，不传某供应商。

旧的分类、租户自己填的 CPS 行，不再给顾客端。

## 关键规则

- 平台下架 → 店内和在线商城的顾客端同时不出。无行 = 下架。
- 不得把店铺轮播、周边轮播、平台轮播当成同一套图。
- 在线商城供应商无周边能力。
- 在线商城的顾客端底部附近页可以还在工程里，是否露出留给分端；本篇只定筛选规则。

## 会变成什么

店内顾客看见的附近，跟老板勾了什么走。在线商城顾客看见的附近，跟全平台本地根走。同一条 CPS，平台下架后两端都没有。

## 明确不做 / 未定

- 不恢复周边分类管理。
- 不给供应商做一套店内周边。
- 不编造 extraData 里未点名的键。

## 和谁交接

店内小程序还有没有周边入口，见分端《众享营销-本地生活》。在线商城的顾客端附近页见分端《众享源品-在线商城》。首页模块归属点到《本地生活怎么履约》和《平台运营与现码保留》。

## 落在哪一端

目录在平台后台；勾选和本店上下架在本地生活租户后台；顾客分别在店内小程序或在线商城的顾客端附近看见结果。
