# 用户账号与用户池

店和店之间、店和在线商城的顾客端之间，账号不能互相替代。同一部手机可以是三个号。不另建一套「在线商城的顾客端专用用户表」来绕过分池。

## 谁用、在哪一端

- **众享营销 - 本地生活**：顾客在**某一家店**的小程序注册或登录，只当这家店的人。打开另一家店，还要再注册。
- **众享源品**：须在在线商城的顾客端单独注册。手机号加账号密码。不能把在线商城的顾客端用户做成某家虚拟店会员，也不能拿官方店身份冒充自营。
- **平台后台**：用户列表怎么拆两个菜单，**未定**。未定就不要在会上说已经拆好或永远不拆。
- **不用人点**：下单、读写订单必须带着「在哪个池」，防止串号。

## 主路径怎么走

1. 在店 A 小程序注册 → 只是店 A 的店铺池账号。
2. 同一手机打开店 B → 仍要在店 B 注册，不能直接当店 B 会员。
3. 同一手机打开众享源品 → 未在在线商城的顾客端注册就要单独注册。
4. 老数据一律看成店铺池。店铺身份是空的脏数据，不要默认当成在线商城的顾客端用户。

## 关键规则

- 两个池：店铺池、众享源品池。唯一性在池内：店铺池按「哪家店 + 手机号」；在线商城的顾客端按「在线商城的顾客端 + 手机号/账号」。
- **认店只约束本地生活。** 店内下单、支付、券，不能信顾客端传来的店号。在线商城的顾客端没有「当前小程序等于唯一店」这一套。
- 本地生活本期不另开一套和在线商城的顾客端完全相同的密码登录（在线商城的顾客端才是短信或账密）。店内怎么登沿用已确认的本地生活能力，不在本篇发明第三种登录。
- 账号启用/禁用沿用现页，资料没重写就保持现状。

## 会变成什么

人看见的是：这个号只能进这一家店，或只能进在线商城的顾客端。店内登录态作废，在线商城的顾客端那一个号还在；反过来也一样。

## 明确不做 / 未定

- 不为在线商城的顾客端再新建一张用户总表来当业务真源。
- 不把空店身份默认成在线商城的顾客端用户。
- 平台用户列表是否拆成两个菜单：未定。
- 池字段落在哪一列：技术评估，本篇只要求业务上能区分。

## 和谁交接

登录怎么踢、怎么作废见《登录会话与口令》。认店失败时顾客下不了单，钱走哪见《订单支付与结算》。入驻申请人不是这两个池里的消费者。

## 落在哪一端

顾客分别在店内小程序或在线商城的顾客端「我的」看见自己的号。租户后台看到的是本店会员，不是在线商城的顾客端整池。
