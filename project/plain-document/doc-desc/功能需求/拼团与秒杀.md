# 拼团与秒杀

两条流程，不要套成一套。本地生活仍是店自己发、平台不审。众享源品是平台开场、供应商报名、平台审。成交都走同一套下单付钱，不另做支付通道。

## 谁用、在哪一端

- **租户后台 · 本地生活**（含按餐饮/美发/商超拷出来的新根）：完整的拼团、秒杀创建和上下架。价格给人看、给人填用元。
- **众享营销 - 本地生活 · 顾客**：本店上架的活动可见可买，规则跟后台设的一致。首页按归属可以出拼团、秒杀坑，没有进行中的活动就空着。
- **平台后台**：侧栏没有已删的「秒杀管理」「拼团审核」，不要写回来。另有「商城秒杀」「商城拼团」，各下场次和报名审核。不给平台强制下架经营菜单去管本地生活店内活动。
- **租户后台 · 在线商城**：一级「秒杀报名」「拼团报名」。只能报已审通过的货。
- **众享源品 · 顾客**：平台审过的场次可进、可下未付单。没有设计图就自编页，不卡像素。

## 主路径怎么走

**本地生活**

1. 租户创建拼团或秒杀并上架 → 本店小程序可见，不经平台审核，也没有「待平台审核」状态。
2. 下架或停用后，新顾客不能再参加。已经下的单不自动关、不自动退；要退走现成退款，见《售后与退款》。
3. 成交仍走订单支付。美发/商超拼团不另出一张核销码，跟普通已付同一套码。餐饮拼团仍扫桌。
4. 历史上平台待审的拼团秒杀，改成未上架，不要继续当待审经营。

**众享源品**

1. 平台创建秒杀场或拼团场。
2. 在线商城供应商用已审货报名。
3. 平台审核通过后，在线商城的顾客端可见可买，走出未付单。活动单平台统一收款。
4. 到期没成团：未付单关掉，活动占用放掉。本批没有真付，也就没有真退。

## 关键规则

- 有该菜单的本地生活店都可以自发，不要写死「只有三个业态名」。
- 库存不足不能超卖；现码有规则就沿用，没写数字就不编。
- 不要把已删的平台经营旧名写回来。新菜单不是旧菜单换皮。
- 本地生活停用规则不改：停用后不可新参，已下单不自动退。
- 不要把本地生活活动接到在线商城的顾客端接口。
- 两种流程允许状态不一样，禁止拿「店自发」去套源品，也禁止拿「平台审」去套店内。

## 会变成什么

店内顾客看见进行中的活动可以买；停用后新参失败，旧单还在。源品顾客看见审过的场次可以下未付单；未成团则未付单取消。平台运营看不见已删旧入口，看得见商城场次和报名审核。

## 明确不做 / 未定

- 本批真退款、成团失败已付款路径（本批无真付）。
- 平台给店发活动通知：资料没写。
- 参考图只当交互线索，非正式视觉验收。源品自编页不卡像素。

## 和谁交接

钱和主状态见《订单支付与结算》。扫桌核销见《本地生活怎么履约》。源品逛买见《众享源品怎么逛买》。菜单里有没有这一项，见《租户后台与菜单》和分端。

## 落在哪一端

本地：创建在本地生活租户后台；购买和核销/扫桌在该店小程序。源品：开场和审核在平台；报名在商城供应商后台；购买在在线商城的顾客端。
