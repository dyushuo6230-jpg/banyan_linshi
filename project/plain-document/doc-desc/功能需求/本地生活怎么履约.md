# 本地生活怎么履约

本地生活是某一家店自己的小程序，不是在线商城的顾客端。履约跟这家店业态从哪套拷来：餐饮扫桌，美发/商超核销。没有外卖。

## 谁用、在哪一端

- **众享营销 - 本地生活 · 顾客**：打开**这一家店**的小程序。首页模块按平台配的「首页模块归属」过滤。点单或选服务、付钱、看订单。美发/商超顾客在已付待履约时，看到的是「待核销」。
- **众享营销 - 本地生活 · 店员**：同一套小程序里出餐或核销，不是租户网页，也不是另一套独立 App。
- **租户后台 · 本地生活**：桌台、核销、订单也可以办。店员页和后台都能核的，以后分端写清入口。
- **在线商城供应商**：没有独立小程序，本篇没有他的履约。

## 主路径怎么走

**餐饮（及从餐饮拷来的新根）**

1. 顾客到店扫合法桌号，按这张桌点单。
2. 付钱进该店账户。
3. 店员出餐或确认完成 → 订单**已完成**，不进待评价。已完成可以写评价，评完订单仍是已完成。

**美发 / 商超（及从这两套拷来的新根）**

1. 顾客先付，钱进该店。
2. 生成核销码（拼团不另出一张主码，跟普通已付同一套）。
3. 到店整单一次核销。成功 → **已完成**，跳过待评价。
4. 本期不设核销天数，也没有到期自动退。

未付过期：顾客打开本店订单列表、详情或去支付时，到期的待付款立刻关掉；后台定时仍会关。待付款页要能看见还剩多久，到点不能再去付。

## 关键规则

- 一套首页，不是按业态做三套小程序产品。轮播在装修里配。归属增加拼团、秒杀两种，默认通用；不并进活动三坑。没有进行中的活动该坑空着。发活动仍店自发、平台不审。
- 认店：下单、支付不能信顾客端随便传的店号。
- 无桌、桌号无效：不能按这张桌下单。
- 全额退完：该单核销码不能再核，不补第二张主码。
- 有待处理售后时，不能再出餐、核销。
- 周边按本店已勾的本地业态展示；CPS 用平台目录。两边细则在《周边与到店服务》，本篇只点到：供应商没有周边菜单。

## 会变成什么

- 未付 → 已付待履约（美发/商超对顾客显示待核销）→ 已完成。
- 没有「待评价」主状态。已完成可评。
- 全额退完 → 已关闭，码作废。

## 明确不做 / 未定

- 外卖。
- 第四种履约。
- 过期自动退、按天算核销有效期。
- 装修做成全新设计系统。
- 模板市场运营细则：待配置。
- 核销通知文案：不验收死句子。

## 和谁交接

钱进谁账户、主状态数字怎么展示见《订单支付与结算》。拼团秒杀本地生活可自发，源品另一套流程见《拼团与秒杀》。本篇只保证店内成交仍走同一套核销或扫桌。账号认店见《用户账号与用户池》。

## 落在哪一端

顾客和店员都在该店小程序里看见结果；老板也可以在租户后台核。平台不审本地生活普通商品，也不替店出餐。
