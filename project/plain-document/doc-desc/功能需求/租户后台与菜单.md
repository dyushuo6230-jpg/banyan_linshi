# 租户后台与菜单

租户后台是**一套系统**，不是四个产品、四套网址。登录之后侧栏按业态模板不同。细菜单树留给分端，本篇只把规则说清。

## 谁用、在哪一端

- **全体已通过租户**：同一套租户后台登录入口。餐饮、美发、商超、在线商城供应商看到不同侧栏。
- **平台后台**：租户菜单配置是**同一页**，切换业态再编那一套。种子四套：餐饮、美发、商超、在线商城。新增本地根多一个页签，菜单从餐饮/美发/商超之一拷快照后再按点名表删减。
- **租户子账号**：仅本地生活。在线商城供应商无员工、无角色，只用主账号。

## 主路径怎么走

1. 入驻通过后套该业态模板，见《租户入驻与审核》。
2. 租户打开后台，看见本业态侧栏。不要要求在线商城供应商去另一套后台网址经营。
3. 平台改某一业态并保存，只影响这一套。未保存就切换业态会不会丢草稿：**待配置**，不编造提示文案。改完之后租户要不要重登才看见新侧栏：也**待配置**。

## 关键规则

**「无」和「隐藏」不是一回事**

- 这一业态没有这项能力：模板里**删行**。平台侧栏同样：无 = 删行。
- 隐藏：行还在，侧栏看不见。本期四套模板都把小魔推隐藏。隐藏不是安全边界：直接打开旧页或调接口，仍要按权限拒绝。看不见不等于已经授权。无权限时的文案：**待配置**。

**在线商城供应商有 / 没有**

| 有 | 没有 |
|---|---|
| 店铺资料 | 员工 / 角色 |
| 送审、发货、提现 | 小程序装修、内容管理里的轮播 |
| 秒杀报名、拼团报名、板块报名 | 周边、周边 CPS |

**对照（文字，不是三份全文）**

- 本地三套：都有店内发品、订单、履约相关能力；差异是扫桌还是核销、以及点名表里删了哪几行。不要按餐饮、美发、商超各写一篇发品说明书。
- 本地生活「店铺」页补省市区、坐标、详情顶图、介绍组图、营业说明，不新开菜单。在线商城仍只有「店铺资料」。
- 店员出餐、核销在本地生活小程序里，不写进租户网页当另一套 App。
- 店员出餐、核销在本地生活小程序里，不写进租户网页当另一套 App。
- 未点名的菜单，不得按「看起来像本地/像商城」自行推断有无。已删的周边分类管理、平台秒杀管理、拼团审核，不要写回来。平台另有商城秒杀、商城拼团和板块，那是新名字，不是旧入口复活。

## 会变成什么

人看见的是：同一登录页，不同侧栏。某项没有了就是侧栏没有这一行；小魔推是有代码但侧栏藏着。直访仍可能被拒。

## 明确不做 / 未定

- 不新开第二套租户后台产品。
- 租户不能改平台模板定义。
- 隐藏与无权限的界面文案、改模板后是否重登：待配置。

## 和谁交接

套菜单时机见《租户入驻与审核》。拼团有无见《拼团与秒杀》。周边有无见《周边与到店服务》。每一行叫什么、现在露出哪几个，见分端两本租户后台。

## 落在哪一端

配置在平台；日常点菜单在租户网页。店员核销不在这一端。
