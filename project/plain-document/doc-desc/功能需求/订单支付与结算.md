# 订单支付与结算

本地生活钱进该店；众享源品付给平台，再按一级类目快照抽佣后结给供应商。本轮在线商城的顾客端可以下未付单，不真扣款。抽佣看哪、空怎么办，以《业态经营类目与抽佣》为准，本篇不重写公式。

## 谁用、在哪一端

- **众享营销 - 本地生活**：顾客在该店小程序付到店。美发/商超已付后看见待核销。
- **众享源品**：顾客在在线商城的顾客端下单、看未付倒计时。本轮点支付不调起微信、支付宝、金豆，订单保持未付，按钮还在。
- **租户后台**：看本店订单。书面语页签：待付款 / 已付待履约 / 履约中 / 已完成 / 已取消 / 已关闭。不要出现待发货、待收货、已付款这种页签。在线商城的顾客端来的货，发货在详情里办，不在列表行上点一下就发。
- **平台后台**：看各店和在线商城顾客端的单，列用来源、履约方式。售后只看不办。
- **不用人点**：到期未付，打开列表/详情或去支付时立刻关掉；定时仍会关。

## 主路径怎么走

**本地生活**

付到该店账户 → 餐饮继续扫桌履约，美发/商超去核销 → 出餐或核销成功写成已完成。支付成功不等于平台已经收到那笔佣金；本地佣金只出对账单，店线下转，平台勾已收。禁止做成一笔假入账去增加可提现余额。

**众享源品**

顾客下未付单。目标态是付给平台，再按快照抽佣后结给供应商。本轮停在未付，不要标成已付。以后确认收货或到期自动确认 → 已完成，中间没有单独的「待评价」主状态。履约中只出现在在线商城的顾客端这条发货链。

## 关键规则

给人看、给人填用**元**。

后台状态列用书面语。顾客端（现用本地生活 + 众享源品）用口语：在线商城的顾客端已付待履约可以说待发货，履约中可以说待收货；已关闭不要说成别的。

| 变成什么 | 人怎么理解 |
|---|---|
| 待付款 | 还没付。页上要有倒计时，到点不能再去付 |
| 已付待履约 | 钱已付（在线商城的顾客端本轮不应出现，除非以后真扣到账）。本地美发/商超对顾客显示待核销 |
| 履约中 | 仅在线商城的顾客端发货途中 |
| 已完成 | 可以评价，不能再申请售后 |
| 已取消 | 未付取消或超时 |
| 已关闭 | 全额退完 |

有效订单 = 已完成，且没有正在处理的售后。结算从进入已完成起算。

未挂一级的货不能卖。类目停用后不能再卖，已下的单快照不动。

## 会变成什么

本地生活：待付款 → 已付待履约 → 已完成（没有履约中）。  
在线商城的顾客端目标态：待付款 → 已付待履约 → 履约中 → 已完成。  
未付超时或取消 → 已取消。全额退完 → 已关闭。

## 明确不做 / 未定

- 部分退、退货物流主路径。售后怎么办见《售后与退款》，本篇不展开。
- 本轮在线商城的顾客端真扣款成功。
- 通道商户号、手续费死数字。
- 拆单部分成功：资料没写死 → 待配置。
- 平台不按自营筛选结算。

## 落在哪一端

顾客在小程序或在线商城的顾客端看自己的单和倒计时；租户在后台办发货或看账单；平台财务看在线商城的顾客端抽佣和本地对账，不把本地佣金当成已经替店收进可提现。
