# 商城发货与确认收货-泳道

这张图看在线商城的顾客端货怎么发、怎么变成已完成。供应商在订单详情里发货，不在列表行上点一下就发。确认收货或到期自动确认即已完成，不经过待评价。堂食和核销不走这张图。

## 给谁看

开会投在线商城的顾客端履约；测试有售后不能发货、确认收货即完成。细则在《订单支付与结算》；页面在分端《租户后台（在线商城）》《众享源品-在线商城》。

## 关键规则

- 履约中只出现在在线商城的顾客端这条发货链。顾客端口语：待发货 / 待收货；后台书面语：已付待履约 / 履约中。
- 有待处理售后时不能发货、不能确认收货。
- 本轮 C 端常停未付，不应标成已付待发货；后台仍要能看、能在详情发货（闭口）。
- CSV 批量发货可以留；列表行内没有发货按钮。

## 图

```mermaid
flowchart TB
  subgraph 顾客["顾客"]
    direction TB
    cStart((顾客在在线商城的顾客端有一张该发货的单<br/>口语可说待发货；本轮若仍未付则不应当成已付))
    cWait["顾客看见待收货<br/>后台书面语是履约中"]
    cRecv["顾客确认收到货"]
    cDone["订单变成已完成<br/>可以写评价，不能再新开售后"]
    cAuto((到期自动确认同样已完成<br/>没有待评价主状态))
  end

  subgraph 供应商["供应商"]
    direction TB
    sOpen["供应商打开租户后台这一单的详情<br/>不在列表行上点一下就发"]
    sAfter{"这一单有待处理售后吗？"}
    sBlock["不能发货<br/>须先办完售后"]
    sShip["供应商在详情办理发货或限时改运单<br/>履约权限落到发货途中"]
    sCsv["CSV 批量发货可以留<br/>仍是同一套发货结果"]
    sLocal["无此路径：堂食出餐、核销码当发货"]
  end

  subgraph 顾客端订单["在线商城的顾客端订单"]
    direction TB
    oPaid{"钱已经付到平台了吗？"}
    oUnpaid["本轮常见：仍是待付款<br/>不能当成已付待发货去验收真扣款"]
    oOnWay["订单变成履约中<br/>顾客看见待收货"]
    oFinish["确认收货即已完成<br/>不要画出待评价中间态"]
  end

  cStart --> oPaid
  oPaid -->|本轮未付| oUnpaid
  oPaid -->|目标态已付待履约| sOpen --> sAfter
  sAfter -->|有待处理售后| sBlock
  sAfter -->|没有| sShip --> sCsv --> sLocal --> oOnWay --> cWait
  cWait --> cRecv --> oFinish --> cDone
  oOnWay --> cAuto
```

## 不画什么

- 不画店内扫桌、核销、本地提现。
- 无此路径：列表行内发货、待评价中间态、部分退、退货物流、本轮把未付单验收成已付待发货。
- 不画端口、域名、快递公司接口字段。
