# 拼团秒杀-泳道

这张图看两条流程：本地生活店自己上架；众享源品平台开场、供应商报名、平台审。成交仍走同一套付钱。不要把已删的秒杀管理、拼团审核画回来。

## 给谁看

开会讲「店自发一套、源品平台审一套」。细则在《拼团与秒杀》。

## 关键规则

- 有该菜单的本地店都可以自发，不要写死三个业态名。
- 下架后新参失败，旧单不自动关、不自动退。
- 美发/商超拼团不另出主码。餐饮拼团仍扫桌。
- 源品只能报已审货。到期没成团关未付单。本批没有真退。

## 图

```mermaid
flowchart TB
  subgraph 本地生活["本地生活"]
    direction TB
    mStart((租户在租户后台创建拼团或秒杀并上架<br/>价格填元，不经平台审核))
    cSee["本店小程序看见进行中的活动，可以买<br/>首页按归属可以出拼团、秒杀坑，没有活动就空着"]
    cPay["成交仍走本店付钱<br/>钱进该店账户"]
    cDo["餐饮继续扫桌；美发/商超仍用同一张核销主码"]
    mOff["租户下架或停用<br/>新顾客不能再参加，已下的单不自动关"]
  end

  subgraph 众享源品["众享源品"]
    direction TB
    pOpen((平台在商城秒杀或商城拼团里创建场次<br/>不是已删的秒杀管理、拼团审核))
    sApply["在线商城供应商用已审通过的货报名"]
    pReview{"平台审核通过了吗？"}
    pReject["顾客看不见这场<br/>供应商可以改完再报"]
    oSee["在线商城的顾客端看见审过的场次，可以下未付单<br/>钱目标进平台，本轮不真扣"]
    oFail["到期没成团：未付单关掉，活动占用放掉<br/>本批没有真付，也就没有真退"]
  end

  subgraph 不要混["不要混"]
    direction TB
    mixA["无此路径：拿店自发去套源品，或拿平台审去套店内"]
    mixB["无此路径：把本地生活活动接到在线商城的顾客端接口"]
    mixC["无此路径：把已删的秒杀管理、拼团审核写回侧栏"]
  end

  mStart --> cSee --> cPay --> cDo --> mOff
  pOpen --> sApply --> pReview
  pReview -->|没过| pReject
  pReview -->|过了| oSee --> oFail
  mStart --> mixA
  oSee --> mixB
  pOpen --> mixC
```

## 不画什么

- 无此路径：已删经营旧入口、另做一套支付、本批真退款。
- 活动玩法不改一版新规则。不画端口、域名。
