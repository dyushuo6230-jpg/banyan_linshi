# 整单退款-泳道

这张图看已付还没完成的整单怎么退。租户全额退或拒绝。平台只看不办。部分退、退货物流本期无此路径。在线商城的顾客端本轮未付本来就不能申请售后。

## 给谁看

开会投售后边界；测试平台列表不能点办理。细则在《售后与退款》。

## 关键规则

- 仅已付待履约（美发/商超显示待核销）或在线商城的顾客端履约中可新申请。已完成、已取消、已关闭不能新申请。
- 待处理时可撤销。有待处理售后时不能出餐、核销、发货、确认收货。
- 全额退完：订单已关闭；本地该单码不能再核，不补第二张主码。
- 给人看用元。

## 图

```mermaid
flowchart TB
  subgraph 顾客["顾客"]
    direction TB
    cStart((顾客在现用订单或在线商城的顾客端售后入口申请<br/>须是已付还没完成的单))
    cCan{"这一单还允许新开售后吗？"}
    cNo["已完成、已取消、已关闭、本轮未付：都不能新申请"]
    cRevoke["待处理时顾客可以撤销<br/>订单主状态不变"]
    cClosed["顾客看见订单已关闭<br/>本地原码不能再核"]
  end

  subgraph 租户后台["租户后台"]
    direction TB
    mSee["租户待处理只能整单全额退或拒绝<br/>没有确认收到退货"]
    mPart["无此路径：只退一部分金额"]
    mShip["无此路径：退货寄回、填物流"]
    mAfter{"有待处理售后时还想出餐、核销、发货吗？"}
    mBlock["不能办履约<br/>须先退完或拒绝"]
    mRefund["全额退：订单已关闭，钱按现页退回"]
    mReject["拒绝：订单主状态不变<br/>顾客不能当平台已经介入去催"]
  end

  subgraph 平台后台["平台后台"]
    direction TB
    pRead["平台售后管理只读<br/>页签全部 / 待处理 / 已退款 / 已拒绝 / 已撤销"]
    pNo["无此路径：同意、拒绝、仲裁、平台介入中"]
  end

  cStart --> cCan
  cCan -->|不能| cNo
  cCan -->|能| cRevoke
  cStart --> mSee --> mPart --> mShip --> mAfter
  mAfter -->|有售后未了| mBlock
  mSee --> mRefund --> cClosed
  mSee --> mReject
  mSee --> pRead --> pNo
```

## 不画什么

- 无此路径：部分退、退货物流、平台仲裁、超管代退办理口。
- 不新编退款通道状态机。不画端口、域名。
