# 真评价-泳道

这张图看谁能写评价、写完订单变成什么。只有已完成订单能写。本地出餐或核销完成不进待评价，直接已完成，仍可评。在线商城的顾客端详情展示真评价，不是假数据。

## 给谁看

开会讲没有待评价主状态。细则在《众享源品怎么逛买》《本地生活怎么履约》；售后见《售后与退款》。

## 关键规则

- 已完成可评，评完仍是已完成。已取消、已关闭不能评。
- 在线商城的顾客端详情：有该商品已完成单的人才能从详情去写；谁都能看见已提交的真评价。
- 不做先审后发。

## 图

```mermaid
flowchart TB
  subgraph 顾客["顾客"]
    direction TB
    cStart((顾客订单已经已完成<br/>本地出餐/核销或在线商城的顾客端确认收货都会到这里，不进待评价))
    cWrite["顾客提交评价<br/>金额和星级沿用现页"]
    cHall["顾客打开在线商城的顾客端商品详情评价区<br/>能看见已经交上去的真评价"]
    cNo["对该商品没有已完成单：不能从详情去写"]
    cDone((订单仍是已完成<br/>不能因为写了评价再开售后))
  end

  subgraph 评价["评价"]
    direction TB
    eWho{"这张单是已完成吗？"}
    eNo["未完成、已取消、已关闭：不能评"]
    eSave["写入评价管理<br/>不做先审后发"]
    eDetail{"从在线商城的顾客端详情写吗？"}
    eNeed["必须对该商品有已完成单"]
  end

  cStart --> eWho
  eWho -->|不是已完成| eNo
  eWho -->|是| cWrite --> eSave --> cDone
  cHall --> eDetail
  eDetail -->|没有该商品已完成单| cNo
  eDetail -->|有| eNeed --> cWrite
```

## 不画什么

- 无此路径：待评价主状态、假评价、先审后发。
- 不把本地完成画成必须先评才能完成。
- 不画端口、域名。
