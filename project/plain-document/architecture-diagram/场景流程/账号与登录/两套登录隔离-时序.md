# 两套登录隔离-时序

这张图看两套登录态怎么错开：店内票不能调在线商城的顾客端，在线商城顾客端登录票不能调店内；作废其中一套，另一套还在。同一部手机可以同时是店 A 的号和在线商城顾客端的号，不是同一个会话。

## 给谁看

开发交接、测试串池。细则在《用户账号与用户池》《登录会话与口令》；两套怎么分别登录见同夹两张泳道。

## 关键规则

- 店铺池按「哪家店 + 手机」；在线商城顾客端用户池按「在线商城的顾客端 + 手机或账号」。读写必须带着在哪个池。
- 店内票调在线商城的顾客端必须拒绝；在线商城顾客端登录票调店内必须拒绝。
- 退出、改密、封号：只作废这一套。另一套原样可用。
- 不写接口路径、字段名、类名。闲置天数、票过期秒数图上不写死。

## 图

```mermaid
sequenceDiagram
  actor 顾客
  participant 店内 as 店 A 小程序
  participant 本地 as 本地生活
  participant 顾客端 as 众享源品
  participant 源品 as 在线商城的顾客端账号

  顾客->>店内: 在店 A 用店内现有方式登录
  店内->>本地: 请按店铺池认出这是店 A 的人
  本地-->>店内: 发给店内登录票，权限只落在店 A
  顾客->>顾客端: 从「我的」用短信或账密登录，并同意在线商城的顾客端协议
  顾客端->>源品: 请按在线商城顾客端用户池认出这个人
  源品-->>顾客端: 发给在线商城的顾客端登录票，「我的」能看出已登录，不强制绑微信

  顾客->>顾客端: 拿店内那张票去在线商城的顾客端逛、下未付单
  顾客端->>源品: 把店内票当成在线商城顾客
  源品-->>顾客端: 拒绝：这不是在线商城顾客端账号，在线商城的顾客端货架权限不落到这个人
  顾客->>店内: 拿在线商城的顾客端那张票去店 A 点单、付到店
  店内->>本地: 把在线商城顾客端登录票当成店 A 会员
  本地-->>店内: 拒绝：这不是店 A 店铺池的人，钱和券都不能落到店 A

  顾客->>店内: 在店 A 点退出
  店内->>本地: 立刻作废店内这一张票
  本地-->>店内: 店内旧票不能再当本店会员
  顾客->>顾客端: 仍用在线商城顾客端登录票打开「我的」
  顾客端->>源品: 在线商城顾客端登录票还算不算已登录
  源品-->>顾客端: 仍已登录；店内作废不影响在线商城的顾客端这一套

  顾客->>店内: 再次用店内现有方式登录店 A
  店内->>本地: 再发一张店内票
  本地-->>店内: 店 A 会员权限重新落到这个人
  顾客->>顾客端: 在在线商城的顾客端点退出
  顾客端->>源品: 立刻作废在线商城的顾客端这一张票
  源品-->>顾客端: 在线商城的顾客端旧票不能再逛买、不能再下未付单
  顾客->>店内: 仍用刚发的店内票在店 A 点单
  店内->>本地: 店内票还算不算本店会员
  本地-->>店内: 仍是店 A 的人；在线商城的顾客端作废不影响店内这一套
```

## 不画什么

- 不把两套登录合成一张「用户登录成功」图。
- 无此路径：第三方登录全家桶、短信二次验证、设备列表、异地登录提示、顾客端额外 30 分钟闲置。
- 不画支付回调、发品、履约、入驻资格票。
- 不画端口、域名、接口路径、字段名、类名。
