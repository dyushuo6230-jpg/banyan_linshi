# 图怎么读

这套图给人开会投屏、交接看边界。静态图看系统是什么，泳道看谁在哪一步把订单或权限变成什么，时序只看会串端、串钱、串池的先后顺序。图是说明的配图，不是第二套需求。

图在 `architecture-diagram/`，文字在 `doc-desc/`。本篇不抄全目录，挑图看地图《文档地图》。

## 给谁看

开会先看静态四张。要对某条主链，再打开对应场景泳道。开发交接看隔离时序：两套登录、两种支付回调，以及入驻套菜单、商城审品、核销。

## 怎么选图

1. 五端和外部通道 → 《系统上下文》
2. 各端能办什么、两套登录态 → 《应用架构》
3. 共库怎么隔离、两类订单 → 《数据架构》
4. 本机端口、测试/正式域名、两套回调 → 《部署架构》（**唯一写端口和域名的图**）
5. 入驻、登录、发品、履约、支付怎么一步步走 → 场景流程里的泳道
6. 会不会拿店内票调在线商城的顾客端、两套支付回调会不会打到同一处 → 时序

改规则：先改正式文档和功能需求，再改对应白话，最后改图。不要只在图上改流程当已经拍板。

## 每张图挂到哪

| 图 | 先对照的文字 |
|---|---|
| 系统上下文 | 总览《五端与角色》；技术设计《系统怎么拆》 |
| 应用架构 | 《系统怎么拆》《两套C端与独立打包》 |
| 数据架构 | 《账号用户池与登录会话》《数据金额与快照》；抽佣公式见功能需求《业态经营类目与抽佣》 |
| 部署架构 | 《部署与环境》 |
| 场景泳道 / 时序 | 对应功能需求和分端，见地图 |

## 本夹不画

外卖、商城拼团秒杀、AI / 发现对接、真扣款成功（在线商城的顾客端支付只用虚线标留口）、部分退、退货物流、积分、收藏、装修细图、推广员改造、全库 ER、接口参数、类图。
