# 系统上下文

这张图看本期系统盒子和谁在外面。五端都是入口，不是五个互不相干的产品。钱有两条：店内付给该店，在线商城的顾客端目标付给平台（本轮在线商城的顾客端不真扣）。

## 给谁看

开会开场、对「谁用哪一端」。细则在总览《五端与角色》、技术设计《系统怎么拆》。

## 关键规则

- 租户后台是一套系统、四套菜单。
- 店内小程序走本地生活接口；在线商城的顾客端只调自己的接口。
- 短信、上传沿用同一通道；支付通道按「付到店 / 付给平台」分开。
- 端口和进程名见《部署架构》，本图不写。

## 图

```mermaid
flowchart TB
  subgraph 外部
    支付店["微信等：店商户号<br/>只给本地生活付到该店账户"]
    支付平台["微信等：平台商户号<br/>在线商城的顾客端目标付给平台；本轮虚线留口、不真扣"]
    短信OSS["短信 / 上传存储<br/>两套顾客端共用通道、不混业务"]
  end

  subgraph 本期系统
    入驻["入驻申请人<br/>入驻页交执照、选业态"]
    平台["平台运营<br/>审店、审商城货、配树和菜单"]
    租户["已通过租户<br/>同一套租户后台、侧栏按业态"]
    店内["店内顾客和店员<br/>众享营销：点单/扫桌/核销"]
    在线商城的顾客端["在线商城顾客<br/>众享源品：逛已审货、下未付单"]
  end

  入驻 -->|"提交待审，不问自营"| 平台
  平台 -->|"通过后套该业态菜单"| 租户
  租户 -->|"本地上架即可本店卖"| 店内
  租户 -->|"挂叶子送审，通过后在线商城的顾客端可售"| 在线商城的顾客端

  店内 -->|"付到该店账户"| 支付店
  在线商城的顾客端 -.->|"本轮不调起；目标付给平台"| 支付平台
  店内 -->|"发验证码、传图"| 短信OSS
  在线商城的顾客端 -->|"发验证码、传图"| 短信OSS
```

## 不画什么

- 把两条支付画成同一个通道。
