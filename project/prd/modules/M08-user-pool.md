## REQ-070 用户分池共表

| 字段 | 值 |
|---|---|
| 需求编号 | REQ-070 |
| 名称 | 用户分池共表 |
| 目标与价值 | 店与店、店与众享源品 - 在线商城账号互不替代 |
| 需求变化状态 | 修改 |
| 结论标签 | 已确认 |
| 开放项状态 | PRD 后技术评估（池字段如何落地） |
| 角色 | 本地生活消费者；众享源品 - 在线商城用户 |
| 前置条件与入口 | 注册/登录 |
| 页面和字段 | 两池：众享营销 - 本地生活池、众享源品 - 在线商城池。PRD 不写表名作为实现要求；业务上必须能区分池 |
| 主流程 | 1. 在店 A 小程序注册 → 仅店 A 店铺池账号。2. 店 B 须再注册。3. 众享源品 - 在线商城须再注册 |
| 分支和异常 | 不得把众享源品 - 在线商城用户做成虚拟店会员或占用官方店铺身份冒充自营。老数据视为店铺池。不得把店铺身份为空的脏数据默认当成众享源品 - 在线商城 |
| 业务规则 | 不新建众享源品 - 在线商城用户表。唯一性在池内：店铺池按店 + 手机号；众享源品 - 在线商城池按商城池 + 手机号/账号 |
| 状态变化 | 账号启用/禁用沿用现码（资料未重写） |
| 权限和数据范围 | 读写必须带池 |
| 消息通知 | 无 |
| 审计要求 | 无 |
| 非功能约束 | 不写建表语句 |
| Given/When/Then | Given 手机号已在店 A 注册；When 打开店 B 小程序；Then 仍须在店 B 注册，不能直接当店 B 会员。Given 同一手机号未在众享源品 - 在线商城注册；When 打开众享源品 - 在线商城；Then 须单独注册 |
| 来源编号 | SRC-REQ-001、DEC-003 |
| 关联设计图 | 无 |

## REQ-071 众享源品 - 在线商城手机号与账号密码登录

| 字段 | 值 |
|---|---|
| 需求编号 | REQ-071 |
| 名称 | 众享源品 - 在线商城手机号与账号密码登录 |
| 目标与价值 | 多端综合商城可独立登录 |
| 需求变化状态 | 新增 |
| 结论标签 | 已确认 |
| 开放项状态 | 无 |
| 角色 | 众享源品 - 在线商城用户 |
| 前置条件与入口 | 众享源品 - 在线商城登录页 |
| 页面和字段 | 手机号登录；账号密码登录。注册/改密的密码框旁须写明顾客端规则（至少 8 位且同时有字母和数字，DEC-062） |
| 主流程 | 用户用手机号或账号密码登录众享源品 - 在线商城池 → 进入逛买 |
| 分支和异常 | 密码错误：失败并计入锁定策略（与 M09 租户/平台锁定不是同一产品，C 端锁定资料未写 → 待配置，不得抄后台次数）。口令存储与设密复杂度见 REQ-080 / DEC-062 |
| 业务规则 | 本题不给众享营销 - 本地生活自动打开同一套密码登录。众享源品设密走顾客端规则，不走平台/租户那套 10 位三类 |
| 状态变化 | 登录成功建立可作废会话（REQ-082） |
| 权限和数据范围 | 仅众享源品 - 在线商城池 |
| 消息通知 | 无 |
| 审计要求 | 登录失败不宜写明文密码到日志（REQ-089） |
| 非功能约束 | 无 |
| Given/When/Then | Given 众享源品 - 在线商城已注册用户；When 用正确账号密码登录；Then 进入众享源品 - 在线商城池会话。Given 仅有众享营销 - 本地生活账号；When 用该密码登众享源品 - 在线商城；Then 不能当作已注册众享源品 - 在线商城用户。Given 顾客在众享源品注册或改密；When 密码不足 8 位或没有字母和数字；Then 失败且页面已写明规则 |
| 来源编号 | SRC-REQ-001、DEC-003、DEC-062 |
| 关联设计图 | 无 |
