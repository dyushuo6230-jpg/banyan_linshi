| 替代文档 | 无 |

全业态走同一入驻 H5。业态选项仅为「入驻可选」开启的根（DEC-046）。资质沿用当前 mall 入驻页执照（DEC-032）。在线商城强制 1～3 个启用中的一级。审核通过后按业态套菜单。待审/已通过同手机不能再提；驳回后只能提新申请（DEC-043）。存量待审不猜业态（DEC-044）。入驻票隐私见 M09。

## REQ-010 全业态同一入驻 H5

| 字段 | 值 |
|---|---|
| 需求编号 | REQ-010 |
| 名称 | 全业态同一入驻 H5 |
| 目标与价值 | 不按业态拆第二套入驻产品 |
| 需求变化状态 | 保留 |
| 结论标签 | 已确认 |
| 开放项状态 | 无 |
| 角色 | 入驻申请人；推广场景下的访客 |
| 前置条件与入口 | 现码入驻 H5（方案要求所有业态走这套；路径保持现状产品，不在此写实现目录） |
| 页面和字段 | 现有入驻流程页面 + 业态选择（及在线商城一级，见 REQ-003） |
| 主流程 | 1. 打开入驻 H5。2. 按业态填报。3. 提交待审 |
| 分支和异常 | 凭证无效/过期：不能提交，须重新获取入驻资格（现码有入驻票，规则见 REQ-083）。待审或已通过的同手机不能再提新申请。驳回后只能提交新申请重新待审，不能改原单（DEC-043）。网络失败：现码已有幂等则沿用，不另编策略 |
| 业务规则 | 入驻可选为开的根均走同一入驻产品（含以后新增的本地根）。再提口径 DEC-043 |
| 状态变化 | 草稿/待审沿用现码入驻状态（资料未重定义枚举则保留现状） |
| 权限和数据范围 | 持有效入驻凭证的申请人 |
| 消息通知 | 沿用现码 |
| 审计要求 | 提交记录 |
| 非功能约束 | 无 |
| Given/When/Then | Given 美发申请人打开入驻；When 开始申请；Then 进入同一套入驻 H5 而非另一产品。Given 在线商城申请人；When 申请；Then 仍是同一入驻 H5。Given 同手机已有待审申请；When 再提交；Then 失败。Given 申请已驳回；When 再入驻；Then 只能提新单重新待审 |
| 来源编号 | SRC-REQ-001、SRC-CODE-006、DEC-043 |
| 关联设计图 | 无 |

## REQ-011 入驻按业态采集

| 字段 | 值 |
|---|---|
| 需求编号 | REQ-011 |
| 名称 | 入驻按业态采集 |
| 目标与价值 | 本地生活不选下级类目；在线商城采集可售一级 |
| 需求变化状态 | 修改 |
| 结论标签 | 已确认 |
| 开放项状态 | 无（资质沿用现码执照，DEC-032） |
| 角色 | 入驻申请人 |
| 前置条件与入口 | 已选业态 |
| 页面和字段 | 业态相关项见 REQ-003。资质：沿用当前 mall 入驻页营业执照采集，不新编分业态证件，不把身份证/行业许可证升格必填 |
| 主流程 | 选择业态 → 本地生活只填执照等现页项；在线商城另选 1～3 个一级 → 提交 |
| 分支和异常 | 执照缺失不能提交。在线商城一级个数不合 1～3 不能提交 |
| 业务规则 | 本地生活（全部非在线商城根，含新增）不选经营类目下级、不选一级。在线商城强制 1～3 个启用中的一级（DEC-032） |
| 状态变化 | 提交后待审 |
| 权限和数据范围 | 仅本人申请 |
| 消息通知 | 沿用现码 |
| 审计要求 | 采集快照 |
| 非功能约束 | 无 |
| Given/When/Then | Given 申请人选商超；When 填写；Then 不出现「必须选经营类目下级」，须上传执照，不要求身份证或行业许可证。Given 选在线商城；When 验收资质；Then 仍只验现码执照项，另验 1～3 个一级 |
| 来源编号 | SRC-REQ-001、DEC-001、DEC-032 |
| 关联设计图 | 无 |

## REQ-012 入驻不再询问是否自营

| 字段 | 值 |
|---|---|
| 需求编号 | REQ-012 |
| 名称 | 入驻不再询问是否自营 |
| 目标与价值 | 平台无自营店，避免申请人勾选自营 |
| 需求变化状态 | 修改 |
| 结论标签 | 已确认 |
| 开放项状态 | 无 |
| 角色 | 入驻申请人；平台审核人 |
| 前置条件与入口 | 入驻表单；众享源品 - 在线商城侧若仍出现该问法同样去掉 |
| 页面和字段 | 无「是否自营」 |
| 主流程 | 表单不采集自营；审核页不展示/不要求该问 |
| 分支和异常 | 旧申请带自营答案：不作为身份，也不据此改业态 |
| 业务规则 | 身份只看业态。新单不写入有业务含义的自营「是」 |
| 状态变化 | 无 |
| 权限和数据范围 | 无 |
| 消息通知 | 无 |
| 审计要求 | 无 |
| 非功能约束 | 列可保留默认否，本期不为删列（DEC-006） |
| Given/When/Then | Given 打开入驻表；When 填写；Then 看不到是否自营。Given 审核一笔新申请；When 判定身份；Then 只看业态 |
| 来源编号 | DEC-006 |
| 关联设计图 | 无 |

## REQ-013 平台审核入驻

| 字段 | 值 |
|---|---|
| 需求编号 | REQ-013 |
| 名称 | 平台审核入驻 |
| 目标与价值 | 继续由平台决定谁能开店 |
| 需求变化状态 | 保留 |
| 结论标签 | 已确认 |
| 开放项状态 | 无 |
| 角色 | 平台运营 |
| 前置条件与入口 | 平台入驻审核列表（现码已有） |
| 页面和字段 | 申请详情含业态；在线商城含已选 1～3 个一级。无自营问项 |
| 主流程 | 1. 待审列表。2. 通过或驳回。3. 通过则生成/启用租户并套菜单（REQ-014） |
| 分支和异常 | 驳回：申请人不能当已入驻租户使用后台。重复点击通过：结果仍是一户，不得生成第二套店（现码若已有则保留）。存量待审无业态：不猜；审核时补选业态，补选可列出全部业态根（含入驻可选已关），在线商城再补 1～3 个启用中一级；补不了则驳回，申请人按新 H5 再提（DEC-044） |
| 业务规则 | 未通过不能经营。平台不因此成为自营店。存量映射 DEC-044 |
| 状态变化 | 待审 → 通过 / 驳回（沿用现码枚举名，PRD 不写字段名） |
| 权限和数据范围 | 平台审核全部申请；租户不可审自己 |
| 消息通知 | 沿用现码 |
| 审计要求 | 审核人、时间、结果 |
| 非功能约束 | 无 |
| Given/When/Then | Given 待审申请；When 运营通过；Then 租户可登录对应后台。Given 驳回；When 申请人用该申请经营；Then 不可。Given 无业态的存量待审；When 运营审核；Then 须补选业态（在线商城还须 1～3 个一级），不能由系统猜 |
| 来源编号 | SRC-CODE-001、SRC-REQ-001、DEC-044 |
| 关联设计图 | 无 |

## REQ-014 通过后按业态套菜单

| 字段 | 值 |
|---|---|
| 需求编号 | REQ-014 |
| 名称 | 通过后按业态套菜单 |
| 目标与价值 | 开业即看到该业态工作台 |
| 需求变化状态 | 新增 |
| 结论标签 | 已确认 |
| 开放项状态 | 无（无业态老店默认餐饮，DEC-011）
| 角色 | 系统在审核通过时执行；租户使用结果 |
| 前置条件与入口 | 入驻审核通过；该业态菜单模板已存在 |
| 页面和字段 | 租户侧栏为对应模板。现网单树可作为餐饮模板初稿；其余业态可从餐饮复制后删减（DEC-002） |
| 主流程 | 通过 → 按申请业态套模板 → 租户登录见到该模板菜单 |
| 分支和异常 | 模板未配置：不得假装套成功。无业态老店：按餐饮模板套用（DEC-011） |
| 业务规则 | 按该店业态菜单快照套用（种子四套或克隆出的新根页签）。隐藏项侧栏不可见但仍非安全边界 |
| 状态变化 | 租户进入可经营 |
| 权限和数据范围 | 仅该租户账号 |
| 消息通知 | 沿用现码开户/通过通知 |
| 审计要求 | 记录套用了哪套模板 |
| 非功能约束 | 无 |
| Given/When/Then | Given 在线商城申请通过；When 租户登录；Then 菜单为在线商城模板且无独立小程序相关能力。Given 餐饮申请通过；When 登录；Then 为餐饮模板。Given 无业态老店完成迁移；When 登录；Then 为餐饮模板 |
| 来源编号 | DEC-002、DEC-011 |
| 关联设计图 | 无 |
