## 1. 项目背景和问题陈述

现码（`CURRENT_BASELINE`，分支 `feature/multiple_business_model`）以餐饮向本地生活为主：平台后台、租户后台、mall C 端、众享营销 - 本地生活、入驻 H5 已在运行。无业态字段；租户菜单单树；抽佣在店铺字段；用户按店隔离；平台有拼团秒杀审核和 `is_self` 自营语义；众享源品 - 在线商城前端页面已在，独立后端服务不存在。

本期要把同一套系统扩成 **本地生活（可增根）+ 在线商城**，并承认并行的 **ToB 营销独立端**（不是第四个本地业态根，也不是众享源品商城；CR-042）。种子根仍是餐饮、美发、商超、在线商城；本地根可按 DEC-046/047 新增（拷贝源仅餐饮/美发/商超）。本地生活继续店内小程序、支付到该店账户，普通商品店内上架即可本店可售、平台不审（DEC-026）；在线商城供应商无独立小程序，商品经平台审核后出现在众享源品 - 在线商城，平台统一收款（多支付留口）并按类目抽佣。ToB 营销：专用小程序/H5，平台配置营销展示内容，C 端浏览功能与数据看板；本期不做留资后台闭环。同时按冻结正文一次落地登录/会话/口令改造。

问题：现码无法按业态入驻、套菜单、计佣和履约；登录存在明文旁路口令、无法立刻作废会话、本地生活可被客户端伪造店号等安全缺口。

## 4. 使用场景

1. 新租户在入驻 H5 选择「入驻可选」为开的业态根提交，平台审核通过后进入对应菜单模板的租户后台。
2. 拷贝源为餐饮的店：顾客到店扫桌点餐并支付到该店账户，出餐/确认完成后订单已完成、不进待评价。拷贝源为美发/商超的店：顾客支付后持核销码到店核销，核销成功后订单已完成、不进待评价。
3. 本地生活租户发布普通商品：店内上架即可本店可售，平台不审；可自行推到本店推荐栏。发布拼团/秒杀无需平台审核：勾本店货，秒杀自建场次，拼团上架即卖（DEC-070）。优惠券由该店自己发。
4. 在线商城供应商发品并送审；通过后众享源品 - 在线商城用户浏览、加购、下未付单，付给平台（微信/支付宝等留口，本轮不真扣款），按商品一级类目抽佣后再结算。众享源品 - 在线商城使用平台优惠券。平台可开秒杀/拼团场，供应商用已审货报名，审过可售。
5. 同一手机号在店 A 小程序、店 B 小程序、众享源品 - 在线商城是三个独立账号。
6. 后台人员持续操作不被无故踢下线；离开超过闲置须重登；退出或改密后旧会话立刻失效。

## 6. 总体业务流程

```text
入驻 H5 选业态（在线商城可多选一级类目）
  → 平台审核入驻
  → 按业态套租户菜单模板
  → 本地生活：店内分类发品 → 上架即可本店可售（不审）→ 小程序经营（扫桌或核销；可自发拼团秒杀；店内券；本店推荐栏）
     支付到该店账户；抽佣按业态节点费率快照
  → 在线商城：按平台类目发品（不强制店铺分类）→ 平台审品 → 众享源品 - 在线商城上架
     平台统一支付（微信/支付宝等留口，本轮不真扣款）；抽佣按商品所属一级类目节点费率快照；平台券
     可选：平台开秒杀/拼团场 → 供应商用已审货报名 → 平台审过 → C 端可进、可下未付单（DEC-068）
```

登录：平台/租户网页走 Cookie+CSRF；小程序走 Header。众享源品 - 在线商城与众享营销 - 本地生活分池。认店只约束众享营销 - 本地生活。

## 8. 公共金额、状态和权限规则

### 8.1 金额与抽佣（已确认，DEC-001）

- 权威费率在**节点**上：本地生活看**业态根**；在线商城看**商品所属平台类目一级**（DEC-021）。在线商城发品必须挂叶子，计佣仍向上取该一级（DEC-055 收窄 DEC-021「任意深度」）。节点费率为空或为 0，新单按**不抽佣**快照（DEC-058）；不编造根费率死数字与类目节点名单。
- 在线商城发品类目与计佣一级为同一套（DEC-012）：结构在「平台类目」维护；经营类目**不再挂子节点**，只给对应一级配置费率/排序/启停。
- 给人看、给人填的金额用元；库内仍为分（DEC-054）。`system_config` 最低提现等配置仍按分存储。
- 入驻多选一级只表示可售范围，不把多个费率平均到店铺。
- 新单使用下单时节点费率**快照**；店铺上的抽佣字段不再作为新单权威。
- 商品未挂一级时：不可售、不可下单（DEC-013），不得用缺省费率或 0 抽佣**冒充已挂一级**放行。已挂一级但费率为空或 0：可售，快照为不抽佣（DEC-058）。

支付通道（已确认，SRC-REQ-001，无相反来源、无未关闭冲突）：

### 8.3 权限与数据范围

- 租户只能操作本店数据；身份以业态为准，不以自营标记为准（DEC-006）。
- 菜单隐藏不是安全边界，接口仍按权限校验（DEC-002）。
- 平台非超管管理员必须至少有一个角色才能保存；无角色不能当运营用。每次请求按当时库中的角色/超管标记授权。平台超管只属于 `ZadminDister`；其它角色勾不上管理员/角色管理/菜单管理/API 管理（REQ-025、REQ-086、DEC-005、DEC-065、CR-033）。
- 平台列表/筛选/统计/结算不以 `is_self` 为准。
- 用户与订单必须带**用户池**，防止串号（DEC-003）。
- 本地生活 C 端购物车/下单/支付/券/预约不信客户端传来的店号（DEC-005）。
