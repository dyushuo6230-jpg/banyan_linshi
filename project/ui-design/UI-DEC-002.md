- 主题：重写源品底栏时，原「发现」坑位怎么用
- 选择：方案 A
- 限制条件：五坑顺序为购物、附近、AI、购物车、我的；发现业务仍不做、不对接；购物车进现有购物车路由；图标暂用发现资源；本决策不改代码
- 被拒方案：B（继续藏掉发现、只留四坑）、C（按设计图把发现做回来）
- 知情决策证据：用户口头修改 → 复述 → 回复「确认该决策」→ DECISION_APPLY

## 已确认规则

1. 众享源品 C 端底栏 **五个坑**：购物、附近、AI、购物车、我的。中间仍是 AI。
2. **发现业务本期仍不做**（REQ-063 / DEC-008）。不得把发现列表、关注、内容详情做成必验能力，不得把第四坑链回发现页。
3. 重写底栏时：原发现坑改为 **购物车**，文案为「购物车」，点击进入现有购物车页（现码 `/addon/shop/pages/goods/cart`，若路由有变以当时真源为准）。
4. 购物车 **图标先用发现的图**（含未选中/选中若只有一套就先用一套）。有专用购物车图标后再换。在此之前，视觉验收 **不卡**「必须与购物车语义图标一致」，**要卡**「第四坑是购物车文案且能进车、不是发现」。
5. 《Tab Bar交互》等设计图上的「发现」**不得**作为一比一还原项。anydesign 与视觉修复循环必须按本 UI-DEC 覆盖该图。
6. 购物车页面本身仍按 DEC-008：本批不像素验收。本决策只约束底栏入口。
7. 本决策 **不** 修改 `go-uni-app-online`。落地等到点名重写底栏（建议与首页、分类一组）。

## 未扩大

- 不恢复发现 Tab 业务
- 不新做购物车高保真页
- 不改 Tab 顺序为其它排列
- 不跑 anydesign、不改现网底栏
