# 分端页面相关文档编写方案

这是「给人看的白话说明」里 **分端页面** 这一夹的编写方案，不是需求真源，也不覆盖 `prd/`。

正式口径仍在 `docs/project/prd/`、`baseline/`、`changes/`。本夹是按「打开哪一端、哪一级菜单、哪一个页面」翻译出来的同步副本，开会时对着屏幕念。

落地目录（尚未写正文）：

```
docs/project/plain-document/doc-desc/分端页面/
```

---

## 1. 这套文档干什么

| 项 | 约定 |
|---|---|
| 回答什么 | 打开这一端，侧栏/Tab/页面上有什么；这一页干什么；重要表单填什么 |
| 不回答什么 | 抽佣公式、用户池规则、支付到谁——那些写在「功能需求」；进程、端口、表名——那些写在「技术设计 / 部署」 |
| 读者 | 老板、业务、测试、交接时对着产品走菜单的人 |
| 和功能需求的关系 | 规则只在功能需求里写全。分端里点到规则时，一句话说明 + 指向对应功能需求文档，禁止两套各写一套抽佣 |

---

## 2. 必须遵守的编写规则

1. **单向同步。** 规则从已确认产品口径摘；会上新口径先改进正式文档，再刷本夹。禁止「页面说明里改了规则、代码按说明做」。
2. **按批同步，不整夹重生。** 只改本批碰到的端和页面。
3. **正文不出现文档编号。** 不写需求号、决策号、变更号。写「哪一端、哪个菜单、订单变成什么」。
4. **标题树对齐现码 + 已点名菜单。** 举例里的菜单只说明细度，不是清单。已删的菜单（平台秒杀管理、拼团审核、周边分类、WiFi 等）不要为了完整写回来。
5. **每一级标题下都要有说明。** 一级到四级，标题下面至少一段人话，不许空标题。
6. **重要细点单独成节。** 例如在线商城发品必须挂叶子、众享源品不真扣款、未付倒计时，用四级标题单独写，不要埋在段落里。
7. **待配置不编造。** 未点名的校验、字数、错误文案、费率死数字，写「沿用现页」或「未定」。
8. **复制来的现码菜单先占位。** WiFi 已无；OSS、短信、会员等：树上要有，正文写「有此菜单，沿用现页，本期未另定」，不按每个输入框写到字段级。
9. **以落地事实校正页面。** 规则跟已确认口径；「现在实际露出哪几个 Tab、哪张是现用页」跟当时代码。
10. **框架示例页不进说明书。** 后台 `widgets` / `examples` / 模板演示页不算产品功能。

---

## 3. 细度（按这个写，不要按举例菜单抄）

```markdown
# 端的名称
这一端给谁用、和另外几端什么关系。

## 一级菜单或 Tab
这段菜单/Tab 整体干什么。

### 具体页面
这一页打开后能看见什么、能办什么。

#### 重要细点或表单要点
只写和规则有关、选错会不可售/不能提交/会串端的字段。
普通现码框：列出名字，写「沿用现页」。
```

不要机械地每个页面都套「功能描述 / 发布商品」两个四级标题。有表单、有验收细点才加四级。

P0 闭环页写到字段级：入驻、审店、发品/审品、订单、支付、履约、登录、众享源品首页/详情/下单/我的。  
其余现码复制页写到「有、沿用」即可。


不把租户后台和本地生活小程序的店员页合成一本：经营在网页后台，出餐/核销在店内小程序，混成一本菜单会对不上。

餐饮 / 美发 / 商超 **不要写成三份全文**。本地生活租户后台一本 + 开篇对照表；仅某业态有的菜单单独标明。在线商城差很多，单独一本。

## 5. 和代码、正式文档怎么对齐

| 来源 | 本夹怎么用 |
|---|---|
| 已点名侧栏 | 后台标题树按这个，不按仓库里所有 vue |
| 现码页面 | C 端用现用路径（新首页、新订单、现用详情），旧页/静态复刻页标注「非现用主链」 |
| 已确认规则 | 「必须 / 不能 / 变成什么」只摘正式口径 |
| 本批已落地 | 通道用量、无自营、首页模块归属、周边仅 CPS、未付倒计时、真评价等按已落地写 |
| 明确未做 | 真扣款、部分退、退货物流、AI/发现对接、商城拼团秒杀、外卖 |
| 未定 | 用户列表是否拆两个池菜单、参数里支付字段清单、费率死数字 —— 写未定 |

标题名若和当时测试库侧栏不一致，以库里的显示名为准改标题，不要把已删项写回。

编写时不要在正文出现编号。本方案为了对齐真源，维护者可对照：平台侧栏点名、租户四套菜单有无、入驻与执照、两类生意主口径、众享源品页面口径与本轮能力收口、未付关单与倒计时。

### 6.1 `平台后台.md`

# 平台后台

给平台运营用的 Web。侧栏：秒杀管理、拼团审核已删；周边分类已删；补了通道用量、首页模块归属、周边 CPS、众享源品协议。没有「设为自营」。

## 登录

网页登录。闲置要重登；退出或改密后旧会话立刻作废；持续操作不无故踢。不要求短信二次验证。

## 仪表盘

看今日概览、待办、趋势。不作为本期业务验收主链。

## 商户管理

管入驻、已开业租户、业态树、租户菜单模板、店内首页模块归属。

### 入驻审核

待审 / 已通过 / 已驳回。通过后按业态套该店菜单。待审或已通过的同一手机不能再提；驳回只能提新单。

#### 审核时要看什么

店铺名、业态、可售一级（仅在线商城）、执照图、识别结果。存量待审没有业态时，通过前必须补选。在线商城还要 1～3 个启用中的一级。没有「是否自营」。

### 商户列表

已开业租户。可冻可解冻、可关闭。无「设为自营」。本地店可勾「周边业态」。抽佣列只展示「按业态根 / 按一级」，权威费率在经营类目节点上。

### 经营类目

业态树。种子根：餐饮、美发、商超、在线商城，不可删。可新增本地根，拷贝源只能是餐饮（扫桌）或美发/商超（核销）。入驻可选开关控制能不能被选。本地抽佣看业态根；在线商城经营类目不再挂子节点，只给对应一级配费率。空或 0 表示新单不抽佣。未配置的费率数字不编造。

#### 和平台类目的关系

在线商城发品树、计佣一级，和「商品管理 → 平台类目」是同一套。这边改的是费率/排序/入驻，名称以平台类目为准。

### 商户菜单

同一页切换业态改模板。新本地根会多一个从拷贝源克隆的页签。「无」= 该业态没有这一行；小魔推是隐藏不是删除。隐藏不是权限边界。

### 首页模块归属

决定本地生活一套首页里，哪些模块通用、哪些按业态开。预约默认仅餐饮；本店服务默认餐饮+美发。在线商城无独立小程序，不走这页。

## 商品管理

平台类目、品牌、只审在线商城商品、全站商品列表、评价。不审本地生活普通商品。

### 平台类目

树可改。发品必须挂到叶子；计佣仍取该叶子所属一级。停用一级或节点后，已上架不可再售，不改商品行，已下单不改快照。

### 品牌管理

品牌库保留。发品可选，不强制。

### 商品审核

只办理在线商城送审。可单条或批量通过/驳回。通过后众享源品可售。本地生活普通商品不出现在待审办理范围。

### 商品列表

平台侧查看，不是供应商发品页。

### 评价管理

看评价、改显示状态。众享源品详情展示已提交的真评价，不在这页编评价。

## 用户管理

### 用户列表

现码一个用户列表。业务上已分「店内池」和「众享源品池」。是否拆成两个菜单未定，写未定。

## 订单管理

平台看单、看售后。售后只读，没有「平台介入中」、没有仲裁办理。金额给人看用元。

### 订单列表

筛选、详情。状态书面语与现码订单主状态对齐（无中间态 40；确认收货即完成）。

### 售后管理

看售后单。部分退、退货物流本期不做。

## 营销管理

只留平台优惠券。无秒杀管理、无拼团审核。

### 平台优惠券

众享源品用平台券。供应商不发店铺券。未点名字段沿用现页。

## 内容管理

轮播、公告、两套协议。众享源品首页只读平台轮播；没数据就不轮，不用静图冒充。

### 轮播管理

平台 banner。众享源品首页读这里。

### 公告管理

沿用现页。

### 协议管理

本地生活协议。

### 众享源品 - 在线商城协议

与上一页分开。C 端用户协议/隐私读这一套。

## 市场管理

### 推广员管理

现码保留。本期不改造、不纳入必验。

## 周边管理

无周边分类。只留平台 CPS 目录。

### 周边CPS

平台维护目录。本地店只能引用并上下架。平台下架后，店内和众享源品附近都不再出。

## 财务管理

结算、提现、佣金、流水。本地生活佣金是对账，禁止假入账。在线商城按商品一级类目快照抽佣后再结算。

### 结算管理 / 提现审核 / 佣金报表 / 商户流水

按现页写能办什么。最低额等未点名数字不编造。给人看用元。

## 数据统计

### 交易统计 / 用户统计 / 商户排行

沿用现页，不另定指标。

### 通道用量

看谁用了短信/OSS。不编造用量字段。

## 系统管理

管理员、角色、菜单、API、参数配置、快递公司、登录日志、操作日志。现码「短信配置」菜单已停用，不作为给人看的入口。参数里支付/商城字段清单未点名，不编造。

### 管理员 / 角色

非超管必须至少有一个角色才能保存。

### 参数配置

商城/支付等设置仍走这里，不新建「在线商城设置」根菜单。

### 6.4 `租户入驻.md`

# 租户入驻

全业态同一套入驻 H5。不是租户后台，也不是众享源品里已隐藏的入驻入口。

## 推广入驻码

展示入驻码/链接。码失效不能继续。

## 登录 / 校验手机

凭证无效或过期不能提交。同一手机待审或已通过不能再提。

## 填写申请

选入驻可选的业态根 → 主体类型 → 执照 → 现页项。本地生活不选经营类目下级。在线商城必须选 1～3 个启用中的一级。无「是否自营」。

#### 表单要点

必填：业态、主体类型、店铺名、11 位手机、营业执照且识别成功。在线商城一级个数不合不能提交。

## 提交结果

待审。驳回不能改原单，只能提新申请。通过后进对应菜单模板的租户后台。

## 我的店铺 / 进度

只展示申请状态，不在这里经营商品。

### 6.5 `众享营销-本地生活.md`

# 众享营销 - 本地生活

店内小程序。一套首页，模块按平台归属过滤。用户在店铺池。认店只约束本端。底部 Tab 由该店装修配置。现用订单页是新订单列表/详情，不把拷贝来的旧商城订单页当本期说明。

## 进店首页
