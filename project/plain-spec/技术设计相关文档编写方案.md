# 技术设计相关文档编写方案

这是「给人看的白话说明」里 **技术设计** 这一夹的编写方案，不是正式技术真源。

正式设计仍在 `docs/project/architecture/`、`design/`、`api/`、`database/`。本夹给人交接、测试、运维开会用：系统怎么拆、钱和账号怎么隔离、怎么部署、怎么测。不把本夹升格成第二套 G8。

落地目录（尚未写正文）：

```
docs/project/plain-document/doc-desc/技术设计/
```

---

## 1. 这套文档干什么

| 项 | 约定 |
|---|---|
| 回答什么 | 五端对应哪些服务、两套 C 端为什么不能混接、登录态怎么隔离、钱怎么走、怎么部署、怎么测 |
| 不回答什么 | 业务规则全文（功能需求）；按钮和表单（分端页面）；完整 OpenAPI、逐表字段、类图 |
| 读者 | 开发、测试、运维、技术交接 |
| 比「只写 5 篇横切」多什么 | 补上能力域薄说明 + 安全/数据/多端打包，避免交接时还要翻正式设计才能讲清「扫桌和核销落在哪」 |

原先只保留 5 篇横切，开会够用、交接偏薄。正式技术设计已经按十个能力域写过，白话侧 **不要再译十本带类名的设计**，但应当用业务语言写清「每种能力落在哪一端、怎么串、关键约束」。

---

## 2. 必须遵守的编写规则

1. **单向同步。** 从已确认架构/设计/部署口径摘；本批落地事实用来校正「现在实际怎么跑」。禁止从本夹反写 ADR。
2. **按批同步。** 只刷本批碰到的篇。
3. **正文零编号。** 编号留在真源。
4. **类名、目录、表名能少则少。** 点到「哪一端调哪套」即可。
5. **端口和域名只在《部署与环境》写死。** 其它篇写「独立服务 / 测试域名 / 正式域名」，需要数字就指向部署那篇。
6. **共库不是共业务。** 独立进程不等于独立库；隔离靠业态、用户池、订单池，不要写成「两个库」。
7. **待配置不编造。** Redis 几号库、JWT 过期秒数等未冻结项写未定。
8. **隐藏菜单不是安全边界。** 权限按接口校验，分端写「看不见」，本夹必须写「直访仍要拒绝」。


## 5. 横切九篇

### 5.1 `系统怎么拆.md`

- 平台后台、租户后台、入驻 H5、本地生活、众享源品是五端，不是五个互不相干的产品。
- 租户后台是一套系统、四套菜单，不是四套后台 URL。
- 本地生活 C 端走本地生活服务；众享源品独立服务、独立打包。禁止接到另一套接口或租户后台。
- 平台/租户是后台暴露面，不是独立业务模块。
- 忽略且不考虑仓库里标明忽略的旧目录。
- 结构示意用白话框，配以后的静态结构图。
- 可附当时仓库目录对照（文件夹名字 + 人话职责），方便交接对代码。不写端口和域名（仍只在《部署与环境》）。不把依赖夹、构建产物当业务。不是第二套需求、不是开工清单。

### 5.2 `两套C端与独立打包.md`

- 本地生活一套代码；众享源品多端同一套，有差异必须条件编译。
- 众享源品只调自己的接口。H5 整包独立静态进程，根路径进首页。
- 页面口径以众享源品现用工程为准：新页优先，旧页/静态复刻不作为主链。
- 本轮页面前端接口：可打 iOS/安卓/微信小程序/H5、够申请支付；不把完整逛买当这些接口的必验。
- 本机和测试/正式怎么指过去，细节指向《部署与环境》。

### 5.3 `账号用户池与登录会话.md`

- 一张用户相关数据、两个池：店铺池 vs 众享源品池。
- 登录态两套，作废互不影响。
- 网页 Cookie+CSRF；小程序 Header。
- 认店只限本地生活。
- 闲置踢、忙不踢、闸立刻废、库无明文密码。
- JWT 算法、过期秒数未冻结则写未定。

### 5.4 `权限与菜单模板.md`

- 四套模板存在菜单数据里，按业态套。新本地根拷贝快照后只改自己那套。
- 「无」= 该业态没有这一行；隐藏 = 行还在、侧栏不可见（仅小魔推）。
- 隐藏不是安全边界：直访旧路由仍要按权限拒绝。
- 平台侧栏「无」= 删行，不用隐藏。
- 在线商城无员工/角色，只用主账号。

### 5.5 `数据金额与快照.md`

- 给人看、给人填用元；库内仍为分。配置里最低提现等仍按分存，界面要换算。
- 新单抽佣用下单时节点费率快照，不改已下单。店铺上的抽佣字段不再作为新单权威。
- 用户池、业态、订单归属靠字段逻辑隔离，本期共库。
- 不把数据字典搬进来。需要表名时指向正式数据文档，本夹最多举「记在哪一类数据上」。

### 5.6 `支付结算与资金流向.md`

- 本地：支付到该租户账户。
- 商城：平台统一收款；后续通道微信/支付宝/金豆留口，实现可与本地生活不同。
- 本轮 C 端不调起这三通道；订单可未付；支付按钮保留。
- 回调打对应服务，不能串到另一套。
- 本地佣金对账，禁止假入账。商城按一级类目快照抽佣后再结。
- 通道参数、商户号清单未点名不编造。

### 5.7 `安全边界.md`

单独成篇，避免只写在登录里被当成「改密码」。

- 菜单隐藏 ≠ 授权。
- 不能串店、不能串池、不能用本地生活票调众享源品。
- 入驻票过期不能提交。
- 本期明确不做的安全能力列清单（短信二次验证、设备列表等），避免交接时当缺口补进去。
- 非超管管理员必须有角色。

### 5.8 `部署与环境.md`

**允许写端口、域名的唯一专页。**

- 本机：平台、本地生活、租户、入驻、众享源品 API、众享源品 H5 各是什么进程；众享源品 API 与 H5 不要接到本地生活或租户后台。
- 测试一律测试域名，正式一律正式域名（按已确认部署口径写全，不在其它篇重复）。
- 共库、短信/OSS 沿用，不等于业务可以混接。
- Jenkins / 面板 / Nginx 由运维加的，写清「文档不代替运维清单」。
- 未合主分支不把开发进度写成已上线。

### 5.9 `测试怎么做.md`

- 测哪几条主链：入驻→套菜单→发品→履约或审品→支付/未付→结算对账。
- 两套 C 端不要串测（账号、接口、域名、协议）。
- 闭口标准：后台和本地生活能闭口就闭口；众享源品前端接口先做到可打包、可申请支付。
- 测试环境用哪套域名，指向部署篇。
- 不抄测试用例编号。不写未实现的监控大盘。
- 未付倒计时、超时关单、真评价、不真扣款，列为必看现象，不写实现步骤当攻击说明。

## 6. 能力怎么落地（五篇薄说明）

每篇不超过两页。功能规则仍以功能需求为准，这里只补「落在哪、怎么串」。

### 6.1 `业态树与入驻.md`

- 树由平台维护；入驻只读树。
- 审核通过后绑定该店业态菜单快照。
- 在线商城可售一级存在入驻绑定上，发品时校验范围。
- 新本地根：菜单快照 + 履约跟拷贝源，不新写第四套履约代码路径。

### 6.2 `商品两种流程.md`

- 一个商品能力、两种流程：本地店内分类不审；商城挂叶子送审。
- 审核台不拆成两个产品。
- 可售判断：挂一级、类目未停用、商城须过审。
- 推荐：平台推荐与类目列表双轨，不要写成一个开关。

### 6.3 `履约扫桌与核销.md`

- 履约是独立能力，只出现在本地生活。
- 餐饮：桌台 + 扫桌；出餐/确认完成关单。
- 美发/商超：核销码，整单一次；后台和小程序店员页都能核。
- 不把核销做成餐饮主路径，不把扫桌做成商超主路径。

### 6.4 `拼团秒杀怎么落地.md`

- 独立能力，本期只暴露给本地生活 / 对应 C 端。
- 租户后台创建上下架；平台菜单已删经营入口。
- 成交仍走交易，不另做一套支付。
- 在线商城模板与众享源品接口都不提供这能力。

### 6.5 `订单状态与售后.md`

- 主状态与展示：无 40；确认收货即完成；后台书面语、C 端口语。
- 未付关单：打开即关 + 定时仍留；倒计时到点不能支付。
- 售后办理范围；平台只读。
- 本地生活现用订单页与众享源品订单页都要覆盖展示对齐，不覆盖本地生活拷贝来的旧商城页。

## 9. 写完后的自检

- 没有把 G8 十份设计翻译成十份带表结构的白话。
- 端口只出现在部署篇。
- 没有教人怎么接到另一套环境「方便联调」而违反独立打包口径。
- 隐藏菜单的章节明确写了「不是安全边界」。
- 能力薄说明没有重写功能规则全文。
- 未合主分支的实现，不写成「生产已如此」。
