# 白话文档生成方案

本文回答三件事：方案能不能施工、哪里做不到万无一失、施工时用哪张对照表和哪两段提示词。

落地根目录：`docs/project/plain-document/`。规格以同目录编写方案为准，总树以 `白话文档总体编写规划.md` 为准。

**结论：可以按本文施工第一批；不能保证万无一失。** 未先做第零批（空目录 + 对照表 + `doc-map.md`）时，不要直接生成 71 份正文。

---

## 0. 能不能施工、是否万无一失

**可以施工**，前提是把「三份正文永远一样」改成「出处、现码入口、上次同步版本能对上」。上一版方案缺这几块，本文已补上：

| 已收紧 | 做法 |
|---|---|
| 对照表落点 | 只用 `docs/project/progress/PLAIN_SYNC.yaml`，不进开会包 |
| 差异基线 | 每行记录产品需求版本 + git commit，没有基线不准走差异模式 |
| 先预检再写 | 两种模式都先列「将写哪些文件 / 发现哪些冲突」，你回「按预检施工」才落盘 |
| 一次范围 | 口令写死文件清单，禁止 71 份一次出 |
| 冲突不私了 | 规则跟正式文档；菜单有无跟现码；对不上只记账 |
| 缺口往哪记 | `docs/project/progress/PLAIN_SYNC_GAPS.md`，不写进白话当已定 |

**做不到万无一失**，必须接受：

- 现码和正式口径本来就可能不一致；白话不能替你做变更决策。
- 提示词会漏页、写串附近/CPS、把「敬请期待」写成已上线。预检和抽查消大部分，消不干净。
- 未点名字段、复制菜单，模型容易编造。口令里要写「沿用现页 / 未定」。
- 第一批之后若不跑差异模式，对照表会立刻过期。

施工顺序：**第零批（目录 + 地图 + 空对照表）→ 预检 → 第一批初次创建 → 以后只走差异同步。** 本文提示词就是干这个的。3.1 加正式章节可以稍后，先用本文口令开工。

## 1. 权威怎么排

| 内容 | 权威 | 白话怎么写 |
|---|---|---|
| 规则（审不审、抽佣、能不能做） | 正式文档 `prd/`、`baseline/`、`changes/` | 只摘已确认 |
| 侧栏有无、现用哪张页、Tab 露出几个 | 现码（菜单库脚本 + 前端现用页） | 按现码；已删菜单不写回 |
| 端口、域名 | 已确认部署口径 | 只出现在《部署与环境》和《部署架构》 |
| 现码有、正式文档没有的规则 | 不是白话来源 | 记缺口，禁止写成已定 |
| 口径已定、代码未到 | 正式文档 | 可写口径，并写「代码未到」 |
| 白话本身 | 永远是输出 | 禁止反写正式文档 |

## 2. 要维护的三份（不是开会正文）

| 文件 | 用途 |
|---|---|
| `docs/project/progress/PLAIN_SYNC.yaml` | 71 行对照：白话路径、规则从哪、现码看哪、对应图、状态、上次同步版本 |
| `docs/project/progress/PLAIN_SYNC_GAPS.md` | 现码与口径不一致、提示词不敢写进白话的项 |
| `docs/project/plain-document/doc-map.md` | 给人看的目录；状态列计划中/已同步；**零编号** |

不要：需求编号对每一段白话；在白话正文里写「本页来自某某模块」。

`PLAIN_SYNC.yaml` 一行最小字段：

```yaml
- id: FN-货物审核
  白话: doc-desc/功能需求/商品类目与审核.md
  规则从:
    - docs/project/prd/modules/M04-goods.md
  现码看:
    - nunu-go-api/app/merchant/web/src/views/goods/edit.vue
    - nunu-go-api/app/admin/web/src/views/goods/audit.vue
  图:
    - architecture-diagram/场景流程/商品/
  状态: planned | synced | stale
  prd_version: "0.1.32"   # 上次同步时的产品需求版本；planned 可空
  git_commit: ""          # 上次同步时的仓库 commit
```

状态：`planned` 未写正文；`synced` 已与当时真源和现码对齐；`stale` 真源或现码相对该行的版本变了。  
没有 `prd_version` + `git_commit` 的 `synced` 行，差异模式视为无效，改走初次创建（只补缺篇）。

## 3. 两种模式（都必须先预检）

共同加载（每次都要）：

1. 3.1 主提示词（已在本仓库生效的那份）
2. `docs/temp/文档计划/白话文档总体编写规划.md`
3. 本批涉及到的分册编写方案（总览 / 功能需求 / 分端 / 技术设计 / 架构图 / 地图编写说明，用到哪份加载哪份）
4. `PLAIN_SYNC.yaml`（没有则先第零批建空表，不准猜清单）
5. 当前产品需求总册 + 本批相关模块
6. 本批相关现码（菜单脚本、现用页面，不要整仓无目的扫描）

共同禁令：

- 白话正文和图上不出现需求号、决策号、变更号
- 不编造待配置；不把说明升格成需求
- 不整夹重生；不超出口令里的文件清单
- 餐饮/美发/商超不复制三份全文
- 店员核销不写进租户 Web
- 附近/CPS 两边规则不写串
- 众享源品本轮不画/不写成真扣款成功
- 先输出预检，等「按预检施工」再改文件

### 3.1 初次创建模式

**何时用：** 目标文件在对照表里是 `planned`，或目录还不存在。  
**不要用：** 文件已是 `synced`/`stale`（那种走差异）。

预检必须列出：

- 将创建的路径清单（= 口令范围 ∩ `planned`）
- 将读取的真源和现码入口
- 已发现的口径/现码冲突（预备写入缺口，不写进正文）
- 不会写的内容（本期不做、未定）

施工后：把这些行改为 `synced`，写入当时产品需求版本和 commit；更新 `doc-map.md` 状态列；缺口进 `PLAIN_SYNC_GAPS.md`。

### 3.2 差异内容同步模式

**何时用：** 对照表已有 `prd_version` + `git_commit`，且正式文档或相关现码相对该基线有变更。  
**不要用：** 对照表是空的、或行上没有基线。

步骤：

1. 用基线 commit 对 `docs/project/prd/`、`baseline/`、`changes/` 以及对照表「现码看」里的路径做 diff（或至少列出变更文件）。
2. 把命中的白话行标 `stale`（若尚未标）。
3. 预检：只列出本次要刷的 `stale` 文件、每篇改什么、哪些冲突只记账。
4. 分类写：口径变了 → 先确认已进正式文档，再改功能需求白话，再改分端/图；只是菜单/页面变了 → 只改分端（和对应图）；口径和代码不一致 → 只记缺口。
5. 刷完改回 `synced`，更新版本和 commit。

禁止「根据代码发明规则」。代码多出来的行为不是已确认口径，就不是白话同步来源。

## 4. 第零批（生成正文之前必做）

没有这批，两种提示词都不要跑。

1. 按总体编写规划建 `docs/project/plain-document/` 空目录树（可建空 `.md` 占位，或只建文件夹）。
2. 按 `plain-document文档地图编写说明.md` 第 5 节写入 `doc-map.md`，状态全是计划中。
3. 建 `PLAIN_SYNC.yaml`：71 行都填上「白话 / 规则从 / 现码看 / 图」，状态全 `planned`。现码路径允许第一批写正文时再补全，但白话路径必须与总树一致。
4. 建空的 `PLAIN_SYNC_GAPS.md`（表头即可）。

第零批可以人工做，也可以单独下口令「只建目录和对照表、不写正文」。

## 7. 预检通过才算可写（抽查）

施工后至少抽这几条，不通过就修，不准标整批 `synced`：

- 正文和图找不到需求号、决策号
- 抽佣没有在三篇里各说一套
- 附近/CPS 店内和在线商城的顾客端没写串
- 租户后台没有餐饮/美发/商超三份发品全文
- 众享源品支付是未付/留口，不是扣款成功
- 已删菜单（平台秒杀经营、周边分类、WiFi）没有写回来
- 端口只出现在部署文字和部署图
- 对照表行数 = 总树文件数；本次清单内的行有版本和 commit
- 发现的口径/现码冲突在缺口文件里，不在白话里被抹平
- 流程图和泳道每个框是完整业务话（谁、变成什么、钱或权限落到哪、无此路径），没有「下单 / 支付 / 完成」这类空标题框

## 8. 和 3.1 以后怎么接

本文可以先当开工口令用。点头后再把「对外说明同步」收进 3.1：

- 不新增 G 阶段
- 触发：批次结束且已确认改动已进正式需求之后（36A 之后）
- 先把对照表相关行标 stale，再跑差异口令
- 说明不得升格成 PRD

在那之前，用本文口令即可，不要等 3.1 改完才建第零批。

## 9. 你现在该做的下一件事

1. 用第 6.1 节口令做第零批（或让我按预检建目录和空表）。  
2. 选定第一次初次创建的「本次清单」（建议先总览 7 篇，量小可抽查）。  
3. 跑初次创建预检，你看完再说施工。  
4. 抽查第 7 节。通过后再加分端/技术/图。  
5. 之后每个开发批次结束走差异模式，不要再全量生成。

没有第零批对照表，就还不能说「可以生成我想要的文档」——只能说规格已定、生成器还没有基线。
