# 架构图相关文档编写方案

这是「给人看的白话说明」里 **架构图** 这一夹的编写方案，不是正式架构真源。

正式架构仍在 `docs/project/architecture/`、`design/`。本夹给人开会投屏、交接看结构和主链。图是说明的配图，不另起一套需求。

参考了通用《项目架构图整理指导文档》的 6 类图（上下文、应用、数据、部署、泳道、时序），按本项目裁剪：两条产品线、五端、两套收款、两种履约；本期不做外卖、商城拼团、真扣款、部分退。

落地目录（先不画图）：

```
docs/project/plain-document/architecture-diagram/
```

---

## 1. 这套图干什么

| 项 | 约定 |
|---|---|
| 回答什么 | 系统边界、五端怎么摆、数据怎么隔离、怎么部署；谁在哪一步干什么 |
| 不回答什么 | 业务规则全文（功能需求）；按钮和表单（分端页面）；完整 ER、接口参数、类图 |
| 读者 | 开会（静态图 + 泳道）；开发交接时看少数隔离时序 |
| 和指导文档的差别 | 不按「一个用户端」画 27 条通用商城流程；登录、发品、支付都必须按两条产品线拆 |

静态图描述「系统是什么」，泳道描述「业务怎么做」。时序只给会串端、串钱、串池的少数几张。

---

## 2. 必须遵守的编写规则

1. **单向同步。** 规则从已确认口径摘；会上新口径先进正式文档，再改图。禁止只在图上改流程当需求。
2. **按批画，不整夹一次画完。** 只画本批碰到的场景。
3. **图上零编号。** 不写需求号、决策号、变更号。
4. **类名、表名、接口路径能少则少。** 泳道写角色和步骤；时序写「哪一端调哪套」，不写参数。
5. **端口和域名只出现在《部署架构》。** 系统上下文只画五端和外部系统。
6. **共库不是共业务。** 数据图标明同一套库、靠池和业态隔离，不要画成两个库。
7. **待配置不编造。** Redis 几号库、K8s、监控产品、未定费率不画死。
8. **本轮事实和目标态要分开。** 众享源品真扣款用虚线标「留口」，不要画成本轮已经扣成功。
9. **每张图一个 `.md`。** 用途、谁看、关键规则（人话）+ 图（优先 Mermaid）。需要对外投影再另存同名 `.drawio` / `.png`，源以 Markdown 为准。
10. **一张图不表达所有信息。** 系统级和场景级分开；泳道不要画到字段级。
11. **图要达到完整业务话密度。** 流程图和泳道每个框必须写清：谁、对象/订单变成什么、钱或权限落到哪、本期没有的路标「无此路径」。关键判断用菱形，关键异常（超时、驳回、作废）用分支。禁止「下单 / 支付 / 完成」这类空标题框。时序每条消息用人话，不写接口路径、字段名、类名。静态图框和箭头也必须有人话含义（哪一端、付到店还是付给平台），不要求写成订单步骤长句。图下「关键规则」可以短，框里的字不能短。

---

## 3. 每张图固定骨架

```markdown
# 中文标题
这张图看什么（三句话）。

## 给谁看
开会 / 测试 / 开发交接。

## 关键规则
人话短注。细则指向功能需求中文名，不在图上写长文。

## 图
Mermaid（或嵌入图片）。

## 不画什么
本期没有的分支标「无此路径」，不要用指导文档里的通用步骤填上。
```

泳道：每个参与方一条道；椭圆开始/结束、矩形操作、菱形判断。正常路径为主，关键异常（驳回、超时、码作废）用分支，不要把售后每一种理由都画上。每个矩形/菱形必须是完整业务话，禁止空标题框。

时序：只画对象之间的先后顺序。不出现接口路径、字段名、类名。每条消息仍要用白话写清在干什么。

## 4. 目录结构

```
docs/project/plain-document/architecture-diagram/
├── 图怎么读.md
├── 静态架构/
│   ├── 系统上下文.md
│   ├── 应用架构.md
│   ├── 数据架构.md
│   └── 部署架构.md
└── 场景流程/
    ├── 入驻与审核/
    ├── 账号与登录/
    ├── 商品/
    ├── 本地生活履约/
    ├── 众享源品逛买/
    ├── 订单支付与结算/
    ├── 售后与评价/
    └── 营销周边/
```

不按「用户侧 / 租户侧 / 平台侧」三大夹切：同一条入驻既有申请人又有平台，按角色分夹会把一张泳道拆碎。按业务场景分夹，泳道里再分角色。

根上只放 `图怎么读.md`。文件总清单仍以 `doc-map.md` 为准；增删图先改本文，再改地图。

每个场景夹：

```
场景名/
├── …-泳道.md     必有（该场景需要画的那些）
└── …-时序.md     仅本文标了「要时序」的才有
```

## 5. 根目录：`图怎么读.md`

要写：

- 静态图看结构，泳道看谁在哪一步干什么，时序只看会串的调用顺序。
- 改规则先改正式文档和功能需求，再改图。
- 每张图挂到哪篇白话说明（用中文名）。
- 本夹不画：外卖、商城拼团秒杀、AI/发现对接、真扣款成功、部分退、退货物流、积分、收藏、装修细图、推广员改造。

不要把 `doc-map.md` 的目录树再抄一遍，点到「图在本夹、文字在 doc-desc」即可。

## 6. 静态架构（4 张，对应指导 1～4）

系统级，通常各 1 张，架构稳定后少改。对应技术设计横切，图比文字更适合投屏。

| 文件 | 画什么 | 不画什么 | 挂到 |
|---|---|---|---|
| `系统上下文.md` | 系统盒子 + 五端（入驻 H5、平台后台、租户后台、本地生活、众享源品）+ 外部（微信/支付宝、短信、OSS）。箭头只标「付到店 / 付给平台 / 发短信」 | 端口、进程目录、内部模块 | 总览《五端与角色》；技术设计《系统怎么拆》 |
| `应用架构.md` | 按五端列能力：审店审品、四套菜单、店内发品、商城送审、扫桌/核销、在线商城的顾客端逛买。下一层只写「共用库、两套登录态」 | 十个英文能力域名、类图 | 《系统怎么拆》《两套C端与独立打包》 |
| `数据架构.md` | 逻辑实体：业态树、租户、两种商品、两个用户池、两类订单、费率快照、店内券/平台券、CPS 目录。标明共库、靠池和业态隔离 | 逐表字段、全库 ER、Redis 几号库 | 《数据金额与快照》《账号用户池与登录会话》 |
| `部署架构.md` | 本机各进程、测试/正式两套域名、众享源品不要接到本地生活或租户后台。支付回调两套。**唯一允许写端口/域名的图** | 编造 K8s、监控、多活 | 《部署与环境》 |

## 7. 场景流程：各夹文件

### 5.1 `入驻与审核/`

| 文件 | 优先级 | 泳道角色 | 要点 |
|---|---|---|---|
| `入驻与审核-泳道.md` | 必画 | 申请人、入驻页、平台审核、租户后台 | 选入驻可选业态 → 执照 → 商城选 1～3 个一级 → 待审 → 通过套菜单。无自营勾选。驳回只能提新单 |
| `入驻与审核-时序.md` | 建议 | 入驻页 → 入驻服务 → 平台审核 → 菜单套用 | 标「只读业态树」，不写字段 |

挂到：《租户入驻与审核》；分端《租户入驻》《平台后台》入驻审核节。

### 5.2 `账号与登录/`

指导里「一张用户登录图」在本项目会画错，必须拆。

| 文件 | 优先级 | 要点 |
|---|---|---|
| `本地生活登录-泳道.md` | 必画 | 店铺池、认店只约束本端、小程序 Header |
| `众享源品登录-泳道.md` | 必画 | 独立池、短信或账密、不强制绑微信、协议读商城协议 |
| `两套登录隔离-时序.md` | 必画 | 两套登录态作废互不影响；不能拿店内票调在线商城的顾客端。本夹最值得画的一张时序 |

不画：第三方登录全家桶、设备列表、短信二次验证（本期不做）。

挂到：《用户账号与用户池》《登录会话与口令》。

### 5.3 `商品/`

「发布 + 审核」合成一张会把本地「上架即可售」画没，必须拆。

| 文件 | 优先级 | 要点 |
|---|---|---|
| `本地生活发品-泳道.md` | 必画 | 店内分类、上架即可本店可售，平台不审 |
| `在线商城发品与审核-泳道.md` | 必画 | 挂叶子 → 送审 → 平台审核 → 众享源品可售。未挂一级不可售 |
| `商城审品-时序.md` | 建议 | 租户提交 → 审核台 → 在线商城的顾客端可售。不写接口路径 |

品牌可选、类目停用不可再售用注记，不必单独成图。

挂到：《商品类目与审核》。

### 5.4 `本地生活履约/`

指导没有扫桌/核销，本项目必须单开此夹。

| 文件 | 优先级 | 要点 |
|---|---|---|
| `餐饮扫桌到出餐-泳道.md` | 必画 | 扫桌 → 点单 → 付到店 → 出餐/确认完成 → 已完成、不进待评价 |
| `美发商超核销-泳道.md` | 必画 | 已付 → 核销码 → 店员小程序或租户后台整单一次核销 → 已完成。无天数、无过期自动退 |
| `核销-时序.md` | 建议 | 店员页或后台 → 本地生活服务 → 码作废。全额退后码不可再核 |

不画外卖。预约仅餐饮且受首页模块归属，P2，文字即可。店员出餐/核销不要画成「只有租户 Web」一条道。

挂到：《本地生活怎么履约》；分端《众享营销-本地生活》。

### 5.5 `众享源品逛买/`

| 文件 | 优先级 | 要点 |
|---|---|---|
| `浏览到下未付单-泳道.md` | 必画 | 首页平台轮播 → 已审商品 → 立即购买下未付单。购物/加购可标敬请期待。不调起真扣款，支付按钮保留 |
| `未付超时关单-泳道.md` | 必画 | 打开列表/详情或去支付 → 超时立刻关成已取消；倒计时到点不能付。本地生活现用订单页同样则在图上加注，或与在线商城的顾客端共用一张 |

浏览搜索可省略。AI/发现不画流程。

挂到：《众享源品怎么逛买》；分端同名。

### 5.6 `订单支付与结算/`

「在线支付」不能画成一张扣款成功图，必须拆两条资金链。

| 文件 | 优先级 | 要点 |
|---|---|---|
| `本地生活支付到店-泳道.md` | 必画 | 顾客、店、支付通道、钱进该店账户 |
| `众享源品支付-泳道.md` | 必画 | 本轮：下未付单、不调起通道。目标态用虚线标微信/支付宝/金豆留口、平台收款 |
| `两种支付回调-时序.md` | 必画 | 店商户号回调打本地生活服务；平台商户号回调打众享源品服务。不能画成同一个回调 |
| `商城发货与确认收货-泳道.md` | 必画 | 供应商发货 → 待收货 → 确认收货即完成。无中间态 40 |
| `本地生活结算对账-泳道.md` | 必画 | 佣金只对账，禁止假入账 |
| `在线商城抽佣结算-泳道.md` | 必画 | 下单快照一级类目费率 → 平台抽佣 → 结给供应商。空或 0 = 该新单不抽佣 |

商城提现并进抽佣结算泳道，不必再拆。本地生活无提现菜单，不要画「三套都提现」。

挂到：《订单支付与结算》《钱和券怎么算》；技术设计《支付结算与资金流向》。

### 5.7 `售后与评价/`

| 文件 | 优先级 | 要点 |
|---|---|---|
| `整单退款-泳道.md` | 必画 | 顾客申请、租户看、平台只读不仲裁。部分退、退货物流标「本期无此分支」 |
| `真评价-泳道.md` | 建议 | 已完成订单才能写；详情展示真评价。本地出餐/核销完成不进待评价 |

挂到：《售后与退款》。

### 5.8 `营销周边/`（P1，第二批）

| 文件 | 优先级 | 要点 |
|---|---|---|
| `拼团秒杀-泳道.md` | 建议 | 仅本地生活租户自发布，平台不审。在线商城无此分支 |
| `优惠券-泳道.md` | 建议 | 店内券 vs 平台券画成两条，不要汇成一张通用券 |
| `周边与CPS-泳道.md` | 建议 | 必须画清分叉：店内按本店已勾业态；在线商城的顾客端附近是平台级、不带某供应商 |

小魔推、推广员、装修、库存预警：不建夹、不建图。

挂到：《拼团与秒杀》《优惠券》《周边与到店服务》。

## 8. 和指导文档通用清单的对照

| 指导里的场景 | 本项目 |

| 营销秒杀拼团 | 仅本地，P1 |
| 用户举报、公告 | 不画 |
| 退货物流 | 本期不做，泳道上标无此分支，不单独成图 |

## 9. 数量与批次（先闭口，不一次画完）

**第一批（能把主链开会投出来）**

- 静态 4 张
- 泳道：入驻审核、两套登录、本地发品、商城发品审核、扫桌出餐、核销、在线商城的顾客端下未付单、未付关单、付到店、商城发货确认收货、两套结算
- 时序：两套登录隔离、两种支付回调

大约：**4 静态 + 12 泳道 + 2 时序**。

**第二批**

- 整单退款、真评价、拼团秒杀、优惠券、周边 CPS
- 时序：入驻套菜单、商城审品、核销

**明确不进本夹**

- 全库 ER、接口参数时序、类图
- AI/发现、外卖、商城拼团、真扣款成功路径（口径改了先改进正式文档，再加图）

## 12. 写完 / 画完后的自检

- 没有文档编号。
- 端口只出现在部署架构。
- 没有把餐饮/美发/商超画成三个独立系统。
- 登录、发品、支付都按两条产品线拆开了，没有「一个用户端」大图。
- 众享源品支付是虚线留口，不是本轮扣款成功。
- 核销出现在店员小程序和租户后台，不是只画 Web。
- 附近/CPS 若已画，店内和在线商城的顾客端规则没有画成同一条。
