## 2. 业务 / 技术 / 安全分离

### 业务需求（候选，来自本批）

- 口令：库和接口不再保存/返回可登录明文；生产无默认 `123456`；重置/入驻密码只亮一次并强制首次改密
- 会话：后台忙时不无故掉线，闲置超时要重登；退出/改密/重置立刻作废旧票
- 认店：本地生活 C 端下单/支付/购物车只认服务端按小程序解析出的店，不信客户端传来的店号
- 票面隐私：入驻票解开无手机号；C 端票尽量不放 `openid`
- 验收五条（文档口径）：忙不踢、闲必踢、闸立刻废、串不了店、库无明文密码

### 技术建议（不得批准为架构）

- 三端 JWT 密钥分开；商家 Redis 白名单对齐平台；后台闲置 TTL + 换短票；C 端 access+refresh
- 入驻票改 `jti`，手机号放 Redis
- 网页后台 HttpOnly Cookie + CSRF（与「后期单独立项」在两份文档间不一致，见冲突）
- 日志/网关脱敏；全站 HTTPS/HSTS
- 施工顺序、配置数字、中间件改法：属实施，进 G8/G9，不进 PRD 当表结构/框架名

### 安全改造清单（候选，A1～A17，未裁决是否本期全部落地）

A1 密钥分开；A2 停 `text_password`；A3 生产去默认口令；A4 商家可踢人；A5 闲置换票；A6 入驻去手机号；A7 C 端双票；A8 票面去 openid；A9 日志脱敏；A10/A11 认店；A12 超管查库；A13 商家登录锁定；A14 密码策略；A15 网页 Cookie；A16 HTTPS；A17 前端 401 换票。

文档明确本期不做：短信二次验证、设备列表、异地登录提示、加密 JWT、从商家票删除 `merchant_id`、登录再套 RSA、C 端 30 分钟闲置。
