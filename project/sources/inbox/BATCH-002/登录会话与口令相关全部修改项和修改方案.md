# 登录会话与口令相关全部修改项和修改方案

> 文档位置：`docs/temp/TypesBusines/登录会话与口令相关全部修改项和修改方案.md`  
> 日期：2026-09-03  
> 状态：**一期上线完整清单**（一次交付、一次发版，不按周拆上线）。  
> 配套：`docs/temp/TypesBusines/登录机制与安全改造实施方案.md`（原理与现码盘点）。**改什么、谁改、何序、如何验收以本文为准。**

**交付口径：** 可以一次做完再上线，不必分三次发版。文中「顺序」只是 **动手先后**（先有花名册才能续期，先定存票方式前端才好接），不是分期上线。

**默认数字（产品未另定时按此写配置）：** 后台闲置 30 分钟；后台同一段登录寿命 12 小时；C 端 refresh 7 天无活动作废；短票（access/后台 JWT）30～120 分钟，快过期且会话仍在则换新票。

**上线不做（不是已知 bug）：** 短信二次验证、设备列表、异地登录提示、给 JWT 加密、从商家票删除 `merchant_id`、登录密码再套 RSA、C 端也做成 30 分钟闲置。

**不要改：** 商家接口继续信 JWT 里的 `merchant_id`（正确做法）。

## 0. 一次做完要达成什么

| 目标 | 含义 |
|---|---|
| 口令 | 库和接口不再躺可登录的明文；生产无默认 `123456`；重置只亮一次并逼改密 |
| 会话 | 一直操作不无故掉线；停手超过闲置要重登；退出/改密/重置立刻作废旧票 |
| 认店 | C 端下单/支付/购物车只认服务端解析出的当前店，不信可伪造的店号 |
| 票面 | 入驻票解开无手机号；C 端票尽量无 `openid` |
| 密钥与传输 | 三端 JWT 密钥不同；全站 HTTPS |
| 存放与日志 | 网页票走 HttpOnly Cookie；日志无完整密码/Token |

验收过关的五条：**忙不踢、闲必踢、闸立刻废、串不了店、库无明文密码。**

## 1. 全部修改项

| 编号 | 修改项 | 为什么要改 | 不做会怎样 |
|---|---|---|---|
| A1 | 生产三端 `jwt.secret` 分开且足够长；mall `merchant_secret` 与商家密钥配对 | 同一把钥匙时，商家 `uid=5` 的票可能被 C 端当成用户 5 | 跨端撞号、伪造身份 |
| A2 | 停写停读 `text_password`；历史列清空；账号列表/重置/C 端店铺详情不再返回明文密码；告知改成只亮一次 | 登录虽用 bcrypt，旁边另存能直接登录的原文 | 拖库或调接口=拿到商家后台钥匙 |
| A3 | 生产登录页不预填密码；种子/演示 `123456` 不进生产；超管首次必须改密 | 默认口令等于门没锁 | 打开后台就能试 `admin/123456` |
| A4 | 商家 JWT 对齐平台：Redis 一账号一票；退出/改密/重置/禁用立刻作废 | 现在只验签，退出了旧票还能用到过期 | 离职、重置、丢票无法踢人 |
| A5 | 平台+商家：闲置续期 + 快过期换短票 + 绝对寿命 | 现在从登录起死倒计时，忙也被踢、挂机还不踢 | 机制不合理，也不安全 |
| A6 | 入驻票只放 `jti`，手机号放 Redis | 票可解开，手机号等于印在工牌上 | 日志/截图/偷票直接看到手机号 |
| A7 | C 端 access + refresh；refresh 可作废；闲置按天 | 一张 7 天业务票，丢了窗口太大 | 偷票能当顾客用一周 |
| A8 | C 端票尽量不放 `openid`，用 `uid` 查库 | 同 A6，隐私 | 解开票看到微信身份 |
| A9 | 日志/网关脱敏：密码、Token、Authorization、`text_password`、小程序 secret | HTTPS 管不了落盘的明文 | 运维、ELK 里长期躺着能登录的材料 |
| A10 | C 端认店：登录后店身份只信服务端用 appid 解析的店；购物车/下单/券按这店走；不信可伪造的头/query `merchant_id` | 票里没有店，改头可能串店 | 登录安全改完仍能串别人店下单 |
| A11 | 支付、预约等仍信客户端 `merchant_id` 的接口，改为信服务端店或票，与 A10 同一原则 | 已知越权口子 | 付钱/预约打到别的店 |
| A12 | 平台每次请求以库为准核角色/超管，不长期只信票上的 `is_super` | 取消超管后旧票可能仍是超管 | 权限回收不及时 |
| A13 | 商家登录失败锁定与平台对齐（验证码+失败次数） | 平台有、商家若没有则扫号更易 | 商家后台被撞库 |
| A14 | 密码策略：最短长度；重置/入驻后强制首次改密 | 和 A2/A3 配套 | 弱口令、初始密码一直用 |
| A15 | 网页后台 Token：HttpOnly+Secure+SameSite Cookie；配套 CSRF；小程序仍用 Header | `localStorage` 遇 XSS 整票被偷 | 会话改完，网页一被注入就白改 |
| A16 | 强制 HTTPS / HSTS | 无 TLS 时密码和票都是明文上路 | 前面全白做 |
| A17 | 前端 axios：401 换票重试；新票写入（Cookie 则靠浏览器）；禁止 `console.log` 票和密码 | 否则 A5/A7 用户侧仍是到点踢或丢票 | 机制在后端、体验在前端，缺一不可 |

## 3. 修改方案（落地形态）

### 3.1 口令（A2 / A3 / A14）

- `merchant_user.password` 继续 bcrypt，**不再写、不再读** `text_password`；历史 `UPDATE` 清空。  
- 入驻通过/重置：随机密码只亮一次（弹窗或短信）→ 只存哈希；列表、详情、mall 店铺接口禁止返回明文。  
- 生产构建去掉登录预填与演示账号；超管/商家主账号首次登录强制改密；最短密码长度写入校验。

### 3.2 后台会话（A4 / A5 / A12 / A13）

```
登录 → 短 JWT + Redis「此账号当前这一张」
每次接口 → 验签 + 对花名册 + 拨满闲置 TTL + 查库核超管/角色
快过期且花名册还在 → 发新票（Set-Cookie 或响应头，与 A15 一致）
闲置到点 / 寿命到点 / 退出 / 改密 / 重置 / 禁用 → 撕花名册
商家登录失败次数锁定，与平台同一套规则
```

商家中间件必须与平台一样对 Redis，不能只验签。

### 3.3 C 端与入驻（A6 / A7 / A8）

- 登录发 **access**（调业务）+ **refresh**（只能换 access）；refresh 记 Redis，退出/封号/闲置按天作废。  
- 打开小程序或 401：refresh 换票，失败再微信登录。  
- 入驻：票面 `scp=apply` + `jti`；Redis `jti → 手机号`。  
- 消费者票用 `uid`，不放 `openid`。

### 3.4 认店（A10 / A11）

- 当前店 = 服务端用小程序 appid（及既有可信绑定）解析出的 `merchant.id`。  
- 购物车、下单、券、支付、预约：**禁止**信任客户端传来的 `merchant_id` 作为记账店铺。  
- 商家后台仍信 JWT 内 `merchant_id`，两套不要混。

### 3.5 密钥、传输、存放、日志（A1 / A9 / A15 / A16 / A17）

- admin / merchant / mall 三套 `jwt.secret`；mall 验商家票用 `merchant_secret`。  
- 全站 HTTPS + HSTS。  
- **网页后台只做 Cookie 一版**，不要先 `localStorage` 再迁；Cookie：HttpOnly、Secure、SameSite，并做 CSRF。小程序继续 `Authorization`。  
- 401 换票重试；禁止把票和密码打进 console/日志。  
- 访问日志默认不记 body；敏感字段打码。

## 4. 施工顺序（同一次上线内）

1. 数字写进配置项（闲置/寿命/refresh）。  
2. A16 HTTPS + A1 密钥 **方案**定稿（值上线再换，代码读配置）。  
3. A2 + A3 + A14 口令。  
4. A4 商家白名单（平台已有则对齐）。  
5. A5 + A12 + A13 闲置、换票、超管查库、商家锁定（挂同一本 Redis）。  
6. A6 + A8 入驻 `jti`、C 端去 openid。  
7. A7 mall 双票。  
8. A10 + A11 认店（与双票一起测）。  
9. A15 + A17 网页 Cookie+CSRF，小程序 Header+双票（存票只做一版）。  
10. A9 日志（代码中间件 + 网关）。  
11. 预发换正式密钥、清空 `text_password`、全员重登，走第 5 节。

## 5. 落地验收

**口令**

- 库中 `text_password` 为空；店铺详情、账号列表 JSON 无明文密码。  
- 生产登录页无 `123456`；演示账号登不进生产。  
- 重置/入驻只亮一次密码，刷新后看不到；首次登录能逼改密。

**会话**

- 平台/商家连续操作超过原 2 小时，保存仍成功。  
- 停过闲置再请求 → 401。  
- 退出、改密、平台重置商家密码 → 旧票立刻 401。  
- 取消超管后，旧票不能再当超管（A12）。  
- 商家连错密码到次数 → 锁定（A13）。

**C 端 / 入驻**

- 解开入驻新票无手机号，入驻仍能提交。  
- 小程序正常免登；refresh 作废后须重新微信登。  
- 登录后伪造 `merchant_id` 或换 appid 头，不能下到别人店、不能付到别人店。

**密钥与传输**

- 三端 secret 不同；商家普通票打 mall 用户接口失败（小魔推走 `merchant_secret` 的除外）。  
- 全站 HTTPS；HTTP 登录拒绝或跳转。

**前端与日志**

- 网页票不在 `localStorage`；脚本读不了 Cookie。  
- 小程序 401 能换票，失败才回登录。  
- 日志搜不到完整密码、完整 Bearer。

**五条不过不发生产：** (1) 忙不踢 (2) 闲必踢 (3) 闸立刻废 (4) 串不了店 (5) 库无明文密码。
