## 1. 范围

| 项 | 口径 |
|---|---|
| 职责 | 一个交易能力域：下单、支付、抽佣费率快照、结算/提现沿用现码能力；两种支付通道 |
| 非职责 | 不拆订单模块与支付模块；不按业态拆两套订单模块；不拥有树/入驻绑定/商品审核；不扫桌、不核销（`fulfillment`）；不经营拼团秒杀场次（成交可进入本域）；不签发登录票 |
| 暴露面 | 本地生活下单支付：mall。众享源品 - 在线商城下单支付：mall-online（进程未建，只预留语义）。租户看本店单：merchant。平台财务：admin |
| 稳定 ID | `trade`（ADR-017） |

两种通道是本模块内差异，不是两个技术模块（ADR-049）。

## 2. 组件

| 组件 | 位置（逻辑） | 职责 |
|---|---|---|
| PlaceOrder | 拥有该单的进程 | 再验可售（含树/店内分类停用，DEC-035）；拦截无一级；写订单；**不**用店铺 `commission_rate` 当新单权威 |
| PayChannelShop | mall | 本地生活：支付到该租户账户；回调只打 mall |
| PayChannelPlatform | mall-online | 众享源品 - 在线商城：平台商户号统一收；回调只打 mall-online。不是自营店收款 |
| SnapshotWriter | 与支付成功同一本地事务 | 读 `tree` 当前节点费率，写入本单快照；计算抽佣额 |
| Settle | admin / merchant | 现码结算提现能力；身份只看业态与订单快照，不以 `is_self` 为准 |
| Refund | 拥有该单的进程 | 沿用现码退款路径；**不**新编退款状态机 |

只读：`tree`（节点当前费率、解析一级）；`onboarding`（店铺业态）；`goods`（可售、挂点/所属一级）；`user`（池，防串号）。本模块不写树、不写商品审核态。

进程间 **无**同步 RPC、**无**跨 mall 与 mall-online 的分布式事务。一笔单的下单 + 支付 + 快照只落在拥有该单的进程内。

## 3. 调用流程

### 3.1 本地生活（mall）

1. 下单：店身份来自认店/会话，**客户端不得指定改店**（REQ-085，票与认店属 `auth-session`）。
2. 再验 `goods`：普通商品须本店可售（已过审、未下架、已选店内分类）。拼团秒杀成交可进本域，活动规则属 `group-seckill`，本文不展开。
3. 支付到**该租户账户**。失败不算已付。
4. 支付成功同一本地事务：读该店业态根节点**当前**费率（`onboarding` 业态 → `tree` 根节点），写入快照与抽佣额。不以店铺 `commission_rate` 为权威。
5. 已付之后：餐饮走向扫桌、美发/商超走向核销——交接给 `fulfillment`，本模块不实现码与桌台。

### 3.2 众享源品 - 在线商城 / 在线商城（mall-online）

1. 下单：用户池为众享源品 - 在线商城池（DEC-003）。只买在线商城可售商品。
2. 再验 `goods`：审核通过、未下架、能归属某一级且该一级 ∈ 店可售一级。无所属一级：**拒绝下单**，不发明缺省费率，不把漏挂当 0 抽佣。接口绕过同样拦截。
3. 支付走**平台商户号**，回调 URL 指向 mall-online，不指向 mall，不按「当前店切商户号」（ADR-003）。多店一笔如何拆：部分成功拆单 **TBD**，不得在本文默认拆或不拆。
4. 支付成功同一本地事务：取商品所属一级节点当前费率写入快照。不是平台自营收款（DEC-006）。
5. 按快照抽佣后，剩余按现码结算/提现付给供应商。结算周期资料未重写则保留现状，**不编造天数**。

### 3.3 快照与改树

下单后平台改节点费率：已生成且已写入快照的订单仍用快照（REQ-102）。`tree` 只提供读数，不回溯改单。本地生活按业态根；在线商城按商品所属一级；禁止用店多选一级的平均值当本单费率。

### 3.4 结算与财务

保留现码订单/退款/结算/提现能力。列表、筛选、统计、结算**不以** `is_self` 为准（REQ-105）。在线商城供应商货款按本单快照，不走自营规则。历史上 `is_self=1` 不等于在线商城。

本地生活（DEC-033 / REQ-106）：结算账单是**应付佣金对账**。禁止把「货款−退款−佣金」确认入账成可提现余额。已收/未收由平台财务核销。不接微信分账、不接银行代扣。`Settle` 对本地生活不得再走「净额入店钱包」。对公账号/账期 **TBD**，不得编造。

## 4. 状态机

支付语义沿用现码名称，不重定义枚举字面量。业务上：

```text
unpaid  →  paid      （支付成功）
unpaid  →  cancelled （失败/超时等，沿用现码）
paid    →  履约/退款 （履约属 fulfillment；退款沿用现码，不新画状态图）
```

支付失败不成交。未付订单不得当已结算。已带快照的旧单不因本题重算。

订单详情还要补哪些字段（REQ-104）= **TBD**。已付订单**必须有**节点费率快照（REQ-102）；不得把未确认的地址/核销码展示等写成必填表。

## 5. 逻辑数据（不冻结 DDL）

现码：`order_info` 有 `commission_amount`；支付成功用 `merchant.commission_rate` 万分比计算。目标：

| 实体（逻辑） | 权威 | 含义 |
|---|---|---|
| Order | 本模块 | 落在拥有该单的进程；带用户池，防串号 |
| PayAttempt | 本模块 | 通道：店账户 vs 平台商户号；回调归属该进程 |
| CommissionSnapshot | 本模块 | 节点 ID、下单/支付时刻费率、抽佣额；已付单必有 |
| Settlement | 本模块沿用现码 | 按快照与业态，不以自营为准 |

快照列名、订单完善字段均不在本文冻结。店铺 `commission_rate` 可留列，不作新单权威。

## 6. 操作清单（路径留 G9）

| 操作 | 调用方 | 幂等 |
|---|---|---|
| 下单（本地生活） | mall | 业务单号防重；无票/错店拒绝 |
| 下单（众享源品 - 在线商城） | mall-online | 无一级拒绝；跨池拒绝 |
| 发起支付 / 回调 | 各进程本通道 | 回调按现码通道幂等；细则不新编 |
| 写/读抽佣快照 | 支付成功路径；财务读 | 已付单只写一次，不覆盖成新费率 |
| 退款 | 拥有该单的进程 | 沿用现码 |
| 结算/提现/对账 | 平台、租户 | 沿用现码；筛选项不以自营为准 |

不写具体 URL、不写通道商 SDK。申请支付通道仍是交付依赖；未配齐前不编造商户号。网页后台 Cookie+CSRF。

## 7. 事务、并发、一致性

| 场景 | 口径 |
|---|---|
| 支付成功 | 改已付 + 写快照 + 待结算冻结 同一本地事务。失败则整笔回滚，不算已付 |
| 跨进程 | **禁止** mall 与 mall-online 两阶段提交。众享源品 - 在线商城单不得在 mall 回调用店账户入账 |
| 改费率 vs 下单 | 无分布式锁。快照以本事务读到的树值为准 |
| 回调重复 | 已付则忽略第二次成功回调，不改快照、不重复入账 |
| 补偿 | 无消息队列要求（ADR-005）。退款补偿沿用现码，不发明新队列 |

## 8. 权限、安全、审计、异常

| 项 | 口径 |
|---|---|
| 下单 | 本池用户；本地生活店身份不可由客户端指定 |
| 支付回调 | 验签；只处理本进程订单 |
| 租户 | 只看本店单与本店结算。不可改节点费率、不可改已写快照 |
| 平台 | 全局对账；不以自营筛选当业务口径 |
| 审计 | 快照数值、节点、时刻可查；支付与退款可对账；无一级拦截原因可查 |
| 拒绝 | 未挂一级；把本地生活单收到平台号或把众享源品 - 在线商城单收到店账户；用店铺字段当新单权威；缺省/0 抽佣放行无一级单 |
| 通知 | 众享源品 - 在线商城支付通知文案 **TBD**，不得编造 |

## 9. 性能、灰度、回滚、测试

| 项 | 口径 |
|---|---|
| 性能 | 下单读树与可售为短读。量化 SLA **TBD** |
| 灰度 | 新单一律快照。旧已付单若只有店铺费率计算结果：不重算（已带快照或历史金额保留） |
| 回滚 | 回退本模块代码。不把「店铺 commission_rate 当新单权威」恢复为规则 |
| 测试 | 商超支付成功资金进该店账户；众享源品 - 在线商城进平台号；改树后旧单快照不变；无一级下单失败；绕过接口同样失败；结算筛选不以自营为准；回调重复不双入账 |

Given/When/Then（设计级）：

- Given 商超用户支付成功；When 查资金方向；Then 进入该租户账户。
- Given 众享源品 - 在线商城支付成功；When 看收款方；Then 为平台统一支付。
- Given 下单后平台调高业态节点费率；When 结算该旧单；Then 仍用快照。
- Given 在线商品未挂一级；When 下单；Then 不得成交。
- Given 已补挂一级且在入驻范围内并过审；When 下单支付成功；Then 用该一级节点费率快照。
