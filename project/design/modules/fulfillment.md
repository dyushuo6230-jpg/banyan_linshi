## 1. 范围

| 项 | 口径 |
|---|---|
| 职责 | 两种到店流程：餐饮**扫桌**；美发/商超**核销**。到店是履约方式，不是第五业态 |
| 非职责 | 不并入交易；不收钱、不写抽佣快照；不签发登录票、不认店（`auth-session`）；不经营拼团秒杀场次；本期餐饮**不**走核销码；不做外卖；mall-online / 众享源品 - 在线商城不暴露扫桌或核销；在线商城供应商无独立小程序 |
| 暴露面 | mall（本众享营销 - 本地生活）；merchant（核销操作、桌台）。admin 不经营扫桌/核销 |
| 稳定 ID | `fulfillment`（ADR-017） |

钱仍进**租户账户**（`trade` 店账户通道）。店身份来自认店/会话，客户端不得指定改店。

## 2. 组件

| 组件 | 位置（逻辑） | 职责 |
|---|---|---|
| TableContext | mall | 餐饮：校验桌号；点餐下单携带该桌。无桌/无效桌不能按该桌下单 |
| TableAdmin | merchant | 本店桌台维护（现码已有）。清台规则资料未重写则沿用现码，不编造 |
| VoucherIssue | mall，支付成功后由本域接收 | 美发/商超：已付订单生成核销码给用户。未支付无码 |
| VoucherConsume | merchant | 本店核销本店码。他店码失败。已核销不能再当未核销成功 |
| ChannelGuard | 入口 | 按店铺业态选流程：餐饮禁止核销码主路径；美发/商超禁止堂食扫桌主路径；在线商城无本域 |

只读：`onboarding`（业态）；`trade`（是否已付、本店订单）。本模块不改支付状态、不改快照。

## 3. 调用流程

### 3.1 餐饮扫桌（发生在下单前）

1. 顾客打开**该店**小程序（认店属 `auth-session`）。
2. 到店扫合法桌号 → TableContext 绑定本次点餐桌履约。
3. 点餐下单。订单带该桌。支付由 `trade` 收到该租户账户。
4. 无桌号/桌号无效：不能按该桌下单。重复扫同一桌：沿用现码，不编造清台。
5. 无外卖入口。以后若餐饮要核销：走变更，本题不预设计。

### 3.2 美发 / 商超核销（发生在支付成功后）

1. 顾客在本众享营销 - 本地生活选服务/商品，下单并由 `trade` 支付到该店账户。
2. 支付成功后本域发核销码。用户订单上能看到码。
3. 到店出示；本店店员核销成功 → 履约完成。该码不得再次作为未核销成功。
4. 他店订单码：本店核销失败。
5. **有效期天数、过期自动退 = 本期不做**（DEC-037）：码不因到期作废；无过期 Job。未核要退走现码退款。整单一次核销、部分核销不做（DEC-034）。全额退款后该单主码不可再核，不补发第二张主码（DEC-044）。

### 3.3 明确不走本域

| 场景 | 处理 |
|---|---|
| 众享源品 - 在线商城 / mall-online | 不暴露扫桌、核销 |
| 在线商城供应商 | 无独立小程序，无本域入口 |
| 拼团秒杀成交 | 付钱在 `trade`；是否核销视业态：本地生活美发/商超已付单可走核销，活动规则属 `group-seckill` |
| 无业态老店迁餐饮 | 走扫桌主路径。被误迁的美发/商超如何补核销 **TBD**（DEC-011），本文不编补偿 |

## 4. 状态机

餐饮桌履约：桌号有效性沿用现码。订单支付态属 `trade`。本模块不新造餐饮核销态。

美发/商超核销（已确认的边）：

```text
paid_unconsumed  →  consumed
```

未支付无码。无效/已核销不能当未核销成功。一次核销已确认（DEC-034）。全额退款后码不可再核（DEC-044）：`paid_unconsumed → voided_by_refund`。不补发第二张主码。

## 5. 逻辑数据（不冻结 DDL）

现码：订单有 `table_id` / `table_no`，**无**核销码。目标：

| 实体（逻辑） | 权威 | 含义 |
|---|---|---|
| DiningTable | 本模块 | 餐饮本店桌台 |
| OrderTableRef | 本模块写在下单上下文 | 餐饮订单关联桌；不表示已付 |
| Voucher | 本模块 | 绑定已付订单与本店；码值不进日志明文完整打印（可审计操作，细节 G9） |
| ConsumeRecord | 本模块 | 操作人、时间、订单 |

不在本模块存：支付结果、抽佣快照、用户池、入驻业态（只读）。

## 6. 操作清单（路径留 G9）

| 操作 | 调用方 | 幂等 |
|---|---|---|
| 校验桌号 / 按桌开点 | 餐饮顾客 | 无效桌失败 |
| 维护桌台 | 餐饮租户 | 以桌 ID 更新 |
| 已付发码 | 美发/商超，支付成功后 | 同一订单不发第二张有效主码（DEC-044 不补发） |
| 租户核销 | 本店店员 | 已核销再提交返回已完成，不双次成功入账（入账属 `trade`） |
| 用户查看码 | 本店已付顾客 | 是 |

不写具体 URL。网页后台 Cookie+CSRF。小程序 Header 票。

## 7. 事务、并发、一致性

| 场景 | 口径 |
|---|---|
| 发码 | 确认 `trade` 已付后写码。不在本模块收钱 |
| 核销并发 | 以凭证状态条件更新；第二下视为已核销，不发明双次履约 |
| 与支付 | **无**跨模块分布式事务。支付失败则无码。全额退款后作废该单主码（DEC-044） |
| 与认店 | 本模块不改会话。错店核销直接失败 |
| 补偿 | 无消息队列要求（ADR-005） |

## 8. 权限、安全、审计、异常

| 项 | 口径 |
|---|---|
| 扫桌/点餐 | 仅该众享营销 - 本地生活会话 |
| 核销 | 仅该店员工核销本店单。菜单隐藏不是安全边界 |

| 拒绝 | 餐饮走核销码主路径；美发/商超走堂食扫桌主路径；外卖；他店码；未支付发码 |
| 通知 | 核销通知文案 **TBD**，不得编造 |

## 9. 性能、灰度、回滚、测试

| 项 | 口径 |
|---|---|
| 性能 | 核销为低频写。量化 SLA **TBD** |
| 灰度 | 按店铺业态开关流程。迁餐饮的老店先走扫桌 |
| 回滚 | 回退本模块代码。不把外卖或餐饮核销码当本期能力恢复 |
| 测试 | 扫合法桌号点餐支付：订单带桌且款到该店；无外卖入口；美发已付可见码；本店核销成功后不可再当未核销；他店码失败；mall-online 无扫桌/核销 |

Given/When/Then（设计级）：

- Given 餐饮顾客到店；When 扫合法桌号点餐支付；Then 订单带该桌且款到该店。
- Given 顾客找外卖配送；When 用本期产品；Then 无此能力。
- Given 美发订单已支付；When 用户看订单；Then 有核销码。
- Given 商超店员核销本店合法码成功；When 再核销；Then 不得再当未核销成功。
- Given 他店订单码；When 本店核销；Then 失败。
