## 1. 范围

| 项 | 口径 |
|---|---|
| 职责 | 四个业态根、一棵经营类目树、节点费率；平台维护；只读查询给入驻/发品/下单快照 |
| 非职责 | 不审店（`onboarding`）；不发品（`goods`）；不写下单快照（`trade`）；不配四套菜单；不签发登录票 |
| 暴露面 | 写：仅 admin。读：admin / merchant / mall / mall-online / 入驻 H5 |
| 稳定 ID | `tree`（ADR-017） |

业态代码（逻辑枚举，不是第五业态）：`catering` 餐饮、`hair` 美发、`supermarket` 商超、`online-mall` 在线商城。禁止 `dine-in` / 「到店」。

## 2. 组件

| 组件 | 位置（逻辑） | 职责 |
|---|---|---|
| TreeCommand | admin 进程内 | 创建/改名/排序/启停节点、改节点费率；拒绝第五业态根 |
| TreeQuery | 各进程内只读 | 列根、列子树、按 ID 取节点、取费率、解析所属一级 |
| TreeGuard | 写路径 | 仅平台运营；租户不可写树 |
| RateRead | 只读 | 返回**当前**节点费率，供 `trade` 下单时快照；本模块不写订单 |
| AuditLog | admin | 记录谁在何时改了哪个节点的名称/费率/状态 |

进程间无同步 RPC。mall-online 只读本库树表，不向 mall 要树。

## 3. 调用流程

### 3.1 平台维护树

1. 运营在 admin 打开经营类目树。
2. TreeQuery 返回四根（若缺则实施种子，见 §10）。在线商城下只展示 `goods_category` **一级**（DEC-021）；二级/三级在平台类目页。
3. **不再**在经营类目挂子节点。结构在「商品管理-平台类目」维护；经营类目页配置费率、排序、启停。
4. TreeCommand 保存名称（仅业态根）、排序、启用状态、节点费率。失败保持原树。
5. 费率变更写审计。已产生订单仍用 `trade` 快照，本域不回溯改单。

### 3.2 只读：入驻 / 发品 / 下单

| 调用方 | 读什么 | 不做什么 |
|---|---|---|
| `onboarding` | 四根；在线商城根下启用中的一级列表 | 不写树；入驻强制 1～3 个一级见 DEC-032，本模块不默认 |
| `goods` | 在线商城子树（树形选择器）；节点 → 所属一级 | 不写树；超出店可售一级由 `goods` 拒绝送审 |
| `trade` | 本地生活：店铺业态根节点当前费率；在线商城：商品所属一级当前费率 | 费率写入订单快照属 `trade`；本模块只提供「此刻读数」 |
| 菜单套模板 | 读店铺已绑业态（绑在入驻/租户资料，不在本域写） | 四套菜单不是本模块 |

### 3.3 解析所属一级（在线商城）

商品挂平台类目任意深度时：沿 `goods_category` 父链向上，落到 `parent_id=0` 的一级即为计佣一级（DEC-012、DEC-021）。无法归属到一级 → 视为未挂一级，本模块返回空；`goods`/`trade` 按 DEC-013 不可售、不可下单。本模块**不**发明缺省费率。

## 4. 状态机

### 4.1 节点

```text
enabled  ←→  disabled
```

- 新建后默认 `enabled`（与现码类目启用习惯一致，实施可调，不另开业务 DEC）。
- `disabled`：只读方默认不出现在入驻多选、发品选择器。
- **停用后已上架商品（DEC-035）：** 不可再售；不改商品行、不删挂点；已下单不改快照。再启用后仍上架且（在线商城）已过审的可再售。本模块仍不得静默删绑定。
- **停用后已入驻选中该一级的店（DEC-044）：** 绑定留下、不静默删。该一级不能发新品。读路径：入驻多选/发品选择器不展示停用一级。写路径允许停用。

### 4.2 业态根

四根必须始终存在且不可改成第五个。允许改**显示名**（DEC-012：名称可改），不允许改稳定代码。不允许删除根。根的费率：本地生活三根必须可配置；`online-mall` 根本身**不是**计佣一级（计佣在平台类目一级，DEC-021）。

店铺绑定哪个业态：权威在 `onboarding` / 租户资料，本模块只提供根节点身份。

## 5. 逻辑数据（不冻结 DDL）

现码：`merchant_category` 扁平（id/name/commission_rate 万分比/sort/status）；`merchant.commission_rate` 作店铺抽佣；入驻 `merchant_apply.merchant_category_id` 指向该类目。目标：`merchant_category` **不再作入驻主数据**（DEC-001）；新单不以店铺 `commission_rate` 为权威。

逻辑实体 `TreeNode`（G9 定表名）：

| 字段（逻辑） | 含义 | 备注 |
|---|---|---|
| id | 稳定主键 | |
| parent_id | 父节点；根为空 | |
| code | 根用业态代码；子节点可空或内部码 | 四根 code 冻结为上表四值 |
| name | 显示名 | 可改，不是行业标准 |
| level | 根=0；一级=1 | 便于「所属一级」 |
| rate | 当前抽佣费率 | 与现码一致候选：整数万分比；G9 冻结 |
| status | enabled / disabled | |
| sort | 同层排序 | |
| updated_by / updated_at | 审计 | REQ-001/004 |

不在本模块存：店铺业态、入驻已选一级列表、商品挂点、订单快照。那些分属 `onboarding` / `goods` / `trade`。

并表：本批**不并表删除** `goods_category`（DEC-021）；在线商城一级直接读该表，费率列 `commission_rate`。

## 6. 操作清单（路径留 G9）

| 操作 | 调用方 | 幂等 |
|---|---|---|
| 列出整树或按父节点列子 | 平台；只读方 | 是 |
| 创建子节点 | 仅平台 | **本期拒绝**（DEC-021）；结构在平台类目维护 |
| 改名 / 排序 / 费率 | 仅平台 | 以节点 id 更新；并发见 §7 |
| 启用 / 停用 | 仅平台 | 是 |
| 按 id 取节点与费率 | `trade` / `goods` | 是 |
| 解析所属一级 | `goods` / `trade` | 是 |
| 拒绝新增业态根 | 任何「到店」或第五代码 | 必须失败 |

不在本文写具体 URL。Cookie+CSRF 约束网页后台（DEC-005）。

## 7. 事务、并发、一致性

| 场景 | 口径 |
|---|---|
| 改费率 | 单节点更新事务；成功后新读见新值。进行中的下单：`trade` 以读到的值为准做快照；不在本模块加分布式锁跨进程 |
| 并发改同一节点 | 乐观版本或 `updated_at` 冲突则失败重读；不静默覆盖 |
| 与下单 | **无**跨 `tree`+`trade` 分布式事务。改费率不改旧单 |
| 种子四根 | 实施一次性幂等插入；已存在则跳过 |
| 补偿 | 写失败回滚该次更新。无消息队列要求（ADR-005 延期） |

## 8. 权限、安全、审计、异常

| 项 | 口径 |
|---|---|
| 写 | 仅平台运营（admin 登录）。菜单隐藏不是安全边界（ADR-008） |
| 读 | 已登录后台；C 端/入驻 H5 只读启用节点。不把未启用费率暴露为可下单价 |
| 审计 | 费率、名称、启停、根相关变更：操作者、时间、节点 id、旧值、新值 |
| 拒绝 | 第五业态；删除根；租户写树；把「到店」存成 code |
| 重试 | 读可重试。写冲突返回错误，由运营再提交 |
| 隐私 | 树无用户 PII |

## 9. 性能、灰度、回滚、测试

| 项 | 口径 |
|---|---|
| 性能 | 树体量小（四根 + 在线商城子树）。进程内只读缓存允许，失效：节点更新后丢缓存。量化 SLA **TBD** |
| 灰度 | 读可先双读旧 `merchant_category` 与新树，但**入驻主数据只认新树**。旧表可留作兼容只读，不作新单权威 |
| 回滚 | 回退本模块代码；四根种子保留。不回写「用店铺 commission_rate 当新单权威」 |
| 测试 | 四根存在且无到店；只读解析一级；未挂一级返回空；租户不能写；改费率不影响已有快照（与 `trade` 联测时验，本模块单测只保证读数变化） |

Given/When/Then（设计级，对应 PRD）：

- Given 平台打开树；When 看根；Then 恰四个且无到店。
- Given 在线商城根；When 配一级及费率；Then 只读方可按该节点取费率。
- Given 商品挂二级；When 解析一级；Then 为其父一级，不是根。
- Given 无法归属一级；When 解析；Then 空，不给 0 也不给缺省。

## 10. 迁移

| 步骤 | 谁执行 | 口径 |
|---|---|---|
| 种子四根 | 实施 | `catering` / `hair` / `supermarket` / `online-mall`；餐饮根费率先按运营配置，无配置则 **TBD** 不得在设计里写死数字 |
| 无业态老店 | 实施 + `onboarding`/租户资料 | 店铺业态写成餐饮（DEC-011）。**本模块只保证餐饮根存在**，不写 `merchant` 行 |
| `is_self=1` 老店 | 同上 | 仍迁餐饮，不迁在线商城 |
| 现码 `merchant_category` | 兼容 | 不再作入驻主数据。是否弃用表留 G9 |
| 通用类目树挂到在线商城根下 | 实施 | **改为直接读 `goods_category`**（DEC-021）；不在 `merchant_category` 挂子；示例节点清单不冻结为 PRD |
| 存量在线商品未挂一级 | `goods` | DEC-013：先补挂再卖；本模块提供树节点 |

不批准生产清库（DEC-017 未覆盖生产清库）。本期测试清库不在本模块范围。
