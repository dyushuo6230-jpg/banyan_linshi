本文件是 G8 **Approved**（ADR-038）。已 **Baselined**（TECH_BASELINE=v0.1.5）。不能当作已开工。不改业务代码。不创建 `app/mall-online`。REST 路径与表结构以日后 `api/`、`database/` 为唯一真源；本文只给逻辑边界。G6 架构已 Approved（ADR-040），仅引用。`onboarding.md` 已 Approved，只读引用，不改入驻口径。待配置保持 TBD，批准后也不得编造。本期本域的设计目标是**划清现码边界并禁止误删误改**，不是重做推广体系。

## 1. 范围

| 项 | 口径 |
|---|---|
| 职责 | 同一能力域托管两块现码：推广员入驻注入；小魔推。本期保留 |
| 非职责 | 不改造、不纳入必验、不拥有审店；mall-online 不新做小魔推；不拥有平台 banner |
| 暴露面 | 现码入口继续在 mall / merchant / 众享营销 - 本地生活。入驻 H5 页面属 `onboarding` |
| 稳定 ID | `promotion`（ADR-017） |

两块现码**不是**同一套产品、**不是**本期两套改造：

| 块 | 需求 | 本期 |
|---|---|---|
| 推广员入驻注入 | REQ-120 | 现码可走；不删除；不按自拟新规则验收改造 |
| 小魔推 | REQ-111、DEC-010、DEC-019、CR-035 | 代码保留；四套侧栏隐藏；不纳入多业态必验；本地生活扫码进店可写现状 |

入驻、菜单、发品、逛买、登录、支付**不以**完整小魔推为交付物。误改导致现码不可用按回归处理，不以「必须交付小魔推」验收。不批准停用或拆掉小魔推。

## 3. 调用流程

### 3.1 推广员入驻注入

1. 申请人仍走**同一套**入驻 H5（`onboarding`，REQ-010）。本模块不另开入驻页、不另开审店台。
2. 现码若带推广员标识：注入申请行 `sales_id`（列名是现码事实，不是新设计）。`onboarding` 只存该值。
3. 本模块**不得**改申请 `status`，不得给推广员开审核后门（ADR-015、`onboarding.md`）。
4. 过审、绑业态、套菜单仍属 `onboarding`。佣金、等级、结算资料未展开 = TBD，不得编造。

### 3.2 小魔推（现状保留）

1. 代码、表、接口、小程序页继续保留。租户四套侧栏隐藏小魔推（DEC-019）。本期开发批次不删除、不改造产品。
2. 多业态主路径验收**不含**完整小魔推。
3. 四套租户菜单侧栏均隐藏小魔推（DEC-019）。代码、表、接口、小程序页不拆。以后改造另议。
4. 众享源品 - 在线商城 / mall-online **不**因此获得小魔推。不得把本地生活小魔推入口搬到众享源品 - 在线商城当必验。现码若仍挂扫码入口，属缺口，不是已批准能力。
5. **本地生活已落地现状（人话，不升格接口清单）：** 顾客扫店码 → 中间页登录或注册 → 本店设备一人一机 → 才出推广链。开通没有合法渠道时人能看见失败。注册或绑设备失败不发链；密码错不注册。中间页网址、密码最短位数、聚合密钥待配置。

店铺 `merchant_banner`、周边 `nearby_banner` 也不属本域。
