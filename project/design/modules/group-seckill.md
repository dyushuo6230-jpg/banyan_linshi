## 1. 范围

| 项 | 口径 |
|---|---|
| 职责 | 本地生活（餐饮/美发/商超）拼团与秒杀的活动生命周期：租户创建、上架、下架；C 端本店可见已上架活动 |
| 非职责 | 不并入 `goods` 或 `trade`；不经平台审核、无待审状态；平台不建统一场次、不报名、不增加强制下架经营菜单；在线商城 / 众享源品 - 在线商城 / mall-online **不**暴露；不管支付通道（成交走 `trade` 店账户） |
| 暴露面 | merchant（完整发布）；mall（本店 C 端）。admin **去掉**经营办理。在线商城菜单模板必须删减该能力 |
| 稳定 ID | `group-seckill`（ADR-017） |

先不做插件，直接在租户后台使用完整功能。

## 2. 组件

| 组件 | 位置（逻辑） | 职责 |
|---|---|---|
| ActivityCommand | merchant | 创建拼团或秒杀；上架；下架。拒绝送平台审 |
| ActivityQuery | merchant / mall | 本店活动列表；C 端只读已上架 |
| InventoryGuard | mall 下单前 | 不能超卖（现码若有则保留；数量规则资料未写则不编造数字） |
| PlatformStrip | admin | 拿掉统一场次、报名、审核办理入口 |
| MigratePending | 实施一次性 | 待审 → 未上架；已通过/已上架保留；可追溯 |

成交：用户按活动规则下单 → `trade` 支付到该店账户 → 履约按业态（扫桌或核销）。拼团不另出核销码，与普通已付订单同一套码（DEC-043）。

## 3. 调用流程

### 3.1 租户发布（无待审）

1. 仅餐饮/美发/商超后台出现该能力。在线商城模板无菜单。
2. 租户创建拼团或秒杀并上架。不经平台审核。状态无「待平台审核」。
3. 上架后本众享营销 - 本地生活可见可买，规则与后台设置对齐。
4. 下架后不可再按进行中活动购买。
5. **进行中停用（DEC-038）：** 停用/下架后拒绝新参；已生成订单不自动关、不自动退。不得写「立即失效仍可退」。
6. 审计：谁创建、何时上下架。

### 3.2 本店 C 端

1. 认店后只看本店已上架活动（认店属 `auth-session`）。
2. 浏览 → 按活动规则下单。支付与快照属 `trade`（店账户通道）。
3. 活动已下架：不能按进行中购买。
4. 页面交互可参考 SRC-UI-001，**不以截图像素验收**。

### 3.3 平台侧

运营登录后不能再办理：拼团秒杀审核、统一场次、报名。历史入口不可办理新的平台场次。本题不给平台强制下架经营菜单。原审核菜单如何改名 **TBD**。

### 3.4 明确不走本域

| 场景 | 处理 |
|---|---|
| 众享源品 - 在线商城用户浏览 | 第一种流程不暴露。第二种流程见 ADR-011 v1.1 / DEC-068 / REQ-131（本文件 v1.0 未展开） |
| mall-online | 不暴露本地生活活动；源品活动见 ADR-011 v1.1 |
| 普通商品审核台 | 活动**不进** `goods` 审核队列（DEC-004 不推翻 DEC-016） |
| 在线商城若有历史活动记录 | 不迁成可售 |

## 4. 状态机

目标态（无平台待审）：

```text
off_shelf  ←→  on_shelf
```

`off_shelf` 含草稿/下架语义，C 端不可见。租户可直接上架。

迁移：现码待审 → `off_shelf`（未上架）。已通过/已上架 → 保持可售，不改成未上架。

进行中停用按 DEC-038：不可新参、旧单不自动退。过期结束如何自动下架：资料未写细则则沿用现码时间窗若已有，**不新编**停用退款规则。

## 5. 逻辑数据（不冻结 DDL）

现码：平台有拼团秒杀审核；mall 有下单接口；租户后台有活动。目标：

| 实体（逻辑） | 权威 | 含义 |
|---|---|---|
| Activity | 本模块 | 本店拼团或秒杀；上下架；无平台审核字段作为经营门闩 |
| ActivityRule | 本模块 | 后台设置的成团/秒杀规则；C 端必须对齐 |
| PendingMigrationLog | 实施 | 待审改为未上架的追溯 |

不在本模块存：支付结果、抽佣快照、普通商品审核态。订单上可带 `activity_id`（现码已有），成交仍属 `trade`。

## 7. 事务、并发、一致性

| 场景 | 口径 |
|---|---|
| 上架 | 本店写活动。无跨平台审核事务 |
| 下单 | 本域校验活动仍 on_shelf 且库存允许；支付在 `trade` 本地事务。**无**跨模块分布式事务 |
| 超卖 | 现码有则保留；无数字则实施时用库存条件更新，不在本文写死件数 |
| 与商品审核 | 零耦合。活动不上 `goods` 审核台 |
| 补偿 | 无消息队列要求（ADR-005） |

## 8. 权限、安全、审计、异常

| 项 | 口径 |
|---|---|
| 发布 | 仅本店本地生活租户。菜单隐藏不是安全边界；在线商城即使用户猜 URL 也须拒绝 |
| C 端 | 仅本店用户池；认店后不可改店 |

| 通知 | 资料未写平台通知，不编造 |

## 9. 性能、灰度、回滚、测试

| 项 | 口径 |
|---|---|
| 性能 | 本店活动量小。量化 SLA **TBD** |
| 灰度 | 先迁待审为未上架，再拿掉平台经营入口，避免窗口期仍能审 |
| 回滚 | 回退本模块代码。不把「平台必审才能卖活动」恢复为规则 |
| 测试 | 餐饮租户上架秒杀无需平台审即可被本店看见；状态无待平台审核；平台不能办理审核/场次；在线商城后台无该菜单；众享源品 - 在线商城无购买；待审迁移后 C 端不可见且记录仍在；已上架迁移后仍可售 |

Given/When/Then（设计级）：

- Given 餐饮租户创建秒杀并上架；When 未经过平台审核；Then 本店用户仍可见。
- Given 活动；When 看状态；Then 无「待平台审核」。
- Given 平台运营；When 找审核或统一场次报名；Then 不能再作为经营功能办理。
- Given 在线商城租户；When 打开后台；Then 无拼团秒杀。
- Given 一条待审秒杀；When 上线切换；Then 记录仍在、C 端不可见、租户可自行上架。
- Given 已上架活动；When 迁移；Then 保持可售。
- Given 进行中活动被租户下架；When 新用户参加；Then 拒绝。Given 已付单；When 随后下架；Then 不自动关单、不自动退。
