- 选择：方案 A
- 限制条件：NONE
- 被拒方案：B（先批准 `tree.md`、本轮不写下一模块）、C（跳过入驻、先写 `auth-session`）
- 知情决策证据：INFORMED_REVIEW → INFORMED_CONFIRMATION → DECISION_APPLY

## 已确认规则

1. G8 第二份详细技术设计是 `onboarding`（租户入驻）。
2. 产物：`docs/project/design/modules/onboarding.md`，状态 **Draft**，不是 Approved / Baselined。
3. `tree.md` **保持 Draft**，不升格 Approved。只引用，不改其已确认口径。
4. 只设计该模块。不生成 `goods` / `auth-session` 等其余模块。不批准 G6 架构。不创建 `app/mall-online`。不改业务代码。
5. 待配置（入驻一级数量、资质清单、重复提交幂等、改业态细则）保持 TBD，不得编造。

## 未扩大

- 不批准 `onboarding.md` 或 `tree.md` 为 Approved
- 不启动 `goods` 及后续模块设计
- 不冻结 OpenAPI / DDL（属 G9）
