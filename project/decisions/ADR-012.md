- 主题：用户账号/用户池 和 登录/会话/口令 做成两个技术模块，还是合成一个
- 选择：方案 A
- 限制条件：NONE
- 被拒方案：B（合成一个身份模块）、C（按进程拆两套用户模块）
- 知情决策证据：INFORMED_REVIEW → INFORMED_CONFIRMATION → DECISION_APPLY

## 已确认规则

1. 用户与认证会话是 **两个**能力域技术模块，不合成「身份」一域，也不按 mall / mall-online 拆成两套用户模块。
2. 用户域：注册、分池、池内唯一、账号启用/禁用。继续使用现有用户主体，**不新建**众享源品 - 在线商城用户表；店铺池 vs 众享源品 - 在线商城池（DEC-003）。
3. 认证会话域：口令不可逆、登录、短票/可作废长票、作废名单、网页 Cookie+CSRF、小程序 Header、认店。众享源品 - 在线商城纳入同一套可作废会话语义（DEC-005）。
4. 进程仍只作暴露面（ADR-007）：mall 对店铺池签发 mall 票；mall-online 对众享源品 - 在线商城池签发独立 JWT。票不得跨进程使用（ADR-002）。退出或改密只作废本端。
5. 认店只约束众享营销 - 本地生活，不套到众享源品 - 在线商城（DEC-005）。
6. 数据仍共库。用户共表分池；作废名单按进程隔离键。不按两个用户模块独占表。
7. 模块英文 ID 字符串本题不冻结。用户池字段落地、最短密码长度、jwt.expire、具体 Redis db 本题不编造。
8. **本 ADR 不生成** `MODULE_BOUNDARIES.md`。G7 仍为部分完成。
