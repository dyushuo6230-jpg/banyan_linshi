- 主题：业态/经营类目树 和 租户入驻审核 做成两个技术模块，还是合成一个
- 选择：方案 A
- 限制条件：NONE
- 被拒方案：B（合成一个租户开通模块）、C（业态枚举、类目树、入驻拆成三个模块）
- 知情决策证据：INFORMED_REVIEW → INFORMED_CONFIRMATION → DECISION_APPLY

## 已确认规则

1. 业态/经营类目树 与 租户入驻 是 **两个**能力域技术模块，不合成「租户开通」，也不把业态枚举从树上再拆成第三域。
2. 树域：四个业态根、一棵经营类目树、节点费率配置。类目与计佣一级同一套（DEC-001、DEC-012）。平台维护，租户不改树。
3. 入驻域：全业态同一套入驻 H5、按业态采集、平台审店、过审后绑定业态；在线商城还绑定可售一级。入驻 **只读树，不拥有树**。
4. 抽佣**快照**仍在交易模块（ADR-049）。四套菜单仍是 merchant 暴露面差异（ADR-008、DEC-002），不是本 ADR 的第三个模块。
5. 无业态老店默认迁餐饮（DEC-011）。未挂一级不可售（DEC-013）由树规则约束商品/交易，不改写入驻状态机。
6. 数据仍共库。树权威在平台；入驻申请/审核记录在入驻域。不按进程独占表。admin 只作暴露面。
7. 模块英文 ID 字符串本题不冻结。入驻强制几个一级、资质字段清单本题不编造。
8. **本 ADR 不生成** `MODULE_BOUNDARIES.md`。G7 仍为部分完成。
