- 主题：盖章之后要不要开工（打开改代码；第一批是否升 Ready）
- 选择：CODE-GATE=A
- 限制条件：NONE
- 被拒方案：B（暂不开工）、C（打开改代码但第一批不是 DEV-001）
- 知情决策证据：INFORMED_REVIEW → INFORMED_CONFIRMATION → DECISION_APPLY

## 已确认规则

1. `ALLOW_CODE_CHANGES` 设为 **true**。允许修改业务代码、配置与 `deploy/sql` 增量，**仅限已 Ready 的批次**。
2. **DEV-001（业态树与抽佣挂点）** 由 Planned 升为 **Ready**。其余 DEV-002～011 仍为 Planned，不得当作本批一起实现。
3. 不创建 `nunu-go-api/app/mall-online`（属 DEV-010）。
4. 不启用正式 UI_SPEC；无 UI Contract 不阻断 DEV-001。
5. **待配置继续待配置**，编码遇到未决规则必须停、走知情决策，不得编造。本批不写死：示例树节点清单、类目停用后已上架商品、餐饮根初始费率数字、并 `goods_category` DDL。
6. 改真表走 `database/MIGRATION_PLAN.md` 的 `deploy/sql` 可重复增量；禁止 AutoMigrate 当发布手段。
7. 测试可清库（DEC-017）；生产禁止清库。回滚不得把已确认规则倒回去。
8. 小魔推仍不纳入必验。DEV-003 不因本题升 Ready。

## 未扩大

- 不把 DEV-002～011 升 Ready
- 不把 DEV-001 标为 In Progress / Code Complete（实施另走开发批次会话）
- 不创建 mall-online
- 不清待配置
- 不启用正式 UI_SPEC
