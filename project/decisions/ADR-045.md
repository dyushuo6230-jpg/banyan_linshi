- 主题：是否生成 G10 开发批次文档
- 选择：方案 A
- 限制条件：NONE（沿用已冻结约束：不改业务代码；不创建 `app/mall-online`；不生成正式 UI Contract；不把 PRD/架构收成 Baselined；菜单按 DEC-020；TBD 不得编造；小魔推不纳入必验）
- 被拒方案：B（现在不写批次、先停）、C（本题不写批次；下一题改问是否 Baselined）
- 知情决策证据：INFORMED_REVIEW → INFORMED_CONFIRMATION → DECISION_APPLY

## 已确认规则

1. 生成 `delivery/DEVELOPMENT_BATCHES.md`、`RELEASE_PLAN.md`、`ROLLBACK_PLAN.md`。各开发批次状态为 **Planned**。G10 文档夹状态为 **Draft**。
2. 这是治理门禁的**知情例外**：PRD / G6～G9 仍是 Approved、**不是** Baselined，仍允许先出计划稿。写清单 ≠ 正式批次 Ready ≠ 开工。
3. `ALLOW_CODE_CHANGES` 保持 **false**。不改业务代码。不创建 `nunu-go-api/app/mall-online`。不写真实 SQL、不灌库。
4. `UI_CONSTRAINT_MODE=NONE`。不生成 `EFFECTIVE_UI_CONTRACT`。不启用正式 UI_SPEC。不得因无 UI Contract 而阻断以后把某批升 Ready。
5. 菜单显示名与有无按 DEC-020。四套小魔推侧栏隐藏（DEC-019），小魔推不纳入本期必验。
6. 已标明的待配置继续待配置，写批次也不得编造。做到需要该规则的批次时，须另走知情决策后再编码。
7. **不**自动把任何批次升 Ready。**不**自动进入 G11。**不**把文档收成 Baselined。

## 未扩大

- 不批准改代码
- 不创建 mall-online 目录
- 不生成正式 UI Contract
- 不把待配置清零
- 不把 PRD / G6 / G7 / G8 / G9 收成 Baselined
