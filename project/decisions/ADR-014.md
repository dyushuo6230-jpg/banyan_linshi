- 主题：本地生活扫桌/核销做成独立技术模块，还是并进交易，还是不算模块
- 选择：方案 A
- 限制条件：NONE
- 被拒方案：B（并入交易模块）、C（不算技术模块，只当 mall 暴露面差异）
- 知情决策证据：INFORMED_REVIEW → INFORMED_CONFIRMATION → DECISION_APPLY

## 已确认规则

1. 履约是 **独立**能力域技术模块，不并进交易（ADR-049），也不只当 mall 暴露面差异。
2. 本期两种到店流程：餐饮 **扫桌**；美发/商超 **核销**。餐饮本期 **不** 走核销码主路径（REQ-042）。
3. 只暴露在众享营销 - 本地生活与租户后台。mall-online **不** 暴露扫桌/核销。在线商城供应商无独立小程序（REQ-040）。
4. 付钱仍走交易模块店账户通道（ADR-049、REQ-100）。认店仍走认证会话（ADR-012）。到店是履约不是第五业态（DEC-001）。本期不做外卖。
5. 数据仍共库，不按进程独占表。
6. 以后餐饮若要核销，走变更，在本域加流程；本题不预先设计。众享源品 - 在线商城物流本题不设计。
7. 模块英文 ID 字符串本题不冻结。核销有效期、过期是否退款、部分核销本题不编造。
8. **本 ADR 不生成** `MODULE_BOUNDARIES.md`。G7 仍为部分完成。
