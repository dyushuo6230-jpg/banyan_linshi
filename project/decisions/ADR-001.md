- 主题：众享源品 - 在线商城后端落在哪个进程
- 选择：方案 A（细化）
- 限制条件：见下文「已确认规则」
- 被拒方案：B（API 落在现有 mall 8032）、C（维持开发代理指向 merchant 8033）
- 知情决策证据：INFORMED_REVIEW → INFORMED_CONFIRMATION → DECISION_APPLY
- 背景：现码无 `app/mall-online`；`go-uni-app-online` 开发代理指向 8033；PRD 不把独立进程当作业务必验（REQ-066），实现方式由 G6 决定。

## 已确认规则

1. 本期新建独立进程：`nunu-go-api/app/mall-online`，配置目录 `nunu-go-api/config/mall-online`。
2. 配置形态对齐 mall：`local` / `test` / `prod` + `.yml.example` 模板；真实 yml 不进 Git。
3. `sms`、`db`、`redis`、`upload`、`storage` **沿用 mall 的连接与通道**（同一套库、同一 Redis 实例、同一上传/OSS、同一短信）。独立进程 ≠ 独立数据库。
4. `http` 只沿用结构，不沿用 mall 的 8032。**本机端口写死 8035**（DEC-049）。不得与 8031 / 8032 / 8033 / 8034 / **8036** / 8081 冲突。测试/正式容器内口仍按现码习惯 + Nginx 反代；外网域名见 DEC-049。
5. 众享源品 - 在线商城 H5：独立进程 `nunu-go-api/app/h5-online`，本机 **8036**。`go-uni-app-online` **整包**拷到 `web/dist` 后 `go:embed` 打进二进制；外网根路径进首页。与入驻 `app/h5`（只嵌部分文件、`/wap/`）不同。域名见 DEC-049。不挂微信业务域名校验文件。
6. 实现落点前 `ALLOW_CODE_CHANGES=false`，本 ADR 不创建上述目录、不改业务代码。
7. PRD 验收仍不把「目录是否存在」当作业务必验项；业务仍只验收众享源品 - 在线商城登录与逛买闭合。

## 未扩大

- JWT 已由 **ADR-002** 收口。支付/微信已由 **ADR-003** 收口。
- Redis 键前缀或单独 `redis.db`：ADR-002 已要求与 mall 隔离；具体 db 数字仍不冻结。
- 本机端口已由 **DEC-049** 写死：mall-online **8035**、众享源品 - 在线商城 H5 **8036**；测试/正式 API 与 H5 域名已由 DEC-049 收口（测试 `.gyyx.store`，正式 `.zhengdeyunqi.cn`）。
- 不因此改 DEC-003 分池、DEC-005 可作废会话、REQ-101 支付通道。
- 不生成总体架构 Draft（必选架构决策尚未全部完成）。
- 不把 `go-uni-app-online` 代理长期留在 8033；开发代理按 DEC-049 打 8035。
