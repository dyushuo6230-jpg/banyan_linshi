- 主题：本地生活拼团/秒杀做成独立技术模块，还是并进商品或交易；源品要不要第二种流程
- 选择：方案 A；v1.1.0 加源品第二种流程（DEC-068）
- 限制条件：成交仍走交易能力域（ADR-049，不是 ADR-010 ToB）；本批不真扣款
- 被拒方案：B（并入商品模块）、C（并入交易模块）；套用本地生活「租户自发、平台不审」到源品
- 知情决策证据：INFORMED_REVIEW → INFORMED_CONFIRMATION → DECISION_APPLY；v1.1.0 袋内 BAG-D4/D16/D22 后第 39C 纳入
- 关联变更：CR-044

## 已确认规则

1. 拼团秒杀是 **独立**能力域技术模块，不并进商品（ADR-009），不并进交易（ADR-049）。
2. **第一种流程（本地生活）不变：** 仅餐饮/美发/商超及克隆新根：租户完整创建与上下架，**不经平台审核**，无待审状态（DEC-004）。平台不建统一场次、不增加强制下架经营菜单。只暴露在本地生活租户菜单与 mall C 端。mall-online **不**暴露本地生活拼团秒杀 C 端（ADR-004）。
3. **第二种流程（众享源品，v1.1.0）：** 废止 REQ-052。平台开场；仅在线商城已审商品报名；平台审核通过后 mall-online C 端「限时秒杀 / 拼团活动」可进、可下未付单（DEC-050）。活动单平台统一收款。到期未成团关未付单、释放占用，本批无真退。不改本地生活停用规则（DEC-038）。菜单见 DEC-068 / DEC-020 v1.1 / DEC-031 v1.1。
4. 活动成交仍走交易模块（下单、支付、抽佣快照，**ADR-049**）。本域管活动生命周期，不管支付通道。不得把成交写成 ADR-010（ToB）。
5. 数据仍共库，不按进程独占表。本地生活待审历史按 DEC-014 改为未上架，不自动开卖。不得把本地生活活动接到 mall-online。
6. 两种流程允许不同状态机与菜单，禁止硬套同一套相反规则。
7. 模块英文 ID 字符串本题不冻结。本地生活活动进行中停用细则本题不编造。
8. **本 ADR 不生成** `MODULE_BOUNDARIES.md`。G7 仍为部分完成。
