- 主题：mall-online 的微信支付 / 微信登录配置是否沿用 mall
- 选择：方案 A
- 限制条件：NONE
- 被拒方案：B（支付独立、登录 appid 仍抄 mall 平台兜底）、C（整段抄 mall，含店优先和 mall 的 notify）
- 知情决策证据：INFORMED_REVIEW → INFORMED_CONFIRMATION → DECISION_APPLY

## 已确认规则

1. `config/mall-online` 使用**独立** `wechat` 配置，不得整段抄 mall。
2. 支付走**平台商户号**（官方平台统一支付，REQ-101）。不是收到某家店账户，也不是平台自营店收款（DEC-006）。
3. `pay_notify_url`、`refund_notify_url` 指向 **mall-online 自己的域名**，不指向 mall 8032，不沿用「按当前店切商户号 / `merchant_id` 查询参数」的本地生活逻辑。
4. `mini_appid` / `mini_secret` 作为 mall-online 独立配置项填写，**不得默认抄 mall**。具体数值本题不编造。
5. 本地生活支付到租户（REQ-100）仍走 mall，本题不改。
6. 申请支付通道仍是交付依赖；未配齐前可先搭进程和登录，支付联调后补。不编造商户号。

## 未扩大

- 结算周期、部分成功拆单、退款状态机细则
- jwt.expire、Redis db 号（本机端口已由 DEC-049 写死 8035）
- 不创建 `app/mall-online` 工程代码、不改业务代码、不生成总体架构 Draft
- 工程长出方式已由 **ADR-004** 收口（按 mall 模板复制独立工程，去掉本地生活专用路由）
