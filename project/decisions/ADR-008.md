- 主题：平台后台 admin、租户后台 merchant 是独立技术模块，还是只作能力域暴露面
- 选择：方案 A
- 限制条件：NONE
- 被拒方案：B（admin、merchant 作为独立技术模块与 C 端混切）、C（按业态拆四个租户技术模块）
- 知情决策证据：INFORMED_REVIEW → INFORMED_CONFIRMATION → DECISION_APPLY

## 已确认规则

1. 与 ADR-007 同一原则：技术模块按能力域；**模块 ID ≠ 进程名**。
2. admin（:8031）与 merchant（:8033）是能力域的**后台暴露面**，不是名为 ADMIN / MERCHANT 的两套技术模块。
3. 四套菜单模板是 merchant 暴露面的差异，不是四个技术模块（DEC-002）。
4. 数据仍共库。业态树 / 入驻审核 / 菜单模板配置等权威写入在平台侧暴露面；租户经营写入在 merchant 暴露面。不按 admin/merchant 进程独占表。
5. 不合并两个后台进程，不抽公共包，不创建 `app/mall-online`。
6. 菜单隐藏不是安全边界；敏感能力须服务端按能力域校验（DEC-002）。
7. **本 ADR 不生成** `MODULE_BOUNDARIES.md`。G7 仍为部分完成。

- 订单与支付是否拆开（已由 **ADR-049** 收口）
