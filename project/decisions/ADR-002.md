- 主题：mall-online 的 JWT 和作废名单是否与 mall 共用
- 选择：方案 A
- 限制条件：NONE
- 被拒方案：B（共用 mall 的 jwt.secret，靠用户池字段拦跨池）、C（密钥和黑名单键名都与 mall 完全相同）
- 知情决策证据：INFORMED_REVIEW → INFORMED_CONFIRMATION → DECISION_APPLY

## 已确认规则

1. mall-online 使用**独立** `jwt.secret`，不得抄写 mall 的 secret。
2. 作废名单使用**独立键前缀**，或使用独立 `redis.db` 号；仍连接 ADR-001 已定的同一 Redis **实例**。
3. 众享源品 - 在线商城签发的票不得被 mall 当作有效登录；mall 签发的票不得被 mall-online 当作有效登录。
4. 退出或改密后，只作废本端票；不得误伤另一端会话。DEC-003 分池、DEC-005 可作废会话的业务语义不变。
5. `jwt` 配置字段结构可对齐 mall（如 `secret` / `expire`）；**secret 必须独立**。expire 具体秒数本题不冻结。
6. 本题不改网页后台 Cookie+CSRF 口径；众享源品 - 在线商城 C 端仍按小程序/App/H5 的 Header 票模型理解，实现细节留设计。

## 未扩大

- 支付、微信配置已由 **ADR-003** 收口
- 具体 Redis db 数字不冻结（mall 现用 2；实现时避开即可）
- 最短密码长度仍待配置（REQ-080）
- 不创建 `app/mall-online` 目录、不改业务代码、不生成总体架构 Draft
