## 项目形态（决策透镜）

「三端」只是笼统说法。拍板时用下面这张具体形态，不要收成一个用户、一个租户、一个平台。

**五条产品面：** 平台后台；租户后台（一套系统、四套模板）；入驻 H5（四业态同一套）；众享营销 - 本地生活（一店一个）；众享源品 - 在线商城（所有在线商城供应商共用的一个 C 端，含 App/小程序/H5）。

**两类生意，不是四种小程序：**

| | 餐饮 / 美发 / 商超（本地生活） | 在线商城 |
|---|---|---|
| 租户是谁 | 很多家**独立门店** | 很多家**供应商** |
| 顾客从哪来 | 打开**该店自己的小程序** | 打开**众享源品 - 在线商城**，一次逛多家货 |
| 账号 | 店铺池：店 A 注册 ≠ 店 B ≠ 众享源品 - 在线商城。同一手机号是三个账号 | 众享源品 - 在线商城池，单独注册 |
| 会员/店内券 | 只属于该店；店铺券该店自己发 | 供应商无店会员；**仅平台优惠券**（DEC-026 已锁定） |
| 支付 | 该店自己填的收款（现码微信），钱进该店 | 平台统一收款（微信/支付宝等**留口**），钱进平台，再结算给供应商 |
| 抽佣 | 按下单时**业态根**费率快照 | 按商品挂的**平台类目一级**费率快照 |
| 履约 | 餐饮：到店扫桌点餐。美发/商超：先付再核销。不做外卖 | 快递发货（物流设置、查件在租户侧） |
| 小程序 | 必须有，绑定该店 | **没有**供应商独立小程序 |
| 商品 | 店内分类；普通商品上架即可**本店**可售、平台不审；本店推荐栏租户自推；拼团秒杀店内自发不审 | 平台类目发品；平台审过才在众享源品 - 在线商城可买；无拼团秒杀 |
| 租户后台 | 餐饮/美发/商超各一套模板（桌台仅餐饮等） | 第四套模板（无店铺管理/会员/店内分类等，已点名项见 DEC-020～024） |

**平台具体管什么（所有业态一起管，不是只管一类店）：** 入驻审核（租户不能自审入驻）；经营类目树和四套菜单模板；**只审在线商城商品**；在线商城设置、统一收款留口、平台券；不经营拼团秒杀场次；看全局订单/财务（在线商城提现审核；本地生活结算账单是佣金对账，线下核销已收，不是货款钱包，DEC-033）；众享源品 - 在线商城用户；通道用量（谁走了平台短信/OSS）。不审本地生活普通商品。没有平台自营店。

**拍板时至少问：** 这是哪一业态、哪一类租户、顾客进的是哪一个 C 端、钱进谁的账户、平台在这条链上审什么/收什么。缺一截就是假闭环。

## 盘什么

按本期验收主链（不是把 G6 架构再写一遍）：

| 链 | 模块 | 必须盘的闭环 |
|---|---|---|
| 入驻 | M01 / M02 / DEV-003 | 四业态同一 H5 → 审店 → 套对应菜单 → 在线商城绑一级 |
| 菜单 | M03 / DEV-002 | 四套租户侧栏 + 平台侧栏与权限；隐藏≠安全 |
| 商品 | M04 / DEV-006 | 本地生活店内分类+上架可售不审；在线商城平台类目送审；审核台仅在线商城；停用后不可再售（DEC-035） |
| 本地生活 | M05 / M06 / DEV-007/008 | 餐饮扫桌；美发/商超整单一次核销（DEC-034）；店内拼团秒杀，停用后不可新参（DEC-038）；无外卖 |
| 众享源品 - 在线商城 | M07 / DEV-010 | 无独立小程序；审核后可买；平台收款抽佣 |
| 用户登录 | M08 / M09 / DEV-004/005 | 分池；登录五条；认店仅众享营销 - 本地生活 |
| 钱 | M10 / DEV-009 | 本地生活到店账户、佣金对账线下核销（DEC-033）；在线商城到平台再结算 |
| 平台运营 | M11 / DEV-011 | 无自营；banner 保留不验 C 端 |

明确不盘成必做：外卖、在线商城拼团秒杀、众享源品 - 在线商城 AI/发现、小魔推产品改造、正式 UI 视觉。
