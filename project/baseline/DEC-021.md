- 主题：DEC-012「类目与计佣一级同一套」在本批如何落地；是否继续在经营类目下挂子节点
- 选择：方案 A
- 限制条件：不并表删除 `goods_category`；不在 `merchant_category` 再挂在线商城子节点；费率空=未配置 ≠ 0%；不编造类目清单与根费率数字
- 被拒方案：B（在 `merchant_category` 的 online-mall 下手动新增子节点）、C（并表删 `goods_category`）
- 知情决策证据：本窗用户确认「本批在线商城一级直接读平台类目，经营类目不再挂子节点，并且可以在经营类目中配置费率排序等设置」→ DECISION_APPLY

## 已确认规则

1. **结构权威**在 `goods_category`（商品管理 → 平台类目）。增删改名、层级在平台类目页做。
2. **经营类目页**仍展示四业态根；**去掉新增子节点**。在线商城下展示平台类目树，可在此配置**费率、排序、启停**。平台类目名称以平台类目页为准。
3. **本地生活三根**仍在 `merchant_category` 上配根费率；根不可停用、不可删。`online-mall` 根本身不是计佣一级。
4. **计佣一级**：商品挂平台类目任意深度时，向上落到 `goods_category` 中 `parent_id=0` 的一级，取其 `commission_rate`。不得两套一级各算各的佣。
5. **不并表、不删** `goods_category`。费率列落在 `goods_category.commission_rate`（可 NULL）。增量 SQL：`nunu-go-api/deploy/sql/03-goods-category-rate.sql`。
6. 树 JSON **必须带 `source`**：`root`=业态根（`merchant_category`），`platform`=平台类目（`goods_category`），避免两边 id 从 1 起碰撞。写接口与计佣解析都要带 source。
