- 主题：对照现码可收口、不与已确认 DEC 打架的 R 题
- 选择：沿用现码小改（助手自决，DEC-042 第 2 条）
- 限制条件：不新做入驻改原单；不新做商品独立「送审」按钮语义；不另出拼团核销码
- 知情决策证据：DEC-042 自决范围；现码函数见下

## 已确认规则

1. **R1 入驻驳回后再提（沿用现码）**
   - 待审（0）或已通过（1）：同手机号不能再提新申请。
   - 驳回（2）：可以再提 **新申请**，新单 `status=0` 重新待审。
   - **不能**改原申请再提（现码无更新申请接口）。待审中也不能改单。
   - DEV-003 保持此行为；不新做「原单编辑重审」。

2. **在线商城商品驳回后再提（沿用现码；R5 的再提部分）**
   - 存草稿（`submit=0`）：`audit_status` 保持驳回。
   - 提交或上架（`submit=1` / OnSale，且需审）：自动变待审，清空驳回原因。
   - 本地生活普通商品平台不审（DEC-026），不走这套。
   - 批量审核失败策略 **不在本题**（现码无批量审核接口，见 R5 问卷）。

3. **R7 拼团不另出核销码**
   - 现码无订单核销码。DEV-007 做美发/商超核销时，拼团已付订单与普通已付订单 **同一套码**，不另做拼团码。
   - 餐饮仍扫桌、不走核销码（已确认）。

## 现码依据

- `MerchantApplyRepo.HasPendingOrApprovedByMobile`（只拦 status 0/1）
- `MerchantApplyService.Apply` 只 Create 新行
- `GoodsService.applySubmitStatus` / Update / OnSale
- 无核销码表；拼团 `order_type=3` 共用 `order_info`
