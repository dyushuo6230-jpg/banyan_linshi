## 功能在哪看到（人话 6 问）

1. **哪一端、哪业态：** 平台「商品管理 → 平台类目」；在线商城租户发品；入驻 H5 勾 1～3 个一级；众享源品 C 端商品分类 / 首页类目导航。不涉及本地生活店内分类、附近、ToB。
2. **谁：** 平台灌树和重绑一级；供应商批量改挂叶子；顾客逛新分类。
3. **怎么走进来：** 平台侧栏平台类目；租户发品类目选择器；入驻选在线商城后的一级；源品底栏购物进分类页。
4. **人在哪看见：** 类目树名称与层级；发品叶子；入驻一级；源品左栏一级和右侧二三级。
5. **怎么操作：** 先出裁剪定稿 → 备份 → 截断重导 → 重绑店/待审一级 → 人手改挂商品叶子（DEC-057）→ 经营类目页重填一级费率。本 DEC 不授权立刻截断。
6. **现在怎样 / 改完怎样：** 现在是种子 18 个一级、123 节点。灌完后源品分类换成定稿那棵启用树；旧 id 作废。未改挂则源品暂时没货。

## 已确认规则

1. **受控重导，不原样灌京东全文。** 整理稿当底稿，导入前必须裁：去掉热门推荐/专场推荐等运营坑、超 32 字名称、全球购机型级、京东服务入口。一级去留已随定稿确认：计生情趣、二手、全球购进树；奢侈品不进。
2. **先整理再灌。** 裁剪定稿已确认。本机 `shop` 已按定稿截断重导。测试/正式库仍须对该环境另发灌库口令。
3. **定稿位置。** 裁剪后的导入定稿写入 `docs/project/sources/platform-categories/`（文件名 `平台类目整理.md`），并在来源总登记挂一条。京东截图与未裁对照稿留在 `docs/temp/类目截图/`。
4. **名单不进 PRD。** 叠加 DEC-058 OPEN-08：不把节点清单写进 PRD 当必验。定稿是灌库底稿，不是需求真源。测试/重装可用裁剪后的种子脚本，仍不得把名单升格为 PRD。
5. **切树时必须同步的数据（灌库口令之后才做）：** 在线商城 `goods.category_id` 改挂到新叶子；`merchant` / `merchant_apply` 的可售一级换成新一级 id（仍 1～3 个）；一级费率在经营类目页重填（空或 0 = 不抽佣）；平台轮播跳类目的旧 id 作废或改链；替换 `04-goods-category-seed.sql` 为定稿树。灌前备份类目表、商品挂点、店/申请一级。
6. **不自动猜挂。** 存量货按 DEC-057 人手选新叶子。历史已付订单不重算（无类目 id 快照）。
7. **不动。** 本地生活店内分类、附近、业态根、ToB 分类、DEC-071 分类页交互、真扣款。
