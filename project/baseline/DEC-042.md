## 已确认规则

1. **一组最多 5 个业务待配置**同一窗 INFORMED_REVIEW。用户一条消息写 `Rn=方案`（可多条）。该组一次二次确认：`确认该决策：` 下列已选。禁止弹框/问卷卡。钱进谁账、业态身份、会改验收口径的题仍可单独成组。
2. **助手自决范围：** 现码已有明确行为、且不与已确认 DEC/PRD 打架的，按现码小改定，写入 worklog，事后给清单。不编造数字、清单、新验收。会改验收、资金归属、四业态身份的，必须问用户。
3. **盘到位：** 声称某轮盘点完成前，必须列清：问用户的 / 助手按现码自决的 / 明确后置的。盘完后再掏出同级产品题，视为该轮盘点未完成。编码时新发现的现码冲突可以新开题，不得把已知产品题藏到编码中途。
4. **假数据：** 盘点验证和编码需要时，助手可在测试库写入合理假数据。全部开发阶段竣工后：列出加过哪些假数据，并提供 **不带编号文件名** 的清理 SQL。编号 `NN-*.sql` 只留给可重复增量。正式库不灌假数据。
5. **仍有效：** 以现仓库小改；大面积推倒先问（DEC-041）；待配置不编造；不创建 mall-online；不改 `admin_menu`（除非对应批次按 DEC-031）。本期边界仍是 PRD §5/§12 与 DEC-029，不因本 DEC 扩大或缩小功能范围。
6. **不是每个开发批次开工前都开一轮决策。** 该批会用到、且现码对不上已确认规则时才停。

## 本轮盘点收口清单（声称盘完时以此为准）

| 类 | 项 |
|---|---|
| 仍问用户 | R1～R7（一组最多 5 题；能自决的先自决并告知，从队列拿掉） |
| 后置 | R8 对公/账期/坏账 → DEV-009 开工前 |
| 不问（已收口或不验收） | 密码位数、QPS、新订单字段、jwt/Redis/端口死写、装修市场运营细则、核销通知逐字文案、入驻幂等（现码有则沿用）、外卖/在线商城拼团秒杀/小魔推改造/员工角色 |
| 竣工后交 | 假数据清单 + 不带编号的清理 SQL |

## 未扩大

- 不授权助手静默拍掉资金/身份/验收分叉
- 不把假数据写进编号增量 SQL、不灌正式库
- 不撤回 DEC-041「R 队列问完（或自决收口）再开 DEV-003」
