- 主题：餐饮/美发/商超货款已进店微信后，平台抽佣怎么向店收
- 选择：方案 A
- 限制条件：本地生活结算账单=应付佣金对账，禁止确认入账成可提现余额；线下转账、财务勾已收；不接微信分账/银行代扣；不改库等到 DEV-009
- 被拒方案：B（只出应付账单、系统不办已收）、C（本期改成支付即分账）
- 知情决策证据：INFORMED_REVIEW（会话正文）→ `LOOP-Q6=A` → 二次确认限制条件 → DECISION_APPLY
- 关联变更：CR-014

## 已确认规则

1. **适用范围：** 仅餐饮 / 美发 / 商超。在线商城仍是平台统一收款，再按快照结算/提现给供应商（REQ-101），不改成「店欠佣」。
2. **货款与佣金分开：** 本地生活顾客支付进**该店直连微信商户号**（REQ-100）。平台抽佣按业态根费率快照记账（REQ-102）。支付到店 **不等于** 平台已收到佣金。
3. **结算账单 = 应付佣金对账单**，不是货款钱包，也不是平台给店打款。租户侧只读应付金额与已收/未收状态。
4. **禁止**把本地生活「货款 − 退款 − 佣金」确认入账成可提现余额。本地生活侧栏仍无提现（DEC-024）。
5. **收取方式：** 店线下对公转账；平台财务在账单上标记 **已收 / 未收**。不接银行接口、不识别流水、不接微信分账/服务商代扣。支付配置仍为店自己的直连商户号。
6. **本窗不改业务代码、不改结算表。** 改结算语义与已收标记等 DEV-009。升 Ready DEV-009 时按本 DEC 落地，不必再问向店收形态；若改规则须新 DEC/CR。
