- 主题：新设、改密、重置、注册时密码必须多复杂；平台 / 租户与两套顾客端是否同一套；设密时要不要把规则写在页面上
- 选择：方案 A
- 限制条件：填写密码时写明该端规则（设密、改密、重置、注册的密码框旁或下方；不合格提示须说清该怎么设）
- 被拒方案：B（五端同一套严规则）、C（只加强后台、顾客端维持现状）
- 知情决策证据：INFORMED_REVIEW → 用户书面 `PWD-001=A`（含「填写时写明规则」）→ 复述 → 用户书面 `确认该决策：PWD-001=A` 及限制条件
- 关联变更：CR-037

## 已确认规则

1. **平台后台、租户后台**（餐饮 / 美发 / 商超 / 在线商城同一套口令，含本地生活子账号；入驻 H5 若仍让设主账号密码则同一套）：至少 10 位；大写字母、小写字母、数字、特殊符号四类里至少三类。特殊符号指常见标点或符号（如 `! @ # $ %` 等），不在需求里写正则。
2. **众享营销 - 本地生活顾客端、众享源品 - 在线商城顾客端**：凡设密、改密、注册填密码，至少 8 位，必须同时有字母和数字，不强制特殊符号。本地生活若本轮不以账密注册为必验，只要页面上能设密，仍按本条拦。
3. **何时拦：** 新设、改密、重置、注册。登录已有密码只核「对不对」，登录框不展示复杂度规则，以免误导成「现在这串也要符合新规则才能登」。
4. **人在哪看见：** 上述设密页的密码框旁或下方必须写明**该端**规则（后台一句话、顾客端另一句话）。提交不合格时失败原因须说人话，不能只报参数错误。
5. **存储：** 只存不可逆哈希，不回读明文。权威在服务端；前端提示只是帮忙，以后端校验为准。
6. **本条不处理存量换密：** 已由 DEC-063 收口（下次登录强制改密，不发总清单）。超管登录名与登录页写死账号密码：已由 DEC-064 收口。浏览器禁止回填：已由 DEC-066 收口。

## 对先前决策的收口

- DEC-039 第 5 条作废：最短位数写入 PRD，并纳入设密验收。DEC-039 其余条（banner、供应商轮播菜单、时区、容量、订单字段）不动。
- DEC-005 / 登录五条不变。本条是设密复杂度，不是第五条的替代。
- 本机自测再填 `123456` 会无法通过新设密；正式环境仍禁止默认弱口令、禁止登录页预填。
