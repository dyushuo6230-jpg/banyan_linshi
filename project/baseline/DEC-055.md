- 主题：在线商城供应商发品时平台类目怎么选、列表怎么筛
- 选择：方案 A（只选叶子 + 筛祖先含子孙 + 只见本店入驻一级子树）
- 限制条件：不改平台类目树结构、不加商品字段、不另算一套佣；本地生活仍走店铺分类
- 被拒方案：B 只裁树、父节点仍可挂货；C 整树可见、送审再拦超出范围
- 知情决策证据：袋内 GOODS-CAT-PICK=A 已确认应用；本窗对照表确认后 APPLY
- 关联变更：CR-030

## 功能在哪看到（人话 6 问）

1. **哪一端、哪业态**：租户后台 · 在线商城供应商。餐饮 / 美发 / 商超发品仍走店铺分类，不走本条。
2. **谁**：在线商城供应商发品、改品、按类目筛自己的货。
3. **怎么走进来**：租户后台商品发布 / 编辑；商品列表上的平台类目筛选。
4. **人在哪看见**：类目树选择器里哪些节点能点；保存失败提示；列表筛完出现哪些商品。
5. **怎么操作**：发品/保存/送审只能点最末叶子；有下级的节点不可选。筛选可以点祖先，结果要带上挂在其子孙叶子上的货。
6. **现在怎样 / 改完怎样**：现在稿允许挂平台类目任意深度（DEC-021 第 4 条）。改完：发品必须挂叶子；计佣仍向上落到一级费率；筛选选中父/祖父时不是只精确匹配该 id。

生动例子：供应商入驻时选了「食品」这一个一级。打开发品，树里只看见「食品」及其下级，看不见「家电」。他要点「饼干」（没有下级的叶子）才能保存；点「休闲零食」（下面还有饼干）保存失败。列表筛「休闲零食」时，挂在「饼干」上的货也要出现。旧货若当年挂在「休闲零食」上，打开编辑能看见原值，但再保存必须改成某个叶子，系统不自动改挂。

## 已确认规则

1. **选择器范围。** 平台类目树只显示该店入驻已选一级及其下级（DEC-012 范围落到选择器）。
2. **发品挂点。** 发品 / 保存 / 送审只能挂最末叶子；有下级的节点不可选。未选叶子、或超出入驻一级，保存/送审失败。
3. **计佣不变。** 商品挂叶子后，计佣仍向上落到 `parent_id=0` 的一级取其费率（DEC-021 计佣算法不另开一套）。
4. **列表筛选。** 选中某节点（含根/父/祖父/一级）时，结果包含挂在该节点子孙叶子上的商品，不是只精确匹配该节点 id。
5. **存量。** 已挂在非叶子上的商品：编辑可回显原挂点；保存必须改成叶子。不自动改挂。
