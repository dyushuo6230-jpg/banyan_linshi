- 主题：众享源品 - 在线商城首页无 banner 怎么展示；本轮是否调起支付；后续通道是否含金豆；联调货怎么来；本轮做到哪停
- 选择：S2 五题均为 A
- 限制条件：C 端只调 mall-online；不编造商户号；不拿页面静图冒充 banner 接口；本轮不开发微信/支付宝/金豆扣款；001～006 / 011 不因本 DEC 升 Ready
- 被拒方案：静图当接口数据；本轮 H5 真扣款；拆掉支付按钮；金豆只进迭代建议不进 PRD；SQL 插已过审假货绕过审核台
- 知情决策证据：会话正文 `S2-D1=A` `S2-D2=A` `S2-D3=A` `S2-D4=A` `S2-D5=A`

## 已确认规则

1. **首页轮播。** 众享源品 - 在线商城首页只渲染平台 `banner` 接口返回的图。一张都没有则不轮播，不把页面里的蓝湖静图当成接口数据、不写进 banner 表冒充运营配置。不强制正式运营必须先配图才能验收。联调允许在平台后台录入测试轮播并保留。
2. **本轮支付。** 众享源品 - 在线商城 C 端本轮不调起微信、支付宝、金豆。用户可下未付订单。支付按钮和现有支付组件保留，以便打 iOS / 安卓 / H5 / 微信小程序包去申请支付通道。不得把未付订单标成已付。短信/账密登录没有微信 openid，本轮不做微信小程序支付。
3. **后续通道。** 众享源品 - 在线商城支付后续通道为微信、支付宝、金豆（虚拟）。与众享营销 - 本地生活的支付包、调起方式允许不同。本轮不开发、不验收这三通道的真实扣款。将来对接成功后的收款方仍是平台账户（REQ-101），不是供应商店商户号。
4. **联调商品。** 走租户后台在线商城模板发品 → 平台审核通过 → 众享源品 - 在线商城可售。允许 2～3 个带联调标记的 SKU 并保留。不得 SQL 直插「已过审可售」绕过审核台。未过审不得出现在众享源品 - 在线商城。
5. **本轮施工停点。** 配置、增量 SQL、联调货、C 端接到 mall-online（登录/轮播/商品/购物车可改数量结算进未付/立即购买未付下单/支付按钮）、打包编译、自测、起 H5 与 mall-online。DEV-001～006、DEV-011 不因本 DEC 升 Ready。购物与加购必须能办完未付路径，不得再提示敬请期待。
6. **加购（v1.1.0）。** 详情「加入购物车」写入购物车；购物车可改数量、结算进入未付单。立即购买继续未付单。支付按钮保留，不调起微信/支付宝/金豆。不得把未付单标成已付。购物车、订单继续用旧页，不像素验收。

## 对先前决策的收口

- DEC-029「够申请支付」：本轮落实为打包留口 + 支付按钮/组件仍在，不要求本轮 C 端真扣款。
- DEC-039「没数据可空或占位」：C 端占位不得用静图冒充接口；无数据就是不轮播。
- REQ-064 / SRC-UI-002「本期不做真实支付」：不得把该说明升格为永久废止平台统一收。本轮 C 端不调起通道以本 DEC 为准，将来对接后仍按平台统一收款验收。

## 未扩大

- 不在本轮实现金豆账户、支付宝 App 支付、微信预下单
- 不改众享营销 - 本地生活支付
- 不把众享源品 - 在线商城请求打到 mall（8032）或租户后台
- 不重做众享源品 - 在线商城无图旧页的像素验收（有 PNG 页见 DEC-008 v1.1）
