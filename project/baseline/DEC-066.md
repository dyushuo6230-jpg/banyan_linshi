- 主题：登录框、密码框、微信 AppID 及同类密钥框，要不要禁止浏览器把以前记住的字自动填进来
- 选择：方案 A
- 限制条件：NONE
- 被拒方案：B（只关登录、AppID 不管）、C（不关，继续让浏览器填）
- 知情决策证据：INFORMED_REVIEW → 用户书面 `AFL-001=A` → 复述 → 用户书面 `确认该决策：AFL-001=A` 限制条件 NONE
- 关联变更：CR-041

## 已确认规则

1. **登录类：** 平台后台、租户后台、两套顾客端 H5 上，账号、密码、确认密码框须声明不要浏览器自动填。登录页不要「记住密码」。
2. **密钥配置类：** 微信 AppID、AppSecret、支付密钥/私钥、短信密钥、OSS 密钥同样声明不要自动填，避免浏览器把登录名塞进 AppID、把密码塞进密钥格。
3. **和 DEC-064 分工：** DEC-064 管页面源码不写死默认字。本条管浏览器自己的通讯录。两条都要做。
4. **验收：** 源码不再邀请浏览器填；用没有保存过密码的浏览器打开，框是空的。
5. **承认做不到：** Chrome 对登录框可能仍从自己保险柜填回来。那不算页面又写死默认值。本条不承诺某台电脑上一次都不填。

## 未扩大

- 不改库里已存的 AppID、密钥
- 不关验证码、搜索、店名；不改装修问卷回填；不管微信小程序系统密码保险柜
- 不改业务代码（须另给开工口令）
