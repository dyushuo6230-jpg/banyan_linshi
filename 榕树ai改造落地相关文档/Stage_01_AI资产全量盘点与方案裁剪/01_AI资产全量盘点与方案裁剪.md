# Stage 01：AI 资产全量盘点与方案裁剪

> Charter：v1.9.1 FINAL_FREEZE  
> Upstream：Stage 00 COMPLETED / Stage 01 Entry Gate PASS  
> 本阶段性质：**Discovery + Classification + Preliminary No-Loss Coverage**。  
> 本阶段不是架构冻结、迁移执行或目录重构阶段。

## 1. 核心目标

从**真实 Repository Root**重新发现全部可能影响 AI 软件工程治理的：

```text
AI Asset
Legacy AI Capability
AI Generated Canonical Artifact
AI Generated Derived Artifact
Operational Artifact
Legacy Governance Behavior
Git Identity / Commit Practice
```

Stage 00 的已知目录、总纲 Seed、历史记忆都只能帮助启动发现，**不能替代 Full Discovery**。

本阶段必须回答：

```text
现在项目中到底有哪些 AI / Governance 资产？
它们各自起什么作用？
哪些能力是真正有价值的 Legacy Behavior？
哪些文件只是重复/派生/历史/临时？
哪些内容可能进入 Generic Core？
哪些只能留在 Project / Provider / Compatibility？
有哪些冲突、缺口、未知项？
如果未来迁移，怎样保证不丢能力和不丢 Canonical Artifact？
现有 Git Identity 与 Commit Practice 是什么？
```

## 3. Stage 01 不做

禁止：

- 创建最终 `banyan-framework/`；
- 创建正式 `.banyan/`；
- 移动/整理现有项目目录；
- 改写业务代码、SQL、生产配置；
- 改写 PRD / DEC / ADR / CR / UI_SPEC；
- 改写 Legacy Prompt / Rule / Skill；
- 删除、合并、归档任何 Legacy；
- 冻结 Framework / Project Instance 最终边界；
- 冻结 Source Role 最终 Schema；
- 冻结 Commit Policy；
- 执行 Legacy Migration；
- 自动 `DROP_WITH_APPROVAL`；
- Git commit / stash / reset / clean；
- 修改 Git Identity。

## 5. 必须隔离的两类“非 Legacy”

### 5.1 `.banyan-refactor/**`

只作为：

```text
UPSTREAM_REFACTOR_OPERATIONAL_EVIDENCE
```

不得计入：

```text
Legacy AI Asset
Legacy AI Capability
AI Generated Legacy Artifact
Project Canonical Artifact
```

### 5.2 `榕树ai改造落地相关文档/**`

只作为：

```text
REFRACTOR_CONSTRUCTION_MATERIAL
```

CURRENT Charter / Stage Pack 是施工权威输入；AUDIT / ARCHIVE 是审计与历史资料。

这些不是项目改造前的 Legacy AI Asset，不得污染 Inventory。

## 7. Capability 与 Artifact 分开盘点

文件不是能力，能力也不一定对应单个文件。

### Capability

例如：

```text
知情决策
编号保护
G0～G11
UI Gate
新窗口恢复
变更稿并行盘点
Batch Canonical Reconciliation
测试完整性
临时桩治理
进度/交接
```

每个高价值 Capability 必须有：

```text
candidate_owner_stage
candidate_target_capability
candidate_action
confidence
open_question
evidence_refs
```

Capability 候选动作：

```text
KEEP
MAP
GENERALIZE
PROJECT_ONLY
REPLACE_EQUIVALENT
COMPATIBILITY_READ
ARCHIVE
DEPRECATE
DROP_WITH_APPROVAL
```

Stage 01 不执行 Drop。

### Artifact

AI Generated / Canonical / Derived / Operational 必须区分。

Artifact 候选动作：

```text
KEEP
MAP
TRANSFORM
REGENERATE
INDEX_ONLY
COMPATIBILITY_READ
ARCHIVE
SUPERSEDE
DEPRECATE
DROP_WITH_APPROVAL
```

Canonical Truth 默认倾向：

```text
KEEP_IN_PLACE + MAP + INDEX
```

而不是为了 Banyan 搬目录。

```text
Trailers / issue / PR linkage
是否已有批量/分批提交脚本或习惯
```

规则：

```text
Git Author name + email = Contribution Identity
```

但 Stage 01：

```text
不建立 Contributor Profile Registry
不合并 Identity
不改 Git Config
不冻结 Commit Policy
不执行 Semantic Commit
```

## 12. Git History Discovery

Git History 只用于补全：

```text
已删除/重命名的治理资产
历史上仍被引用的 AI/Governance 文件

```

不得：

- 为了“恢复历史”自动 checkout；
- 改写历史；
- rebase；
- reset；
- force push。
