# F6-D09：已讨论内容、未批准候选与下一步

状态：`HUMAN_REVIEW`。本文是讨论记录，**不是** `FROZEN_CONTRACT`，也不授予修改或施工权限。

## 1. 已形成的讨论方向

上一会话反复对齐了 D09 与 D10 的职责：D09 判断“目标是什么、实际是什么、差异是否构成偏离、证据够不够、已有功能是否回归”；D10 才治理“允许改什么、如何修、如何同步设计与代码、何时停止”。D09 可以读取 Allowed Mutation Scope（允许修改范围）和 Protected Functional Baseline（受保护功能基线）做验证，但不能借此授予写入权限。

顶层讨论名称是 **UI Conformance Session（UI 一致性校准会话）**。旧名 Visual Repair Loop（视觉修复循环）只拟作为 `mode=VISUAL, action=REPAIR` 的兼容配置。会话默认 `OFF / ON_DEMAND / NON_BLOCKING`，不自动成为开发阶段或验收门禁。

目标解析方向：先看 Current Effective UI_SPEC（当前有效 UI 施工规范），再看适用的 Governed Design Package（受治理设计包），再看用户明确指定的设计来源；优先级还须服从 Authority、适用范围、版本与 Freshness（时效）。只有 PRD 而缺少足够 UI 目标时，不应直接启动视觉修复，应先形成设计目标。现有页面默认是当前实现证据，只有被明确指定保护时才成为 Protected Baseline，不自动成为设计真相。

检查应按应用、页面、区域、组件、状态、交互、设备和数据场景限定 Scope（范围）；未检查不能写成通过。实际观察可来自截图、浏览器、DOM、测试等可追踪证据，但观察值不能自动升为设计要求。`Difference（差异）≠ Drift（偏离）`，像素差异不是正确性的最终判据；合法替代实现、动态数据、响应式变化和已批准偏差需要区别处理。目标过期或来源冲突时，不强行给 PASS/FAIL。

检查维度候选包括视觉、结构、布局、状态、交互、响应式、数据展示、可访问性；修复后还要检查受保护的 API、路由、权限、业务状态、上传、删除、分页等功能是否回归。结果应记录目标来源和版本、范围、覆盖、证据、差异分类、功能回归、未知项及 Provider Trace；Validation Result（验证结果）是证据，不是新的 Canonical Truth。

## 2. 后续新增的“一轮校准会话”讨论

用户补充：一轮视觉校准中发现严重风险差异时，先记录，允许继续处理其它互不依赖的低风险事项；本轮结束的报告必须列出风险项。用户确认后，只处理被确认的项并做必要的局部复验和功能回归；处理完停止，**不得自动开启下一轮**。下一轮等用户再次明确发出指令。上一会话助理将其解释为 affected-scope blocking（仅阻塞受影响范围）和“一轮是一轮”。

## 3. 风险分级与决策路由：待确认建议

上一会话最后讨论了一套 **R0～R3 候选**，用户提出“是否需要增加风险等级评估，低等级怎么处理，高等级是否接入决策环节”；助理给出建议，但分享会话里没有看到用户对整套分级的最终批准。

- R0：只观察、采证、比较、报告，没有修改风险。
- R1：目标明确、局部、可逆、在既有授权范围内、可自动复验且不影响受保护功能的低风险修正。建议自动修复并复验。
- R2：影响局部 DOM 或共享组件等中风险事项。先查影响范围、既有授权与项目策略；有足够授权可受控处理，否则记录并挂起受影响项。
- R3：涉及业务语义、API、权限、数据契约、权威冲突、功能回归、大范围重构等。建议挂起受影响项，复用 Banyan 既有 Gap → Decision Routing → Human Decision 治理链。

风险评估针对**处理该差异的治理风险**，不是视觉差异面积或像素数量。风险等级不等于 Authority、Permission，也不自动授予修改许可。候选判定因素：目标与权威是否明确、修改范围、是否跨共享组件、是否影响受保护功能或业务语义、可逆性、可自动验证性、来源冲突。

本轮报告建议至少记录：实际检查范围、已通过项、已授权修复项、普通未解决差异、R2/R3 待确认项、证据不足项、功能回归结果、决策引用和本轮状态。对风险项的用户决定只适用于被点名项目；完成本次修复必要复验后停止，不自行启动新一轮。

## 4. 用户明确提出的架构质量要求

- 灵活、分层有序、可扩展；Scope → Profile → Index 精准加载，避免全量扫描。
- 事实、规则、实现、推断、权威、状态必须分开。
- 确定性工作尽量自动完成；真正冲突或高风险才打扰人，但不能绕过治理。
- 条款之间应预先明确职责、适用条件、覆盖与冲突关系，不能留给执行时 AI 猜测。
- 当前不实现 AI 自主学习、总结或优化；只为未来保留可扩展边界。
