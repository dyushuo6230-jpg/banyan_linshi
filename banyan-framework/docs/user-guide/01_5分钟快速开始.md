# 5 分钟快速开始

> 关键术语：Provenance（来源沿革：内容从哪里来、经过什么处理）；Trace（追踪记录：记录动作、结果和关联证据）。

## 这篇解决什么问题

给出一条最短、可控的开发路径：描述需求，先规划，补证据，做决策，确认施工，验证，再形成提交计划。

## 什么时候需要看

你已有一个小需求或 Bug，希望马上开始，但又不想让 AI 擅自扩大范围时。

## 核心概念

Preflight（执行前预检：正式动作前检查权限、风险、前置条件和证据）可以告诉你动作是 `ALLOW`、`BLOCK` 还是 `NEEDS_INPUT`。Authorization（授权：允许特定动作作用于特定目标和范围的有效依据）与“我看过计划”不同。

完整自动编排当前未实现。最稳妥的对话节奏是“先规划 / 再施工”。

## 推荐操作方式

1. 描述需求：说清目标和验收结果。
2. 限定范围：允许读取什么、允许修改什么、禁止触碰什么。
3. 先分析/规划：让 Banyan 汇总已知事实、风险、缺口和步骤。
4. 提供 Material（物资：需求文档、截图、日志等输入）与 Evidence（证据：可核验的事实材料）。
5. 做决策：对存在取舍或 Authority 不明的地方明确选择。
6. 确认施工：只授权已审阅的范围；新风险应重新停下来。
7. 验证：要求列出实际检查和结果。
8. 获取 Semantic Commit（语义化提交：按变更含义分组的提交）计划；当前项目只支持 dry-run，不会由 Runtime 创建真实 commit。

## 自然语言示例

> 目标：修复订单详情页金额显示错误。范围只限订单详情相关前端文件。先分析原因并给计划，不修改；如果证据不足，列出需要的日志或文件。

确认计划后：

> 我确认按这个计划施工，仅允许修改计划列出的文件。完成后运行相关测试，列出 leftovers，并生成 commit plan，不执行提交。

## 当前实现状态

Runtime preflight、项目检查、commit plan、current-project dry-run、Trace 和 Provenance 查询已经实现。自动把自然语言需求完整路由到全部开发阶段尚未实现。

## 常见误区

- 一次说“帮我完成”并不等于所有写入和 Git 动作都获授权。
- Evidence 不等于 Authorization。
- Commit Plan 不等于 commit，也不等于 Authorization。
- 验证报告应说明实际运行了什么，不能只写“应该没问题”。
