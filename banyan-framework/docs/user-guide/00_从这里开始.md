# 从这里开始

> 关键术语：Project Instance（项目实例：连接具体项目来源、变量和 Provider 的状态集合）；Final Activation（最终激活：经过独立治理决定后正式启用项目实例）。

## 这篇解决什么问题

用 3 分钟认识 Banyan：它怎样帮你把需求、证据、决策、安全检查和交付串起来，以及当前哪些部分仍需你明确指令。

## 什么时候需要看

第一次接触 Banyan，或不确定应该用 Codex / Cursor、WebUI 还是 CLI 时先看本篇。

## 核心概念

Banyan 是一套带事实来源、权限边界和追踪记录的研发协作框架。主入口是 Codex / Cursor 自然语言编辑器；WebUI（网页控制界面：查看 Runtime 结果和提交受限意图）是辅助入口；CLI（Command-Line Interface，命令行界面）是高级、调试和自动化入口。

Runtime（运行时核心：执行权限判断、预检和受控动作）当前支持受限 API。完整自然语言自动 Workflow（工作流：按规则组织任务步骤的过程）编排尚未实现，所以关键任务最好明确说“先分析”“只规划”或“确认后再施工”。

Reference（参考手册：给出精确枚举、状态和边界）适合查规则；User Guide 适合学怎么用。

## 推荐操作方式

1. 在 Codex 或 Cursor 中说明目标、范围、材料、约束、期望输出以及是否允许修改。
2. 高风险或不确定任务先要求分析与计划。
3. 补齐被请求的 Evidence（证据：支持判断的可核验材料）。
4. 对需要人的选择给出明确 Decision（决策：带范围和影响的有效选择）。
5. 施工后要求验证，并先查看提交计划。
6. 遇到状态或术语不清楚时查 Reference，不靠猜测。

## 自然语言示例

> 请先分析这个 Bug 的影响范围，只给计划，不修改代码。列出缺少的证据和需要我决定的问题。

> 允许修改 `src/example/**`，其他目录只读。完成后运行相关验证，并给出语义化提交计划，不要直接提交。

## 当前实现状态

- Codex、Cursor、Generic Editor Adapter（适配器：转换不同编辑器请求格式）已实现受限 action surface。
- WebUI 有 12 个真实页面，但 `/help` 尚未实现。
- 当前项目 Git 执行是 `DRY_RUN_ONLY`。
- `.banyan` 是 Shadow Pilot（影子试点：尚未替代正式项目真相），Final Activation 未授权。

## 常见误区

- “自然语言入口”不等于完整研发流程已经自动化。
- `ALLOW` 是权限判定，不等于动作已经执行。
- Framework 已发布不等于项目已激活。
- 35 个 `CAP-*` 是 Capability Contract，不是 35 个已安装 Skill。
