# 物资、证据、决策是什么

> 关键术语：Material（物资：帮助理解任务的原始输入）；Evidence（证据：支持判断的可核验材料）；Decision（决策：对选项作出的明确选择）；Authorization（授权：允许特定范围动作的有效依据）；Preflight（执行前预检：动作前的门禁检查）；Trace（追踪记录：动作、结果和证据关系）；Canonical Apply（正式真相应用：把批准变更应用到权威来源的治理过程）。

## 这篇解决什么问题

区分 Material、Evidence、Decision 和 Authorization，避免“给了文件”被误解成“允许执行”。

## 什么时候需要看

Banyan 要求补材料、停下来请你选择，或动作被 Gate 阻塞时。

## 核心概念

- Material（物资：帮助理解任务的原始输入）可以是需求说明、截图、日志、原型或代码片段。
- Evidence（证据：支持判断、状态或结果的可核验材料）应能定位来源和适用范围。
- Decision（决策：在人有权决定的范围内对选项作出的明确选择）记录选择、理由和影响。
- Authorization（授权：允许特定动作作用于特定目标和范围的有效依据）控制动作是否可以执行。

`Evidence != Authorization`。证据能证明事实，不能单独授予写入或外部动作权限。

## 推荐操作方式

1. 把原始材料和你的结论分开提供。
2. 对重要事实说明来源、版本或时间；不知道就标 `UNKNOWN`。
3. 要做选择时，确认选项、影响、范围和不可逆后果。
4. 授权时明确动作、目标、范围和限制。
5. 要求 Banyan 把 Evidence、Decision 和 Authorization 分开引用。

## 当前实现状态

Evidence / Decision / Authorization schema 主要是 frozen contracts。Runtime 已实现 permission evaluation、Preflight 和 Trace；Trace 记录本身不授予 Authorization。

## 常见误区

- 设计图、Figma 或截图是 Evidence，不自动成为产品需求真相。
- Reviewer 认可不必然等于有权授权目标动作。
- `ALLOW` 表示权限判定结果，不表示执行已发生。
- Git Identity 不证明 Human Project Authority。
